# SimToolReal 摘要（Abstract）阅读笔记

论文：*SimToolReal: An Object-Centric Policy for Zero-Shot Dexterous Tool Manipulation*（arXiv 2602.16863v3）

说明：关于 zero-shot 的三个问题已记在 Figure 1 的笔记里，这里不重复。标注"（我的解释）"的内容是论文没有展开、由讲解补充的部分。

---

## 摘要的逻辑线

1. 用工具能大幅扩展机器人能做的事，但很难：要抓起很薄的物体、在手里转动、还要承受用力的接触。
2. 路线一（遥操作 + 模仿学习）：数据难采。
3. 路线二（sim-to-real 强化学习）：有前景，但以前每个物体要建模、每个任务要调奖励，工程量大。
4. 本文：不针对具体物体和任务，只训练一个通用策略，把随机生成的工具形状移动到随机目标位姿。
5. 结果：测试时不做任何针对性训练就能用新工具做新任务。比重定向和固定抓取基线高 37%，与专用策略持平；真机 120 次实验，覆盖 24 个任务、12 个物体、6 类工具。

## Q1. "Since collecting teleoperation data for these behaviors is challenging, sim-to-real RL is a promising alternative" 是什么意思？

"因为给这类动作采集遥操作数据很困难，所以仿真到现实的强化学习是一条有前景的替代路线。"

教机器人做事主要有两条路：

- **模仿学习**：人先示范，机器人照着学。需要大量示范数据。
- **强化学习（RL）**：不给示范，只给打分规则（奖励），机器人自己试错。

这句话是说第一条路的数据不好拿，所以走第二条。

---

## Q2. Teleoperation（遥操作）是怎么操作的？为什么难？

**怎么操作**：人实时远程操控机器人，机器人跟着人的动作动，同时录下机器人的关节数据和相机画面，这段录像就是一条示范数据。常见方式：

- 动捕手套：手指怎么动，机器手就怎么动
- VR 头显和手柄
- 相机直接拍人手，估计手的姿态再映射给机器人
- 穿戴外骨骼，把人手和机器手物理耦合

**为什么难**（论文引言给的两个原因）：

1. **人手和机器手不一样**：尺寸、关节结构、驱动方式都不同，人手的动作无法一一对应到机器手上。论文称为 human-to-robot correspondence gap。
2. **操作者没有力觉和触觉反馈**：感觉不到握得紧不紧、有没有打滑，只能靠眼睛看，很难控制接触力。

用工具恰恰最依赖这两点（抓薄物体、手内旋转、敲击时不脱手），所以遥操作只能录到比较简单的动作。

---

## Q3. 外骨骼把人手和机器手耦合在一起了，机器人不就能握稳了吗？

直觉是对的：外骨骼确实缓解了上面两个问题，"握稳"比手套和 VR 容易。但论文指出它仍有三个问题：

1. 笨重，操作者负担大，难以大规模采集。
2. 限制了人手的活动范围。
3. **做不出复杂技能，比如手内旋转（in-hand reorientation）**。

为什么第 3 条做不到（我的解释）：握住不动是静态的，几根手指同时夹紧即可。在手里把锤子转 90° 需要手指轮流松开、换位置、重新接触，其余手指还要撑住工具，是连续的动态协调，高度依赖指尖触觉。戴上外骨骼后，接触工具的是机器手指而不是人的皮肤，力经过连杆传回来只剩大概的感觉；机器手指的粗细、长短、摩擦也和人手不同。

本文需要的能力链条是 **抓取 → 手内旋转 → 使用**，中间这一环外骨骼采不到数据。

## Q4. Sim-to-real RL 是什么？

不是新算法，是两个概念拼起来的一条流程：

- **RL**：只给奖励规则，机器人随便试，得分高的做法被强化，反复极多次后学会任务。
- **Sim-to-real**：试错过程在仿真里进行，学完后搬到真机。

二者几乎总是绑在一起，因为 RL 需要的试错量太大。本文同时跑 24576 个并行仿真环境，总步数上千亿，真机做不到，而且真机试错会摔东西、撞坏手。

## Q5. 仿真和现实不一样（sim-to-real gap），到了真机出问题怎么办？

**本文到了真机之后不再调整策略的任何参数，原样部署。** 能成立是因为差距是提前处理的，分三个时间点：

**训练前：把仿真校准得像真机**
测量真实机器人的关节增益、阻尼等，填进仿真。只能缩小差距，不能消除。

**训练中：domain randomization（域随机化）**
不追求仿真"准"，而是让它"乱"。每个回合随机改变（数值来自论文 Table I）：

- 物体位姿读数加最多 1cm、5° 的噪声，延迟最多 10 步
- 动作和其他观测延迟最多 3 步
- 随机对物体施加最大 5N 的力、0.5Nm 的力矩
- 桌面高度变化 ±1cm
- 工具的尺寸、密度每次不同

策略被迫学会在所有这些情况下都能用的做法，真实世界对它只是范围内的又一个样本。

**部署时：参数不变，行为实时调整**
策略是闭环的，每秒 60 次读取真实位姿再决定动作，偏了下一步就纠正。LSTM 有记忆，能从刚才的交互里推断工具的轻重等属性。适应发生在网络的记忆状态里，而不是权重里。

**真机上还是出问题时**：做一个循环，上真机试 → 观察失败 → 判断是哪种差距 → 回仿真把这种差距加进去 → 重新训练 → 再上真机。**调的是仿真设置，不是真机上的策略。** 论文附录 D 那张清单就是这个循环的产物，例如：

- 发现关节速度和物体位姿在真机上噪声最大 → 给这两项加噪声
- 视觉位姿跟踪比较慢 → 给物体位姿设置更大的延迟
- 手指互相碰撞会损坏硬件 → 限制手指侧摆关节的范围

**这个循环本文没有省掉，任何 sim-to-real 工作都要做**，只是针对这台机器人做一次。剩下没消除的差距直接体现为失败率。

## Q6. 仿真器怎么用？噪声是在哪里设置的？

仿真器不是点按钮的软件，而是在代码里调用的**物理计算器**。它只做一件事：给它当前世界状态和电机指令，它算出下一时刻（本文是 1/120 秒后）世界的状态。它给出的数字完全精确，本身没有噪声。

噪声、延迟、奖励都是**自己写的代码**，夹在仿真器和神经网络之间。示意（不是论文的真实代码）：

```python
每一步重复：
    真实位姿 = 仿真器.读取物体位姿()        # 仿真器给的，完全准确
    观测位姿 = 真实位姿 + 随机噪声           # 自己写：故意弄不准
    观测位姿 = 取几步之前的旧值              # 自己写：故意弄延迟
    动作 = 策略网络(观测位姿, 关节状态, 目标位姿, 包围盒)
    仿真器.对物体施力(随机的力)              # 调用仿真器自带功能
    仿真器.设置电机目标(动作)
    仿真器.前进一步()                       # 仿真器算出下一时刻
    奖励 = 根据真实位姿离目标多近打分         # 自己写：这就是"奖励函数"
```

两种情况：

- **观测噪声、延迟**：纯粹是自己的代码，在把数字交给策略之前动手脚。
- **物体形状、密度、桌子高度、外力**：通过仿真器提供的接口设置。

对应到两个常见说法：
- "调奖励函数" = 改最后一行的打分公式
- "回仿真改设置" = 改中间几行噪声和延迟的大小

改完都要重新跑训练。本文用的仿真器是 IsaacGym。

## Q7. "substantial engineering effort" 具体指什么？

摘要原文：*substantial engineering effort **to model objects and tune reward functions for each task***。重点是 for each task，指两件事：

1. **给物体建模**：要用哪把锤子，就得先在仿真里造出这把锤子，换工具就重做。
2. **调奖励函数**：每个任务的"做得好"标准不同，要单独设计打分规则并反复调试。

Q5 里那个 sim-to-real 循环也是工程量的一部分（Related Work 把三者合称 environment shaping），但它和"换任务要重新设计奖励"是两件不同的事，不要混在一起。

| 工程量 | 以前的方法 | 本文 |
|---|---|---|
| 给每个物体建模 | 每个物体做一次 | 不用做 |
| 给每个任务调奖励 | 每个任务做一次 | 不用做 |
| 缩小 sim-to-real gap 的循环 | 要做 | 仍然要做，只做一次 |

## Q8. 这篇文章的 idea 是什么？怎么解决上面的问题？

**核心观察**：不管什么工具任务，只盯着工具看、不看手，都是同一件事：工具依次经过一串位置和朝向。

- 挥锤：平躺在桌上 → 被拿起 → 转成竖直 → 移到钉子上方 → 砸下
- 扫地：平躺 → 被拿起 → 转成刷毛朝下 → 向前推

所以不教"挥锤""扫地"，只教一个技能：**给一个位置和朝向，把手里的东西摆成那样。** 任何任务都只是一串不同的目标位姿。这就是标题里 object-centric（以物体为中心）的含义。

| 问题 | 本文怎么做 |
|---|---|
| 每个任务要重新设计奖励、重新训练 | 只用一个永远不换的奖励：工具离目标位姿越近分越高，到达给奖金并换下一个目标。训练时目标随机生成；真机上换成从人类视频提取的位姿序列 |
| 每个工具要在仿真里单独建模 | 训练时随机拼"一根手柄 + 一个头"，长短粗细轻重每次不同。真实工具只需提供手柄的粗略包围盒 |
| 遥操作费人力、人手和机器手不一样 | 不遥操作。人用自己的手正常做一遍并录像，只提取**工具**的运动轨迹，不管人手怎么握。机器手怎么握由它自己在仿真里试错学出 |
| 仿真画面和真实画面不一样 | 策略不看图像，只看物体 6D 位姿和包围盒。视觉交给现成模型（SAM 3D、SAM 2、FoundationPose） |

## Q9. 只练"摆到随机位姿"，为什么能学会抓取和手内旋转？

没有人教，是被训练设置逼出来的：

- 工具一开始平躺在桌上，不抓起来拿不到分 → 学会抓取
- 随机目标里有很多大角度旋转，光靠手臂够不着 → 学会在手里转
- 工具掉了这一局直接结束 → 学会握紧
- 训练时有随机外力推工具 → 握得更稳

这是文章的核心论点。Figure 7 是验证：随机目标训练的得分越高，真实工具任务上的表现也越好。

## Q10. 什么是位姿跟踪丢失？

- **位姿**：物体的位置（x、y、z）加朝向（绕三个轴的旋转），共 6 个数，即 6D 位姿。
- **位姿跟踪**：相机一直拍着工具，视觉模型 FoundationPose 每秒 30 次估计工具的位姿。它以上一帧的结果为起点找这一帧的位姿。
- **跟踪丢失**：估计结果和真实位姿对不上且回不来。因为每帧依赖上一帧，一旦偏远就越偏越远。

容易丢的三种情况（附录 G）：

1. 遮挡严重：手把小工具挡住了，如短螺丝刀
2. 旋转对称：马克笔是圆柱，绕长轴转多少度看起来一样
3. 对比度低：深色刷毛在黑色桌面上

**为什么致命**：策略不看图像，对工具的全部了解就是这 6 个数。跟踪一丢，它拿到的是错误信息。训练时的噪声只能让它扛住小误差。所以跟踪丢失时实验直接结束，算失败。

注意：**43.7% 是"失败原因中的占比"，不是失败率。** 其余为物体掉落 34.5%、手内旋转不到位 18.2%、抓取失败 3.6%。

## Q11. 既然有位姿丢失，这篇文章到底改进了什么？以前的方法也会丢吗？

**成功率并不低**：24 个任务的 Task Progress 平均约 79%（由 Table II 计算得出，论文未直接给这个总平均）。橡皮擦四项全是 100%，最差是短螺丝刀竖直旋转 37.9%。

**改进的是泛化能力，不是感知**。位姿跟踪用的是现成的 FoundationPose，没有改进。

| 对比对象 | 对方的问题 | 对方成绩 | 本文成绩 |
|---|---|---|---|
| 运动重定向（把人手动作直接映射给机器手） | 只管几何位置不管接触力，抓不住 | 8.1% / 0% | 98.0% / 82.7% |
| 固定抓取（抓住后手不动，只靠手臂） | 不能手内旋转，需要旋转时手臂撞桌子 | 61.0% / 10.8% | 同上 |
| 专用策略（针对单一物体和轨迹训练的 RL） | 换物体或换轨迹就崩 | 训练设置上约 100%，换了之后跌到 10% 以下 | 三种设置下都高 |

（前两行是真机上红色刷子扫地任务的两个变体：不需要旋转 / 需要旋转 90°。第三行是仿真实验。）

**以前的方法会不会丢**，取决于方法是否依赖位姿跟踪：

- 同样以物体位姿为输入的方法：会有同样的问题。
- 运动重定向：不会，因为它开环回放手的轨迹，不看物体。但这正是它失败的原因。
- 直接看图像的端到端策略：没有这种形式的失败，但要么需要遥操作数据，要么面对图像层面的 sim-to-real gap。

位姿丢失是"以物体为中心"这个设计的代价：绕开了视觉上的仿真现实差距，换来的是依赖外部跟踪器。论文没有拿跟踪丢失率和以前的方法比较。

## 一句话总结

把所有工具任务统一成"让工具依次到达一串目标位姿"，于是只需要在仿真里用一个固定奖励、在随机形状和随机目标上训练一次；任务和工具的差别全部放进输入（目标位姿序列 + 手柄包围盒），而不是靠重新训练来适应。
