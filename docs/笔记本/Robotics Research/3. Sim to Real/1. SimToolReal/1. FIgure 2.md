# SimToolReal Figure 2 阅读笔记

论文：*SimToolReal: An Object-Centric Policy for Zero-Shot Dexterous Tool Manipulation*（arXiv 2602.16863v3）

说明：标注"（通常做法）"的内容是机器人领域的一般情况，论文没有写具体细节。

## Figure 2 在画什么

图分上下两行，中间都是同一个 "Object-Centric Policy" 方块。

- **上：Training in Simulation**。随机挑一个程序生成的几何体 → 随机生成目标位姿 → 策略控制 29 个关节的手臂和手去完成。
- **下：Inference in Real**。从 DexToolBench 里拿一个真实工具 → 目标位姿来自人类视频（图上标的 1、2、3）→ 同一个策略控制真实机器人完成。

要点：**上下两行的策略是同一个，区别只在喂给它的物体和目标位姿。**

## Q1. 什么是 goal-conditioned RL policy？

拆成三部分：

- **Policy（策略）**：就是那个神经网络。输入是机器人当前看到的信息，输出是下一步怎么动。本文输出 29 个关节的目标位置（手臂 7 个 + 手 22 个）。
- **RL**：这个网络是用强化学习、靠试错和奖励训练出来的。
- **Goal-conditioned（以目标为条件）**：**目标本身是网络的一个输入**。同一个网络，给不同的目标就做不同的事。

| | 普通 RL 策略 | Goal-conditioned 策略 |
|---|---|---|
| 目标在哪 | 写死在奖励里，训练完就固定 | 每次运行时作为输入给它 |
| 换个目标 | 重新训练 | 换个输入就行 |
| 类比 | 公交车司机，只会开一条固定线路 | 出租车司机，报地址就开过去 |

论文公式：**a = π(s, o, φ, g)**

| 符号 | 含义 |
|---|---|
| a | 输出的动作（29 个关节目标） |
| s | 机器人自身状态（关节角度、速度等） |
| o | 工具当前的 6D 位姿 |
| φ | 工具的粗略描述（手柄的包围盒） |
| g | 目标位姿，这就是"条件" |

对应到 Figure 2：

- 上面（仿真训练）：物体是随机几何体，g 是随机生成的
- 下面（真机）：物体是真实工具，g 是从人类视频提取的位姿序列

这就是"任务的差别放进输入里，而不是靠重新训练"的具体形式。

## Q2. 什么是 DexToolBench？

名字是 Dexterous + Tool + Benchmark。**Benchmark 就是一套标准考题**，让不同方法在同样的题目上比成绩。

它是本文作者自己做的测试集，专门考灵巧手用工具。理由：现有测试集要么是给平行夹爪用的，要么只考抓取，没有考"抓起来 → 手内转好 → 使用"这一整套的。

内容：6 类工具，每类 2 个实物、2 种任务，共 12 个物体、24 个任务。

| 工具 | 两个实物 | 两种任务 |
|---|---|---|
| 锤子 | 羊角锤、橡胶锤 | 向下砸、侧向砸 |
| 马克笔 | Sharpie、Staples | 画笑脸、写字母 C |
| 板擦 | 带柄的、扁平的 | 擦掉笑脸、擦掉 C |
| 刷子 | 蓝色、红色 | 向前扫、向右扫 |
| 锅铲 | 勺形、平铲 | 盛到盘子里、翻面 |
| 螺丝刀 | 长的、短的 | 竖着转、横着转 |

其他要点：

- 每道题由一段人类演示视频定义，用带深度的相机（ZED 1）拍摄。
- 评分指标是 **Task Progress**：机器人让工具跟上了视频里百分之多少的目标位姿，误差 2cm 以内算到达。
- 评测是闭环的：到达当前目标后才切换到下一个，不要求和人的演示速度一致。
- 每个任务既有真机版本，也有对应的仿真版本。
- 这些工具在训练时全都没出现过。DexToolBench 是考场，不是教材。

## Q3. 为什么说"把 policy zero-shot 部署到 DexToolBench 上"？不应该是部署到机器人上再去考吗？

理解是对的，论文的说法是省略。图注原话是 *deploy this policy zero-shot **on real-world tools from** DexToolBench*，完整意思是：

> 把训练好的策略装到真实机器人上，然后用 DexToolBench 里的工具和任务去考它。

论文里常说"在某某 benchmark 上部署/评测"，省掉了中间的机器人。

## Q4. 模型是一堆参数，机器人是硬件，怎么把模型"装"到机器人上？

模型并不是装进机器人身体里的。实际布置（通常做法）：

- **一台带显卡的电脑**，放在机器人旁边。模型是硬盘上的一个文件，里面是网络参数。电脑上跑一个程序把它加载进来。
- **机器人**通过线缆连到这台电脑。
- **相机**也连到这台电脑。

机器人自带两样厂家做好的东西：

- 每个关节里有**传感器**，报告关节现在转到了多少度
- 每个关节有**电机和底层控制器**，告诉它"转到 30 度"，它自己驱动电机转过去并保持

所以神经网络不需要懂电流电压，只要输出 29 个数（每个关节该转到多少度），剩下的由机器人自带的控制器完成。

论文明确写的部分：手臂是 7 自由度的 KUKA iiwa 14，手是 22 自由度的 Sharpa 五指左手；策略输出关节位置目标；用 FoundationPose 以 30Hz 做位姿跟踪。

## Q5. 机器人是怎么动起来的？

电脑上的程序每秒重复几十次下面这个循环（仿真里的控制频率是 60Hz）。示意，不是论文的真实代码：

```python
不停重复：
    关节状态 = 机器人.读取关节角度和速度()      # 从关节传感器读
    画面 = 相机.拍一帧()
    工具位姿 = FoundationPose(画面)            # 视觉模型算出工具在哪
    如果 工具位姿离当前目标足够近：
        当前目标 = 视频轨迹里的下一个位姿
    动作 = 策略网络(关节状态, 工具位姿, 包围盒, 当前目标)   # 数字进，29 个数字出
    机器人.发送关节目标(动作)                   # 通过线缆发过去
    # 机器人自带的控制器驱动电机转到目标角度
```

和仿真训练时的循环对比：

| | 仿真里 | 真机上 |
|---|---|---|
| 关节状态从哪来 | 仿真器算出来的 | 关节传感器读出来的 |
| 工具位姿从哪来 | 仿真器给的（再人为加噪声） | 相机 + FoundationPose 估出来的 |
| 目标位姿从哪来 | 随机生成 | 人类视频里提取 |
| 动作发给谁 | 仿真器 | 真实机器人 |
| 下一时刻怎么产生 | 仿真器计算 | 真实物理世界自己发生 |
| 策略网络 | 同一个 | 同一个 |

**"部署"的实质：把循环里的仿真器换成真实的机器人和相机，中间的神经网络原封不动。** 网络只认数字，只要送进去的数字格式和训练时一样，它并不知道自己面对的是仿真还是现实。

这也解释了两件事：

- **训练时为什么要加噪声和延迟**：真机上这些数字来自传感器和视觉模型，本来就不准、本来就慢，要让网络提前习惯。
- **位姿跟踪丢失为什么致命**：循环里"工具位姿"那一行给出了错误的数，后面全跟着错。

## 一句话总结

Figure 2 表达的是：同一个以目标为输入的策略，训练时在仿真里拿随机几何体追随机目标，测试时换成真实机器人、真实工具和人类视频里的目标，中间不做任何再训练。
