## Related Work 的结构

三段，分别对应三条技术路线，每段结尾都落到"本文和它们的区别"：

| 段落 | 路线 | 它的问题 | 本文的立场 |
|---|---|---|---|
| Imitation Learning from Teleoperated Data | 人遥操作示范，机器人模仿 | 数据难采，复杂技能示范不出来 | 完全不用遥操作 |
| Learning Dexterity from Human Video | 从人类视频学 | kinematic 抓不住；functional 每个任务要重新训练 | 一次训练，任何视频直接用 |
| Sim-to-Real Learning | 仿真里强化学习再迁移 | environment shaping 工作量大，只能做很窄的技能 | 随机物体 + 统一奖励，不按任务重做 |

## Q1. 什么是 kinematic motion retargeting？

原句：*Kinematic motion retargeting pipelines can translate human hand motions into robot actions by reconstructing hand–object interaction.*

翻译：运动学动作重定向流程，可以通过重建手与物体的交互，把人手的动作转换成机器人的动作。

**拆词**

- **motion retargeting（动作重定向）**：把一个身体的动作搬到另一个身体上。来自动画行业（动捕演员 → 虚拟角色）。这里是把人手的动作套到机器手上。
- **kinematic（运动学的）**：只管几何（在哪、什么角度、怎么动），不管力。管力的叫动力学（dynamics）。
- **pipeline**：流程，一连串处理步骤。

合起来：**一套只从几何上把人手动作照搬给机器手的处理流程。**

**具体步骤**（论文附录 H、Figure 14，本文把它当对比基线）

1. 拍一段人用手做任务的视频
2. 用视觉模型 HaMeR 估计每帧里人手的姿态（手腕、指尖位置）
3. 用深度图把估计校准得更准（ICP 对齐）
4. 用逆运动学（IK）求解机器人关节角度，让机器手的手掌和指尖到达人手对应的位置。IK 的意思是：已知"指尖要到这里"，反推"每个关节该转多少度"
5. 机器人照着算出的关节角度序列播放

**优点**：不需要训练，有视频就能直接算出动作。

**为什么抓不住工具**

- 位置对了不等于握住了。握住需要对物体施加足够的压力，重定向只管指尖到位，不管有没有压紧。
- 人手和机器手不一样，指尖放到同样位置，机器手可能没碰上或压得不对。
- 开环回放，不看工具实际在哪，滑了、没抓起来也照样继续。

实验结果：扫地任务两个变体，成绩 8.1% 和 0%（Figure 5 最右列）。

## Q2. 什么是 functional retargeting？

functional 是"功能上的"：**不追求机器手的动作像人手，只追求最后的效果一样。** 即让工具的运动和人演示时一样，机器手怎么握由它自己用强化学习摸索。

它是为了解决 kinematic retargeting 抓不住东西而出现的。

| | Kinematic retargeting | Functional retargeting |
|---|---|---|
| 对齐什么 | 人手的姿势 | 任务的结果（物体的运动） |
| 机器手怎么握 | 照搬人手 | 自己用强化学习摸索 |
| 要不要训练 | 不要 | 要 |

## Q3. 为什么 functional retargeting "require time-intensive RL training where the resulting policy is limited to the demonstrated manipulation task and object"？

因为它每拿到一段演示就要走一遍这个流程：

1. 拿到一段人的演示（比如用红刷子向前扫）
2. 在仿真里建出这把红刷子的模型
3. 设定目标：让刷子按演示里的轨迹运动
4. 从头跑一次强化学习
5. 部署到真机

- **time-intensive（耗时）**：第 4 步每次都是完整的 RL 训练，加上第 2 步建模，每个演示都要付一遍。
- **limited（受限）**：策略只见过一把刷子、一条轨迹，相当于背下了一道题的答案，换工具或换方向就不会了。

论文的 specialist 基线就是这类方法，Figure 6（仿真中）：

| 测试条件 | 专用策略 | 本文 |
|---|---|---|
| 训练时的物体 + 训练时的轨迹 | 约 100% | 约 98% |
| 同一物体，换一条轨迹 | 约 10% | 约 92% |
| 同一轨迹，换一个物体 | 约 3% | 约 94% |

## Q4. 本文和 functional retargeting 的区别是什么？为什么更好？

思路一脉相承：都只跟随物体的运动，都让机器手自己摸索握法。区别在**训练发生在什么时候、针对什么**。

| | Functional retargeting | 本文 |
|---|---|---|
| 流程 | 拿到演示 → 训练 → 部署 | 先训练一次 → 之后任何演示都直接部署 |
| 训练用的物体 | 演示里的那一个 | 大量随机几何体 |
| 训练用的轨迹 | 演示里的那一条 | 随机目标位姿 |
| 演示视频的作用 | 训练目标 | 只是运行时的输入 |
| 训练次数 | 每个演示一次 | 总共一次 |

一句话：别人是看到题目再去学，本文是先把通用的本事学好，题目来了直接做。

**好在哪**

- 省：新任务、新工具不需要再建模和训练。
- 泛化：学到的是通用的抓握和手内旋转能力。

**"更好"的范围要说准**

- 在专用策略训练过的那个设置上，本文只是持平，没有超过。论文措辞是 *matching the performance of specialist policies*。优势体现在换物体、换轨迹时。
- 通用性有边界：只适用于"手柄 + 头"这类刚性工具，只保证跟上位姿，不保证任务真的完成。

## Q5. 本文的时间优势是"只训练一次"，那强化学习本身是不是一样费时？

机制一样，都是试错。但单看一次训练，本文的那一次**更贵**，不是一样。原因：专用策略只学一个物体走一条轨迹；本文要同时学成千上万种形状和任意目标位姿，探索范围大得多。Figure 7 里通用策略训练到了上千亿步。论文没给专用策略的训练步数，所以没有具体倍数。

优势在**分摊**：

| | Functional retargeting | 本文 |
|---|---|---|
| 一次训练的成本 | 较小 | 较大 |
| 需要训练几次 | 每个新工具、新任务一次 | 总共一次 |
| 第 N 个新任务的额外训练成本 | 又一次完整训练 | 零 |

任务只有一两个时专用策略更划算；任务越多本文越占优。

本文对每个新任务仍需拍视频并处理（重建网格、分割手柄、提取位姿轨迹），但这是数据处理，不是训练。

## Q6. Kinematic retargeting 为什么"不需要训练"？它不也用了别人做好的模型吗？

对，它用了。准确的说法是：**不需要为这个任务训练任何东西**，而不是流程里没有神经网络。

要区分**使用一个训练好的模型**和**训练一个模型**。

| 步骤 | 用了什么 | 算不算训练 |
|---|---|---|
| 从视频估计人手姿态 | HaMeR，现成的视觉模型 | 不算，直接拿来用 |
| 分割出手的区域 | SAM 2，现成的视觉模型 | 不算，直接拿来用 |
| 用深度图校准手的位置 | ICP，几何对齐算法 | 不算，是计算 |
| 把手的姿态转成机器人关节角度 | 逆运动学（IK），解方程 | 不算，是计算 |

最终得到的是一张固定的关节角度时间表，没有产生任何新的、学出来的策略。

本文同理：SAM 3D、SAM 2、FoundationPose 都是直接拿来用的现成模型，自己训练的只有控制策略。三种方法的区别只在控制这一环：

| 方法 | 控制部分怎么来的 |
|---|---|
| Kinematic retargeting | 不训练，用几何计算直接算出动作 |
| Functional retargeting | 每个任务训练一个策略 |
| 本文 | 训练一个通用策略，所有任务共用 |

## Q7. "Policies learned in simulation can acquire dexterous manipulation behaviors without relying on human demonstrations, but transferring these skills to the real world often requires substantial environment shaping" 是什么意思？

翻译：在仿真中学出来的策略，可以不依赖人类演示就掌握灵巧操作的动作；但要把这些技能迁移到真实世界，往往需要大量的 environment shaping。

**Environment shaping**

强化学习里的 environment（环境）指策略训练时面对的一切设定：

- 场景里的物体及其形状、质量、摩擦
- 策略能看到什么（观测）、能控制什么（动作）
- 怎么打分（奖励）
- 每一局怎么开始、什么时候结束
- 加多少噪声和延迟

shaping 是"塑造、打磨"。所以 environment shaping 就是：**工程师手工设计并反复调整这些设定，直到强化学习能学出想要的行为，并且搬到真机上能用。**

它就是摘要里 "substantial engineering effort" 的正式叫法（见摘要笔记 Q7）。论文下一句列出它包含的三件事：

1. 缩小 sim-to-real gap
2. 给每个任务建精确的物体模型
3. 给每种行为设计和调试奖励

本文的做法：第 2、3 项不再按任务重做，只剩第 1 项做一次。

## Q8. 说"不依赖人类演示"，但它不也是用人类数据训练出来的吗？

不是。本文的策略**训练时没有用任何人类数据**，人类视频只在测试时出现。

| | 训练（仿真里） | 测试（真机上） |
|---|---|---|
| 物体 | 程序随机生成的几何体 | 真实工具 |
| 目标位姿 | 程序随机生成 | 从人类视频提取 |
| 用到人类数据吗 | 没有 | 有，一段视频 |
| 这段数据的作用 | — | 告诉策略"要做什么"，不改变策略 |

**区分人能提供的两种信息**

1. **怎么做**：手指怎么动、怎么握、用多大力。模仿学习需要这个，遥操作采集的就是它，原句里的 human demonstrations 指的也是它。
2. **做什么**：工具应该怎么运动。这是任务本身的定义，任何方法都需要有人指定。

强化学习不需要第 1 种。本文测试时用的视频属于第 2 种，而且只提取工具轨迹，人手怎么握的信息被丢掉了。类比：对出租车司机报了目的地，他开车的本事不是你教的。

**两点补充**

- 人仍以"设计"的方式参与训练：写奖励、搭仿真、调噪声。这些是规则，不是示范数据。
- Functional retargeting 那类方法在训练时确实用了人类演示（把物体轨迹当训练目标），但用的也只是第 2 种信息。本文更进一步，把它挪到了测试时。

## Q9. 训练时的目标位姿真的是随机生成的？不是从视频里重建的？

是随机生成的。引言原话：策略 *trained exclusively on procedurally-generated primitives with randomly sampled goal pose trajectories*。

**怎么随机**（Section III-B、附录 C）

1. **第一个目标**：在桌子上方一个长方体空间里均匀随机选位置，朝向随机。空间约为左右 70cm、前后 30cm、离桌面 15 到 52cm。
2. **后续目标**：到达当前目标后，下一个在**上一个目标附近**随机生成，位置最多偏 10cm，朝向最多转 90°。

第一个目标远且朝向任意，逼出抓取和大幅旋转；后续目标挨着前一个，连起来像一条连续轨迹，模仿真实任务。

**容易混淆的地方**

- Figure 3 左半边的 Human Video Processing 看起来像训练的一部分，但整张图标题是 Real-World Deployment，画的全是训练之后的事。
- Specialist 基线才是用视频轨迹训练的。

| | 训练时的目标位姿 | 测试时的目标位姿 |
|---|---|---|
| 本文 | 随机生成 | 从人类视频提取 |
| Specialist 基线 | 人类视频提取的一条固定轨迹 | 同一条或另一条视频轨迹 |

**为什么随机的反而行**

真实任务的轨迹只是"所有可能位姿"里的一小部分。任意位姿都能到达，特定轨迹自然也能跟上。这是文章的核心假设，Figure 7 是它的证据：随机目标上的得分和真实工具轨迹上的表现同步提高。

## Q10. 部署时是不是自己生成一段未来的视频，再从里面重建位姿去执行？

不是。用的是**真人事先录好的视频**（ZED 1 深度相机拍摄）。

顺序：

1. 事先：人拿着工具用自己的手把任务做一遍并录像
2. 事先：离线处理视频，得到工具的 3D 网格、手柄包围盒、位姿轨迹。轨迹抽稀到每秒 3 个位姿，并去掉开头工具躺在桌上不动的那段
3. 执行时：机器人面前放同一把工具，策略按顺序追这串位姿

这串位姿确实描述了机器人"接下来"要让工具走的路线，但来源是过去的真人演示。

**"生成未来视频"这个做法确实存在**

论文 Related Work 提到：有工作把视频生成模型合成的演示转成机器人轨迹（引用 [57, 37, 12]），也有用 AI 生成视频做 functional retargeting 的（引用 [50]）。

本文的策略只认"一串目标位姿"，原理上不关心来源。但：

- 论文没有这么做，所有实验都用真人录像。
- 论文的处理流程依赖深度信息保证尺寸准确，生成的视频通常没有深度（我的解释）。

相关的局限：目标序列固定，执行中不会重新规划。纸团没扫进去，它不会自己再扫一次。

## Q11. "Domain randomization over physical and visual parameters and adaptation methods that infer real-world dynamics online" 是什么？

完整句子的意思：对物理参数和视觉参数做域随机化，以及在线推断真实世界动力学的自适应方法，可以显著缩小 sim-to-real gap。

它列举了两类技术。

**第一类：域随机化**

训练时让仿真设定在一个范围内随机变化（详见摘要笔记 Q5）。随机化的对象有两种：

- **物理参数**：质量、摩擦、关节阻尼、延迟、外力等。本文做的是这种。
- **视觉参数**：光照、颜色、纹理、相机位置等。给直接看图像的策略用。本文策略不看图像，用不着。

**第二类：在线自适应**

- dynamics（动力学）：物理特性，东西受力后怎么反应（多重、多滑）
- infer（推断）：没法直接测，只能从现象猜
- online（在线）：运行过程中实时进行
- adaptation（自适应）：猜出来后调整行为

合起来：**机器人一边干活，一边根据刚才发生的事推断当前的物理状况，并据此调整动作。** 例子：拿起没见过的箱子，手上一沉就知道它重，于是加大力气。

实现上通常专门训练一个小模块：输入最近一段状态和动作历史，输出对当前物理特性的估计，交给策略。代表工作是论文引用的 RMA。

| | 域随机化 | 在线自适应 |
|---|---|---|
| 思路 | 练出一套各种情况下都能用的做法 | 先判断是哪种情况，再对症调整 |
| 类比 | 穿一双什么路面都能走的鞋 | 踩上去感觉路面，再调整步子 |
| 缺点 | 偏保守 | 多一个模块，推断错了会出问题 |

**本文用了哪个**

- 域随机化：用了，只做物理参数。
- 在线自适应：没有单独的模块，但用了同样的思想。策略用 LSTM 做骨干，靠记忆从交互历史里隐式推断工具的轻重和形状。

原文后面的转折：即使有这两类技术，灵巧操作的 sim-to-real 仍需按任务做工程，所以大家只能做很窄的技能（只抓取、只手内旋转、只转笔）。

## 一句话总结

Related Work 把已有路线分成三类并指出各自的短板：遥操作采不到复杂技能；kinematic retargeting 抓不住，functional retargeting 每个任务要重训；sim-to-real RL 按任务做 environment shaping 太费工。本文的位置是：沿用 functional retargeting "只跟物体运动"的思想和 sim-to-real RL 的训练方式，但把训练改成对随机物体、随机目标只做一次，把人类视频从训练目标变成运行时的输入。
