### 这篇论文提出了什么

这篇论文提出的是一个**统一的双向模型**，标题里就写了 **Bidirectional Sonar–Optical Translation**。而且 Figure 1 也直接写了两个方向：

- Sonar → RGB
- RGB → Sonar

并说明 **“A single diffusion bridge serves both directions”**。

### 但“一个模型”不等于“两个方向完全一样”

论文的关键创新不是单纯把两个任务塞进一个模型里，而是：

- **共享一个主干（shared diffusion-bridge trunk）**
- 但是对两个方向分别走不同的物理先验路径

因为 sonar→RGB 和 RGB→sonar 的成像物理过程不一样。论文把这个叫做 **DARB (Direction-Asymmetric Realism Bridge)**。

**更准确地说，不是“同时一起转”，而是“一个模型都能做”**

### 解析
Sonar→RGB 和 RGB→Sonar 这两个方向，在模型结构/随机过程里被当成“地位相同、可以互换”的两个方向。

这篇论文先说，Brownian bridge 这一层本身是对称的。它把两个端点都放进同一个随机过程里：

$$ x_t=(1-m_t)x_0+m_ty+\sigma_t\epsilon $$

这里 $x_0$ 是 target，$y$ 是 source。论文强调，这个公式本身没有用到方向变量 $d$，所以从 stochastic process 的角度，两个方向是对称的。

你可以把它想成一座桥：

$$ A \leftrightarrow B $$

桥本身并不偏向 A→B 还是 B→A。你从左边走到右边，或者从右边走到左边，桥还是那一座桥。

所以在这篇论文里：

$$ \text{Sonar} \leftrightarrow \text{RGB} $$

shared diffusion bridge 本身把两个方向当成对等的。

但问题来了：真实物理并不对称。

Sonar→RGB 要补的是颜色、光照、纹理；RGB→Sonar 要生成的是声学回波、speckle、shadow 等东西。论文明确说，这两个方向缺失的信息不同，所以物理任务本身是 asymmetric。

所以作者的核心观点其实就是一句话：

模型底层的 bridge 可以是 symmetric，但物理处理不能 symmetric。

这也是为什么他们后面说：

“We keep the shared substrate and put back only what the physics requires.”

意思就是：共享的 bridge 保留，但在真正需要的地方重新加入方向不对称性。

最简单记法就是：

对称性 = 两个方向在基础模型里被同等对待；不对称性 = 两个方向的真实物理规律不同，所以不能完全用同一套处理。

## 1. Introduction
## 1.1 
Such a translator requires a framework in which neither direction is privileged. Conditional formulations privilege one: the source conditions a process synthesising the target, so the roles are not exchangeable. Diffusion bridges instead anchor the process at both endpoints, the natural substrate for a unified model这里我完全看不懂他在说什么
### 解析
**conditional formulation 到底是什么**？这里的 `conditional` 就是**有条件地生成**。

最简单的例子：你想让模型根据一张 sonar 图，生成对应的 RGB 图。

那这个任务可以写成：

$$\text{Sonar} \rightarrow \text{RGB}$$

这里 sonar 不是被生成的东西，而是**条件 condition**。

也就是说，模型在生成 RGB 的时候，不是凭空生成，而是“看着这张 sonar 图来生成”。

可以写成：

$$p(\text{RGB}\mid \text{Sonar})$$

这个式子读作：

> 在已经知道 Sonar 的条件下，RGB 是什么样。

这里：

$$\text{Sonar}=\text{condition} \ \ \ \ \ \\ \ \ \ \text{RGB}=\text{target}$$

这就叫 **conditional generation**。

### 我的第二个疑问

为什么不能训练一个模型既能计算 $p(RGB|Sonar)$ 又能计算 $p(Sonar|RGB)$？

### 解析
答案是：**当然可以。**

而且你这个问题本身正好说明，论文那句话容易让人误会。论文不是说“conditional model 绝对做不到双向”，而是在说：**普通 conditional generation 的一次生成过程，总得先规定谁是输入条件，谁是要生成的目标。**

比如第一次：

$$\text{Sonar} \rightarrow \text{RGB}$$

你告诉模型：

- Sonar 是输入
- RGB 是输出

第二次：

$$\text{RGB} \rightarrow \text{Sonar}$$

你又告诉模型：

- RGB 是输入
- Sonar 是输出

所以虽然**同一个神经网络完全可以被训练去做这两件事**，但是对“某一次生成”来说，角色还是固定的：

$$\text{source} \rightarrow \text{target}$$

这就是论文说：

> the source conditions a process synthesising the target

你可以直接翻译成：

> **先指定一个 source，把它作为输入条件，再生成 target。**

然后：

> so the roles are not exchangeable

不是说“永远不能交换”。

而是说：

> **在这一次生成过程中，source 和 target 不是同一个角色，不能不加任何说明就直接互换。**

举个最简单的类比。

假设有一个翻译模型，我告诉它：

$$\text{Chinese} \rightarrow \text{English}$$

当然我可以把同一个模型训练成也会：

$$\text{English} \rightarrow \text{Chinese}$$

但是我每次使用的时候，模型还是得知道：

> “这次输入的是中文，我要输出英文。”

或者：

> “这次输入的是英文，我要输出中文。”

不能什么都不告诉它，就让它自己猜“谁是 source，谁是 target”。

所以论文真正想说的不是：

> conditional formulation 不能做双向。

而是：

> conditional formulation 的基本形式，本身就是一个**有方向的** source→target 生成过程。

也就是：

$$A \rightarrow B$$

而 diffusion bridge 从数学结构上更像：

$$A \leftrightarrow B$$

两边都直接是 bridge 的 endpoint，所以作者觉得它更适合作为统一双向模型的“底座”。论文原文这里就是在做这个对比。

最重要的是：**你刚才“为什么不能一个模型同时学两个 conditional distribution”的质疑是成立的。能。论文这里强调的是结构天然是否对称，不是在证明 conditional model 做不到双向。**

### 1.2
We introduce the Direction-Asymmetric Realism Bridge (DARB), which shares one diffusion-bridge trunk and makes asymmetric only what the imaging physics forces to be asymmetric.这个什么意思

### 解析

> 我们提出 DARB。它让两个方向共享同一个 diffusion-bridge 主干；只有那些由于 Sonar 和 RGB 成像物理不同、必须区别处理的部分，才做成不对称。

这里最重要的是两层。

第一层，**大部分网络是共享的**。

也就是 Sonar→RGB 和 RGB→Sonar 都经过同一个 shared trunk：

$$\text{Sonar/RGB} \rightarrow \boxed{\text{shared diffusion-bridge trunk}} \rightarrow \text{...}$$

所以它仍然是一个 unified model，不是两个完全独立的模型。论文明确说它是一个 shared trunk。

第二层，**某些地方不共享**。

为什么？因为两个方向对应的物理现象不同。

Sonar→RGB 这边，作者关心的是水下光学里的 range-dependent attenuation 和 backscatter，所以走 UAM。

RGB→Sonar 这边，作者关心的是 sonar 的 fan-shaped support 和沿 ray 产生的 shadow，所以走 SPADE + RCASM。

所以整个模型更像：

$$\text{input} \rightarrow \boxed{\text{shared trunk}} \rightarrow \begin{cases} \mathrm{UAM}, & \text{Sonar}\rightarrow\text{RGB}\\ \mathrm{SPADE+RCASM}, & \text{RGB}\rightarrow\text{Sonar} \end{cases} \rightarrow \text{output}$$

那它怎么知道该走哪个模块？就是你刚刚问的那个点：**用方向变量 $d$ 做 hard routing。**

$$\begin{aligned}
\\& d=0  \Rightarrow \text{走 UAM}
\\& d=1 \Rightarrow \text{走 SPADE+RCASM}
\end{aligned}$$

论文 Figure 2 的 caption 就直接说，方向标量 $d$ 决定 forward pass 经过哪一个 physical operator。

所以这句话最核心的意思就是：

> **能共享的主干全部共享；只有 Sonar 和 RGB 的物理机制真正不同、没法用同一种处理时，才通过方向 $d$ 切到不同的小模块。**

因此：

$$\text{DARB} = \text{shared trunk} + \text{direction-specific small modules}$$

不是“两个模型”，也不是“所有东西完全一样”。而是**一个模型里，大部分共享，少部分按方向分支。**

## 3. Method
### 3.1
为什么要定义那个噪声？

### 解析：

因为如果没有噪声，这条 “bridge” 基本就只是**两个端点之间的一条确定性直线插值**：

$$x_t=(1-m_t)x_0+m_ty$$

这样每个 $t$ 都只有唯一一个中间状态。

但 Brownian bridge 本质上是一个**随机过程**，所以作者加了：

$$\sigma_t\epsilon$$

其中

$$\epsilon\sim\mathcal N(0,I)$$

来让同一个 $t$ 不只有一个固定的 $x_t$，而是有一整片可能的中间状态。

所以变成：

$$x_t=(1-m_t)x_0+m_ty+\sigma_t\epsilon$$

你可以理解成：

> 直线插值决定“平均应该在什么位置”，噪声决定“在这个平均位置附近随机晃动多少”。

而且这个噪声不是随便加的。论文定义：

$$\sigma_t^2=2m_t(1-m_t)$$

所以在两端：

$$\begin{aligned}
\\&t=0\Rightarrow m_t=0\Rightarrow \sigma_t=0
\\&t=T\Rightarrow m_t=1\Rightarrow \sigma_t=0
\end{aligned}$$
也就是说 bridge 两头必须严格落在真实端点上，不能被噪声扰乱。

而中间的时候噪声比较大，让中间状态形成一个随机分布，而不是一条死板的直线。论文正是这样定义 latent Brownian bridge 的。

最简单地记：

> **线性部分负责“从哪边走到哪边”，噪声负责“让这条桥成为一个随机生成过程，而不是简单插值”。**

至于为什么生成模型需要这种随机性，一个很重要的原因是：Sonar→RGB 本身就是 one-to-many，同一张 sonar 可能对应不止一种合理的 RGB 外观，所以不能只允许唯一确定的中间路径。论文前面也强调过这种不确定性。
