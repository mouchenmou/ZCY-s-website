## 0. Abstraction

### 0.1 
cloud inference啥意思，pond-side connectivity啥意思。local inference为什么会independently excuting detection and segmentation networks？我对这些一点概念都没有他也完全不解释
### 解析：
### 0.1.1 **cloud inference** 就是：

> 模型不是在鱼塘旁边的设备上运行，而是把摄像头拍到的视频通过互联网传到远程服务器 / 云服务器，在服务器上跑神经网络。

可以想成：养虾场在台湾，服务器可能在某个数据中心。摄像头源源不断拍视频：

```
pond camera
    ↓
video stream
    ↓
Internet
    ↓
cloud server
    ↓
YOLO / segmentation model
    ↓
results
```

这就是论文说的 **continuous cloud inference**。

#### 0.1.2. 为什么 cloud inference 需要 `sustained video transmission`？

`sustained` 就是**持续不断的**。

因为摄像头不是只传一张图，而是不断地产生视频帧。

假设摄像头：

$$30\ \text{FPS}$$

那就是每秒 30 张图片。

如果你全部送到云端处理，就得不断把视频上传到服务器。所以作者说需要 sustained video transmission，也就是**持续的视频传输**

问题是视频数据量很大。哪怕只是一条普通视频流，也可能每秒好几 Mbps。如果一个养殖场几十个摄像头：

$$\text{camera}_1 + \text{camera}_2 + \cdots + \text{camera}_{20}$$

全部持续往云端传，就非常依赖网络。


#### 0.1.3. `pond-side connectivity` 是什么？

**池塘现场的网络连接条件**

`pond-side`：

> pond = 池塘  
> side = 旁边

所以：

> pond-side connectivity

就是：

> **养殖池塘现场有没有稳定的 Wi-Fi / Ethernet / 4G / 5G / Internet**

论文前面说：

> reliable pond-side connectivity

意思就是：

> 池塘边必须有稳定可靠的网络。

很多养殖场可能比较偏远，因此网络不一定很好。论文明确把 cloud inference 的问题描述成依赖网络可用性和图像传输带宽。如果这里 Wi-Fi断了、4G很差、带宽不够，那么云端模型就没法稳定实时工作。

#### 0.1.4. `local inference` 是什么？

就是直接把计算设备放在养虾场。

这样你就不用：

```
camera → Internet → cloud
```

而可以：

```
camera → Raspberry Pi
```

因此论文说：

> Local inference reduces this dependency

这里的 `dependency` 就是：

> 对持续互联网连接和视频上传的依赖。

#### 0.1.5. 你问得最关键的一点：为什么 local inference 会 “independently executing detection and segmentation networks”？

这里你理解成因果关系了，但原文其实**不是说**：

> 因为 local inference，所以必须独立运行 detection 和 segmentation。

不是这个意思。

作者真正想说的是：

> 即使我们决定用 local inference，如果我们采用传统做法——分别运行一个 detection 网络和一个 segmentation 网络——那么树莓派会很吃力。

也就是说：


$$\text{local\ inference}≠一定要两个独立网络$$


而是他们在比较两种设计。

##### 1. 传统方案

需要完成两个任务：

1. 任务 1：
    shrimp detection：
	
	输入图像 $x$ 跑一个 YOLO：
	
	$$x \rightarrow \text{YOLO backbone} \rightarrow \text{YOLO neck} \rightarrow \text{shrimp boxes}$$

1. 任务 2：
	residual-feed segmentation
	
	同一张图再跑 PIDNet：
	
	$$x \rightarrow \text{PIDNet encoder} \rightarrow \text{segmentation head} \rightarrow \text{feed mask}$$

这就是 Independently executing detection and segmentation networks，即：**检测模型和分割模型各自单独跑一次。**

#### 0.1.6. 为什么这样不好？

因为你发现一个很明显的问题：

同一张图片被两个 CNN **分别处理了一遍**。

YOLO 会干：

$$\text{image} \rightarrow \text{feature extraction} \rightarrow \text{detection}$$

PIDNet 也会干：

$$\text{image} \rightarrow \text{feature extraction} \rightarrow \text{segmentation}$$

其中最耗计算的往往就是前面的 feature extraction，也就是 backbone / encoder。

**同一张图被提取两次特征。**

论文把这个叫 duplicates feature extraction，即：重复做 feature extraction。


#### 0.1.7. 这为什么在树莓派尤其是问题？

如果你有一张 RTX 5090，这点计算可能没那么要命。

但 Raspberry Pi：

- CPU 很弱；
- 内存有限；
- 没有强大的独立 GPU；
- 要求实时处理视频。

所以他们想：

> 既然两个任务看的都是同一张图片，能不能前面的 feature extraction 只算一次？

变成：

#### 0.1.8. 所以这篇文章到底想解决什么？


> **一张图只跑一次 PIDNet 特征提取，同时得到 feed segmentation 和 shrimp detection。**

你现在如果已经明白这里，我建议下一步直接继续看摘要里的 **“two-state shrimp detections / clean shrimp / count shrimp”**，这个也很容易第一次看懵，而且它跟“测虾长度”到底是什么关系需要单独解释。

### 0.2

我没搞懂为什么要把 yolo 弄过来，我也不清楚 yolo 具体的构造是什么我只是听过这个名字。我觉得要解决这个问题就只用训练一个网络既能做 detection 又能做 segmentation 就行了啊，为什么还要莫名其妙把 yolo 弄进来？

### 解析

假设图里有两只虾和一些饲料。
#### Detection 要的结果是这种

```
┌──────────┐
│   shrimp │
└──────────┘

             ┌────────┐
             │ shrimp │
             └────────┘
```

也就是**把每一个物体用 bounding box 框出来。**模型输出大概是：

$$(x_1,y_1,x_2,y_2,\text{class},\text{confidence})$$

比如：

```
虾1：框在这里，clean，置信度0.91
虾2：框在那里，count，置信度0.83
```

这篇文章检测虾的时候，还把虾分成两个类别：

- `clean`：适合后续测长度的虾
- `count`：能看见，但不适合测长度的虾

#### Segmentation

Segmentation 不给你一个框，它是**给每一个 pixel 分类。**

例如一张 $640\times640$ 图片，模型要判断每个 pixel 是 $\text{feed}$ 还是 $\text{background}$，最后得到一个 mask：

```
图片：

~~~~ shrimp ~~~~
~~~~~~~ feed~~~~
~~~feedfeed~~~~~

mask：

000000000000
000000111100
001111110000
```

其中：

$$\begin{aligned}
\\ &1=\text{feed} 
\\& 0=\text{background}
\end{aligned}
$$

所以：

- detection 回答：**“虾在哪里？”**
- segmentation 回答：**“哪些像素属于剩余饲料？”**

#### 那 YOLO 是干嘛的？

YOLO 就是一类非常经典的**Object Detection 模型。**

所以它最核心的工作就是：

$$\text{image} \rightarrow \text{bounding boxes + classes}$$

这篇文章需要做 shrimp detection，因此作者用了 **YOLOv9-T** 来负责找虾。

你可以暂时把 YOLO 当成一个黑盒：

```
图片
 ↓
YOLO
 ↓
这里一只虾
那里一只虾
每只虾给一个框
```

所以不是因为“这篇文章必须用 YOLO”。而是因为**他们需要一个现成的、比较成熟的 detection 模型，而他们选择了 YOLOv9-T。**

完全可以想象另一篇论文用：

- Faster R-CNN
- RetinaNet
- DETR

来做 detection。

YOLO 只是作者选的一种 detector。
#### 那 PIDNet 又是什么？

PIDNet 则主要是一个：

> **semantic segmentation 网络。**

所以它擅长：

```
图片
 ↓
PIDNet
 ↓
每一个 pixel 属于什么
```

这篇文章让 PIDNet 来做 residual-feed segmentation，也就是找剩余饲料的区域。

所以一开始你可以非常粗暴地理解：YOLO 负责找虾，PIDNet 负责找饲料区域

#### 你现在问的关键问题：

> 难道不能直接训练一个模型既能 detection 又能 segmentation 吗？

**当然能。**

而且你这句话实际上就是这篇论文要干的事情。作者就是想做：

$$\text{一个模型} \rightarrow \begin{cases} \text{shrimp detection}\\ \text{feed segmentation} \end{cases}$$

论文自己把它叫做 `shared multi-task network`

而且 Introduction 也直接说，共享 encoder 可以让 detection 和 semantic segmentation 从共同 feature 中在一次 forward pass 里产生。

所以你的直觉完全没问题。
#### 那为什么还要出现 YOLO 和 PIDNet？

因为一个模型同时做两件事不代表**从零发明一个完全陌生的神经网络**。最常见的做法反而是**拿两个已经很成熟的模型组件，拼成一个 multi-task model。**

比如作者知道 PIDNet 的 segmentation 很强，而且适合实时场景，YOLOv9-T 的detection 很成熟。所以他们想：

不要：

```
Image → PIDNet → segmentation
Image → YOLO → detection
```


而要：

```
             ┌→ segmentation head → feed mask
Image → shared features
             └→ YOLO detection part → shrimp boxes
```

#### 那为什么不直接让 PIDNet 自己也输出虾框？

也可以设计。

但是 PIDNet 原本是 segmentation architecture。

它已经有：

> segmentation head

但它没有成熟的：

> object detection head。

如果作者自己从零设计一个 detection head，就得重新解决一大堆东西，比如：

- 怎么做 box regression；
- 怎么做 classification；
- 怎么处理多个尺度的虾；
- 怎么处理重叠框；
- detection loss 怎么定义；
- feature pyramid 怎么设计。

而 YOLO 这些都已经帮你解决了。

所以作者思路很自然：

> **PIDNet擅长 segmentation，那我保留它。YOLO擅长 detection，那我把 YOLO 后半段拿过来。**

不是“为什么非得搞 YOLO”，而是：

> **YOLO 是他们拿来充当 detection branch 的现成工具。**

#### 最重要的是：原来的方案和论文方案有什么区别

你把这个对比记住，整篇文章就不会迷糊。

### 原始 naive 方案

```
                 PIDNet
               ↗
Image ─────────
               ↘
                 YOLO
```

实际上：

```
Image
 ↓
PIDNet整个网络
 ↓
feed segmentation
```

同时：

```
Image
 ↓
YOLO整个网络
 ↓
shrimp detection
```

所以同一张图片：

> 被两个网络各自理解一遍。
### 论文方案

作者把 YOLO 前面负责“看图”的部分砍了。

变成：

```
                       ┌→ PIDNet segmentation part
Image → PIDNet features
                       └→ YOLO detection part
```


也就是说：

> **PIDNet 负责共享的视觉特征提取。**

然后：

- 一个 branch 做 feed segmentation；
- 一个 branch 用 YOLO 的 detection machinery 做 shrimp detection。

所以这就是：

$$\boxed{\text{one shared model, two tasks}}$$

#### 甚至可以完全不提模型名字来理解这篇论文

你现在先把 `PIDNet` 和 `YOLO` 两个名字忘掉。

整篇论文其实就是：

```
过去：

一张图
 ↓
视觉网络A
 ↓
饲料分割

同一张图
 ↓
视觉网络B
 ↓
虾检测
```


问题：

> 计算了两遍，很慢。

作者：

```
一张图
 ↓
共享视觉网络
 ↓
共同特征
 ↙        ↘
饲料分割    虾检测
```

问题又来了：两个任务的数据不是同时标注的，所以共享网络不好训练。于是他们又发明**三阶段训练**。再然后：Raspberry Pi 还是嫌大。于是：缩小网络 + knowledge distillation。

所以整篇文章的逻辑其实非常干净：

$$\boxed{ \text{两个独立模型太浪费} \rightarrow \text{共享一个模型} \rightarrow \text{两个任务训练互相干扰} \rightarrow \text{三阶段训练解决} \rightarrow \text{再压小以适合 edge device} }$$

而 **YOLO 本身不是这篇论文的核心问题**。它只是作者选来负责“虾检测”的一个成熟 detector。真正的核心是：

> **怎样让 detection 和 segmentation 共用前面的特征提取，而又不让两个任务互相把对方学坏。**

### 0.3
![](附件/Pasted%20image%2020260922180158.png)
这一整段的各种专业术语我是一点也看不懂啊

### 解析
原文第一句：

> **We remove the GELAN backbone of YOLOv9-T**

YOLO 本身可以粗略拆成：

```
图片
 ↓
backbone
 ↓
neck
 ↓
detection head
 ↓
虾的框
```

其中：

- `backbone`：负责从图片里提取 feature；
- `neck`：整理不同尺度的 feature；
- `detection head`：最后输出框、类别、置信度。

作者想避免的重复计算。所以作者干脆**把 YOLO 的 GELAN backbone 删掉。**

论文方法部分明确说，删除 YOLOv9-T 的 layers 0–8，也就是它的 GELAN backbone，只保留 multiscale neck、detection head 和训练时的 PGI。

接下来：

> **connect scale-aligned proportional, integral, and derivative features from PIDNet**

这句话意思是：

> 把 PIDNet 产生的 P、I、D 三种 feature，送给 YOLO。

PIDNet 有三条主要分支：

```
P：空间细节
I：语义 / context
D：边界
```

你现在可以非常粗暴地理解：

```
P：细节看得清
I：知道整体是什么
D：知道物体边界在哪
```

但这里有个问题：

YOLO 想要的 feature 有不同大小。

例如：

```
80×80
40×40
20×20
```

因为 detection 要同时检测：

- 小目标；
- 中等目标；
- 大目标。

可是 PIDNet 各个 branch 出来的 feature 尺寸可能不一样。

比如：

```
P：80×80
I：40×40
D：80×80
```

你不能直接把 $80\times80$ 和 $40\times40$ 拼在一起。所以要先把它们调整到同一个尺度。这就是**scale-aligned**，意思就是：

$$把 PIDNet 的 feature 调整成 YOLO 需要的对应尺寸。$$


然后原文说：

> **through learned spatial resamplers**

就是：

> 用可以训练的模块调整 feature map 的空间尺寸。

这里不是简单 resize，而是用 stride convolution 来做，所以参数是能学习的。

因此叫：

> learned spatial resampler。

后面：

> **and depthwise–pointwise adapters**

这东西就是一个“转接头”。

PIDNet 输出的 feature 格式和 YOLO 想吃的 feature 格式不一定一样。

比如 PIDNet 拼完 P/I/D 后有 $384\text{ channels}$，YOLO 这里只想要 $128\text{ channels}$

那你不能直接硬塞进去。

所以中间放一个：

```
PIDNet feature
 ↓
adapter
 ↓
YOLO-compatible feature
```

这个 adapter 里面主要用了：

- depthwise convolution；
- pointwise convolution。

你现在不用深究卷积细节，只需要知道：

> **它的作用就是把 PIDNet 的 feature 整理成 YOLO 能接收的形式。**

论文也明确说 pointwise $1\times1$ convolution 会把 feature 投影到 YOLO 所需的 64 / 96 / 128 channels。

所以第一整句翻译成人话就是：

> **作者把 YOLO 原本负责提取图像特征的 backbone 删掉，改成直接使用 PIDNet 提取的 P、I、D 特征。由于 PIDNet 的特征尺寸和通道数跟 YOLO 需要的不完全匹配，所以先做尺寸调整，再通过 adapter 转成 YOLO 能接受的特征，然后送进 YOLO 保留下来的 neck 和 detection head 做虾检测。**

接下来第二句：

> **Because feed masks and shrimp boxes belong to separate annotation pools**

这个现在特别重要。

作者手里的数据不是：

```
一张图片
同时有：
虾框
+
饲料 mask
```

而是两批数据。

一批：

```
图片 A
有 shrimp bounding boxes
没有 feed mask
```

另一批：

```
图片 B
有 feed segmentation mask
没有 shrimp boxes
```

也就是：

> detection 标注和 segmentation 标注来自不同 annotation pool。

论文明确说 detection 和 segmentation 使用 disjoint annotation pools。

这就导致一个问题：

现在 PIDNet 是两个任务共享的。

那么：

```
训练虾 detection
→ PIDNet 参数往“找虾”方向改
```

之后：

```
训练 feed segmentation
→ PIDNet 参数又往“分饲料”方向改
```

第二个任务可能把第一个任务学好的 feature 改坏。

所以作者不能很粗暴地说：

> 今天训 detection，明天训 segmentation，随便交替。

于是设计了：

> **three-stage curriculum**

也就是三阶段训练。

### Stage 1：shrimp-oriented representation learning

先训练虾 detection。

目标是先让 PIDNet 学会：

> 什么 feature 对找虾有用。

也就是：

```
虾图片
 ↓
PIDNet
 ↓
YOLO
 ↓
detection loss
```

这时 detection loss 会反向传播进 PIDNet。

所以 Stage 1 之后，PIDNet 已经不是一个普通 PIDNet 了，而是：

> 一个“对虾 detection 友好”的 PIDNet。

### Stage 2：protected feed adaptation

然后开始训练：

> 残饵 segmentation。

但作者怕把 Stage 1 学好的 detection feature 全洗掉。

所以训练 feed 的时候，不让 PIDNet 所有东西随便改。

特别是：

> D branch 被保护。

D branch 跟 boundary 有关，而且对虾 detection 很重要。

所以 Stage 2 大概是：

```
P / I：
继续适应 feed segmentation

D：
尽量冻结、保护
```

它仍然参与 forward，但是参数和 normalization state 都保护住，不让 feed loss 随便改。

这就是：

> protected feed adaptation

即：

> 学饲料，但尽量别毁掉之前学会的检测能力。

### Stage 3：detector recovery

虽然 Stage 2 已经保护了一些东西，但 PIDNet 还是变化了。

于是 YOLO 原来适应的是：

```
Stage 1 的 PIDNet feature
```

现在看到的却是：

```
Stage 2 的 PIDNet feature
```

所以 detection 会掉得很厉害。

于是最后：

> 冻结已经完成 segmentation 训练的 PIDNet。

然后只重新训练：

```
adapter
YOLO neck
YOLO head
```

让 detector 重新适应现在这个 PIDNet。

这叫：

> detector recovery。

论文实验也证明 Stage 2 后 detection 会掉得很厉害，AP50:95 从恢复后的约 $0.5606$ 对比 Stage 2 后只有 $0.1947$。

所以三阶段可以记成：

```
Stage 1
先学会找虾

↓

Stage 2
再学会分饲料
但保护检测相关 feature

↓

Stage 3
冻结 PIDNet
重新把 YOLO 调好
```

最后一句：

> **Boundary-Privileged Knowledge Distillation supports feed adaptation in a PIDNet-S-0.75 variant with reduced channel capacity.**

这里其实是在说：

> 作者还做了一个更小的 PIDNet。

`PIDNet-S-0.75` 就是把 network width 缩到大约 $0.75$。

比如：

32→2432\rightarrow24 96→7296\rightarrow72 128→96128\rightarrow96

为什么缩？

因为要部署到 Raspberry Pi：

> 越小越省算力。

但模型变小以后能力可能下降。

所以让：

```
大 PIDNet
= teacher

小 PIDNet-S-0.75
= student
```

大模型去教小模型。

这就是：

> knowledge distillation。

而且不是平均地教，而是特别关注：

> segmentation boundary。

因此叫：

> **Boundary-Privileged Knowledge Distillation**

你可以理解成：

> 大模型尤其把“饲料区域的边界应该怎么分”教给小模型。


所以你刚刚那一整段，现在最简单的版本就是：

> **作者把 YOLO 前面负责提 feature 的部分砍掉，让 PIDNet 一个人负责提 feature，然后一部分 feature 用来做 feed segmentation，另一部分经过调整后送给 YOLO 后半部分做 shrimp detection。因为两种任务的标注数据不是同一批，所以设计了三阶段训练：先学 detection，再在保护 detection feature 的情况下学 segmentation，最后冻结 PIDNet，把 detection 再调回来。为了进一步让模型适合 Raspberry Pi，又做了一个 0.75 倍宽的小 PIDNet，并让大模型通过 knowledge distillation 帮它学习 segmentation。**

你现在如果把这段吃透了，后面 Method 里面最难的主线其实已经提前懂了七八成。

### 我的疑问1：什么事通过大模型去教小模型？
可以把它理解成：**小模型不仅看“标准答案”，还看“大模型是怎么判断的”。**

先用最普通的监督学习说起。

假设现在有一张图，ground truth 告诉你哪些像素是饲料。普通训练就是：

```
图片
 ↓
小模型
 ↓
预测的 feed mask
 ↓
和 ground truth 比较
 ↓
算 loss
 ↓
更新小模型
```

也就是小模型只跟“标准答案”学。

而 knowledge distillation 会再加一个已经训练得更好的大模型，叫 **teacher**：

```
同一张图片
   ↓
大模型 teacher
   ↓
teacher 的预测
```

同时：

```
同一张图片
   ↓
小模型 student
   ↓
student 的预测
```

然后训练小模型时，不仅要求：

$$\text{student prediction} \approx \text{ground truth}$$

还要求：

$$\text{student prediction} \approx \text{teacher prediction}$$

所以小模型的 loss 可以粗略写成：

$$L_{\text{ground truth}} + \lambda L_{\text{distillation}}$$

这里第二项就是：“你这个小模型，除了要答对，还要尽量学得像老师。”

为什么 teacher 的输出有用？因为 ground truth 往往只是一个硬标签，比如某个 pixel：y=1，表示 feed。但 teacher 可能给出更细腻的判断：

$$P(\text{feed})=0.82,\quad P(\text{background})=0.18$$

另一个边界 pixel：

$$P(\text{feed})=0.53,\quad P(\text{background})=0.47$$

这就告诉 student：

> 第一个 pixel 很确定是 feed；第二个在边界附近，很模糊。

这种“软信息”通常比单纯的 0/1 标签包含更多结构信息。

所以所谓“大模型教小模型”，不是大模型真的在说话，而是：

> **大模型的输出被当成额外训练目标，用来约束小模型。**

在这篇论文里，大模型是 full-width PIDNet，student 是更窄的 PIDNet-S-0.75。作者在 Stage 2 做 feed segmentation 时，让小模型去匹配 teacher 的 segmentation logits，而且特别区分 interior 和 boundary 区域。

所以这篇里的 BPKD 你可以先记成一句话：

> **大 PIDNet 先把“饲料区域尤其是边界该长什么样”预测出来，小 PIDNet 一边看真实 mask，一边模仿大 PIDNet 的预测。**

这样小模型虽然 channel 少、容量小，但能尽量保留大模型学到的能力。

### 3.1
![](附件/Pasted%20image%2020260922212241.png)

I do not know what's the meaning of disjoint annotations, reduced-width, distilled edge configuration, teachers, auxiliary paths, removed for deployment.

### 解析

- **disjoint annotations**: the two tasks are labeled on different images. Some images have shrimp bounding boxes but no feed masks; other images have feed masks but no shrimp boxes. So the annotations are “disjoint,” meaning they do not overlap on the same samples.
- **reduced-width**: the network is made narrower by reducing the number of channels in its layers. For example, the paper changes widths like $32\to24$, $96\to72$, $128\to96$. This makes the model smaller and cheaper to run.
- **distilled edge configuration**: this means a lightweight version of the model designed for an edge device such as a Raspberry Pi, and trained using knowledge distillation. “Distilled” means a larger teacher model helps train the smaller student model.
- **teacher**: the larger model used only during training to guide the smaller model. In this paper, the full-width PIDNet acts as the teacher for the smaller PIDNet-S-0.75.
- **auxiliary paths**: extra branches or heads that exist only to help training. They are not necessary for the final prediction pipeline. In this paper, things like PGI auxiliary structures and auxiliary heads are examples.
- **removed for deployment**: when the model is actually put onto the Raspberry Pi and used in the real world, those teacher models and training-only auxiliary branches are deleted. Only the main inference network remains.

So the whole sentence is basically saying:

> “Because detection and segmentation labels are on different image sets, we use a three-stage training procedure. We also create a smaller model for edge devices and train it with help from a larger model. When the model is actually deployed, all training-only helpers are removed.”
