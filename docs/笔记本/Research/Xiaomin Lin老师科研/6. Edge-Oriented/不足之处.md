There are several clear shortcomings, and some of them are already admitted by the authors. I’d separate them into **data limitations, training limitations, model limitations, and evaluation limitations**.

1. The biggest issue is the **disjoint annotations**. Detection images have shrimp boxes, while segmentation images have feed masks, so the model cannot directly learn both tasks on the same sample. That is exactly why the authors need the complicated three-stage curriculum.

A natural improvement is to build a dataset where the same image has both annotations:

image→{shrimp boxesfeed mask\text{image} \rightarrow \begin{cases} \text{shrimp boxes}\\ \text{feed mask} \end{cases}

Then you could try direct joint multi-task training:

L=λdetLdet+λsegLsegL=\lambda_{\text{det}}L_{\text{det}}+\lambda_{\text{seg}}L_{\text{seg}}

That may make training simpler and could encourage the shared encoder to learn genuinely useful features for both tasks instead of learning one task, adapting to another, then recovering the first.

2. The three-stage training is effective, but it is also **complicated and somewhat inelegant**. Stage 2 damages detection badly, and Stage 3 has to recover it. Their own ablation shows AP50:95 dropping to $0.1947$ after Stage 2 and recovering to $0.5606$ after Stage 3.

That tells us the two tasks still interfere strongly.

A better direction could be to design a joint optimization method that reduces gradient conflict, rather than fixing the damage afterward. For example, conceptually:

∇Ldetand∇Lseg\nabla L_{\text{det}} \quad\text{and}\quad \nabla L_{\text{seg}}

could be adjusted so they do not strongly fight each other in the shared encoder.

Another possibility is to share only some layers:

```
early shared encoder
        ↓
   ┌────┴────┐
det-specific  seg-specific
features      features
```

instead of forcing too much sharing.

3. The fused model saves resources, but **accuracy does not consistently improve**. At 448, fused detection AP50:95 is $0.5442$ versus $0.5834$ for separate models. At 640, fused is $0.5805$ versus $0.6032$. Segmentation also becomes worse in some 640 settings.

So the model mainly gains efficiency, not better perception.

A possible improvement is to make the sharing more adaptive. Right now, PIDNet features are routed into YOLO through fixed architectural interfaces. You could instead learn which features should be shared and which should remain task-specific, perhaps through gating, attention, or task-specific adapters.

In other words:

> do not assume every useful segmentation feature should also be used for detection.

4. The model is only tested on data from **one private shrimp farm in Taiwan**, and although the split is session-disjoint, it is not farm-disjoint.

The authors themselves identify this as a limitation.

That means we do not know whether it generalizes to:

- another farm,
- different water turbidity,
- different lighting,
- another camera,
- another shrimp species,
- different feed types.

The obvious improvement is a **farm-disjoint evaluation**:

```
Train:
Farm A + Farm B

Test:
Farm C
```

Even better would be multi-farm, multi-camera, multi-season data.

5. Their holdout is not a true blind test. They explicitly say it was accessed during legacy development, so it is only a “secondary, non-blind estimate.”

That weakens the evidence for generalization.

A stronger experiment would use a completely untouched test set that is never used for architecture selection, threshold tuning, or checkpoint selection.

6. Some experiments have very few repeated runs. The paper says full-width models, standalone controls, and most ablations have fewer repeats, with many ablations being single runs.

That is a problem because deep-learning training can vary across random seeds.

A better evaluation would report:

mean±std\text{mean} \pm \text{std}

over several seeds for all important baselines and ablations.

7. The historical-feed evaluation has no true feed-event annotations. The model finds 27 candidate periods, but the authors themselves say they require visual confirmation.

So this part demonstrates that the system can produce candidates, but it does not really prove that it accurately detects real feeding events.

The improvement is straightforward: manually annotate a subset of historical video with actual feed-event labels, then compute precision, recall, F1, event-level detection accuracy, etc.

8. The shrimp-count output is also limited. The historical metric is based on visible detections, not tracked individual shrimp. The authors explicitly say these are not unique-animal abundance estimates.

So if the same shrimp appears across many frames, it can be counted repeatedly.

A good extension would combine detection with tracking:

detection→tracking→unique shrimp trajectories\text{detection} \rightarrow \text{tracking} \rightarrow \text{unique shrimp trajectories}

Then the system could estimate more meaningful animal-level statistics.

9. The length-estimation evaluation is conditional. It only evaluates cases where a `clean` detection is successfully selected and sufficiently matches the annotation.

So a low MAPE does not mean the system measures every shrimp accurately.

A stronger metric would evaluate the whole end-to-end pipeline, including:

- failed detection,
- wrong clean/count classification,
- bad box localization,
- length error.

That would give a more realistic deployment metric.

10. The edge deployment evaluation is only on one hardware platform: Raspberry Pi 5, one runtime, one mixed-FP16 setup. The paper also does not measure energy or long-term reliability.

A better deployment study could test:

- Jetson devices,
- Raspberry Pi + accelerator,
- mobile NPUs,
- different quantization levels,
- INT8,
- power consumption,
- temperature,
- long-duration stability.

So if I had to summarize the most promising improvements, I would say:

> **First, build joint annotations and try true joint multi-task training. Second, reduce task interference with better shared/task-specific feature design instead of relying on three-stage recovery. Third, evaluate on new farms with a blind test set. Fourth, add real event labels and tracking so the downstream claims are stronger. Fifth, test more edge hardware and energy efficiency.**

And the improvement you already came up with earlier — **collect images with both detection and segmentation labels and train the two tasks jointly** — is probably one of the most natural criticisms of the current setup.
