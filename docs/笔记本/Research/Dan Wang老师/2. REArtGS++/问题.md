### 0. Abstraction

### 0.1 
什么是 part-level surface？

### 解析
这里的 **part-level surface**，可以理解成：

> **不是只把整个物体的外表面重建出来，而是把这个物体的每一个可动/静止部件的表面分别重建出来。**

比如一个柜子有：

- 柜体；
- 左门；
- 右门；
- 抽屉。

普通的 object-level surface reconstruction 只关心：

$$这个柜子整体长什么样$$

但 part-level surface reconstruction 还要知道：

$$哪些表面属于柜体，哪些属于左门，哪些属于右门，哪些属于抽屉$$

所以最终得到的不是一坨不区分部件的 mesh，而是类似：

$$\mathcal M = \{\mathcal M_1,\mathcal M_2,\ldots,\mathcal M_k\}$$

其中 $\mathcal M_j$ 就是第 $j$ 个 part 的 surface mesh。

这对 articulated object 很重要，因为不同 part 会做不同运动。比如门绕铰链旋转，抽屉沿直线平移。如果你只重建“整个物体的表面”，却不知道每块表面属于哪个 part，就没法正确让它们分别运动。

这篇 REArtGS++ 明确说它的目标是同时做 **part-level surface mesh reconstruction** 和 **joint parameter estimation**，也就是既恢复每个部件的几何表面，又恢复这些部件怎么动。

你可以把它想成：

- **object-level surface**  = “我知道这是一个冰箱的完整外壳”
- **part-level surface**  = “我知道这部分 mesh 是门，这部分 mesh 是主体，而且门可以相对主体转动”

而且论文最后确实是先把 Gaussian 按 part 分开，再分别对每个 part 做 RGB/depth rendering，然后通过 TSDF fusion 提取出 **part-level dynamic meshes**。

所以这里的 “part-level” 重点不在“表面更精细”，而在于：

> **表面具有部件归属。**

### 0.2
什么是 Gaussian splatting？

### 解析
Gaussian Splatting 你可以先把它理解成一种 **用很多个“半透明的小椭球”来表示 3D 场景，然后把这些小椭球投影到相机平面上生成图像的方法**。

这篇论文用的是 **3D Gaussian Splatting，3DGS**。它不是像 NeRF 那样用一个神经网络隐式表示场景，而是显式地保存很多个 Gaussian primitive。论文本身也这样说：3DGS 使用一组 Gaussians 显式表示场景。

一个 3D Gaussian 你可以想象成空间里一个软软的、半透明的椭球。每一个 Gaussian 大概都有这些信息：

- 中心位置 $\mu$
- 尺寸/尺度 $s$
- 朝向
- 颜色
- opacity，也就是透明度
- 有时还会有 spherical harmonics，用来表示不同观察方向下的颜色

所以一个物体，比如一个柜子，不是由一个 mesh 一开始就直接表示，而是由成千上万个这种 Gaussian 拼起来。

比如：

```
一个柜子

   [Gaussian][Gaussian][Gaussian]
 [Gaussian][Gaussian][Gaussian][Gaussian]
   [Gaussian][Gaussian][Gaussian]
```

每个 Gaussian 都覆盖空间中的一小块区域，很多个叠起来以后，就形成整个物体。

这里的 **splatting** 是关键。

假设空间里面有一个 3D Gaussian：

```
          3D空间

             ●
          /     \
        / Gaussian \
       \         /
          \   /
```

现在相机从某个方向看它。

这个 3D Gaussian 会被投影到二维图像平面上，变成一个类似二维椭圆的东西：

```
3D Gaussian
      ↓ 相机投影

image plane

      ░░░
    ░████░
   ░██████░
    ░████░
      ░░
```

这个把 Gaussian “啪”一下摊到 image plane 上的过程，就叫 **splatting**。

所以名字其实非常直白：

> Gaussian + splatting  
> = 把 Gaussian 投影/摊到屏幕上。

然后问题来了：

一个 pixel 往往不只被一个 Gaussian 覆盖。

比如沿着一条 camera ray：

```
camera
  📷
   \
    \   G1
     \  ●
      \
       \ G2
        ●
         \
          \ G3
           ●
```

那么这些 Gaussian 对同一个 pixel 都会有贡献。

怎么办？

就按照前后顺序进行 $\alpha$-blending。

论文 Eq.1 就是在干这个：

$$ C = \sum_{i=1}^{N_G} c_i\alpha_i \prod_{j=1}^{i-1}(1-\alpha_j) $$


先不用怕这个公式。它实际上就是：

> 前面的 Gaussian 挡一部分，后面的 Gaussian 再从剩下没被挡住的部分贡献颜色。

比如前面有一个红色半透明 Gaussian：

$$\alpha_1 = 0.7$$

意味着它挡住 70%。

后面一个蓝色 Gaussian 就只能通过剩下的

$$1-\alpha_1=0.3$$

来贡献。

所以最终 pixel 的颜色大致是：

$$C = c_1\alpha_1 + c_2\alpha_2(1-\alpha_1) +\cdots$$

这就是 Gaussian Splatting 的核心 rendering 思路。

你还可以这样对比理解：

### Mesh

Mesh 是：

```
vertices
   ●------●
   |\    /|
   | \  / |
   |  \/  |
   |  /\  |
   | /  \ |
   ●------●
```

用明确的 vertex + triangle 表示表面。

### 3D Gaussian Splatting

则是：

```
  ◯ ◉ ◯
 ◉ ◉ ◉ ◉
  ◉ ◯ ◉
```

用很多带大小、方向、颜色、透明度的 3D Gaussian 表示物体。

所以 Gaussian 本身不一定是“真正的实体表面”。

它更像：

> 一堆可以被渲染出来的空间 primitive。


这也正好解释了为什么这篇 REArtGS++ 要搞 **Planar Gaussian**。

普通 3D Gaussian 是一个真正有厚度的椭球：

```
      ______
   /          \
  |   3D GS    |
   \__________/
```

但对于 surface reconstruction，我们真正关心的是：

> 物体表面到底在哪里？

如果 Gaussian 太厚，那么“表面在哪里”就不够明确。

所以这篇论文把 Gaussian 压扁：

```
ordinary 3D Gaussian

      ______
   /          \
  |            |
   \__________/


Planar Gaussian

   =================
```

它在一个方向上的 scale 被压得非常小，就更接近一个局部的小平面。

论文在 4.1 里就是通过：

$$ L_{\text{scale}} = \frac{1}{N_G} \sum_i \left\| \min(s_1,s_2,s_3) \right\| $$

逼着每个 Gaussian 最短的那个轴变小，从而把 3D Gaussian 压成 planar Gaussian。

这样最大的好处就是：

> 一个 planar Gaussian 可以被当成物体表面上的一小块 local plane。

于是它就可以更准确地得到：

- surface normal
- depth
- surface geometry

这正是后面 temporal geometry constraint 所需要的。

所以对这篇论文来说，你现在先记一句最核心的话：

> **Gaussian Splatting = 用大量带位置、形状、颜色和透明度的 Gaussian 来显式表示 3D 物体，并把它们投影到 2D 图像上，通过 $\alpha$-blending 渲染出图像。**

而 **REArtGS++** 更进一步：

> **把这些胖的 3D Gaussian 压扁成 planar Gaussian，让每一个 Gaussian 更像物体表面上的一小片。**

## 1. Introduction

### 1.1
neural implicit radiance field是什么？
### 解析
**Neural implicit radiance field** 可以拆成三部分理解：

- **neural**：用神经网络表示
- **implicit**：不是直接存一堆明确的点、三角形、Gaussian，而是把场景“藏”在一个函数里
- **radiance field**：这个函数告诉你，空间某个位置、从某个方向看过去，会是什么颜色、密度多大

最典型的就是 NeRF。

它学的是一个函数，大概可以写成：

$$F_\theta(\mathbf{x}, \mathbf{d}) \rightarrow (\sigma, \mathbf{c}) $$

其中：

- $\mathbf{x}=(x,y,z)$：3D 空间中的一个位置
- $\mathbf{d}$：你从哪个方向看这个位置
- $\sigma$：这个位置的体密度
- $\mathbf{c}$：这个方向看到的颜色

也就是说，你问神经网络：

> “空间中这个点，从这个方向看，应该是什么颜色？这里有没有东西？”

网络就给你答案。

这就叫 **implicit**，因为它没有直接告诉你：

> “这里有一个三角形”  
> “这里有一个 Gaussian”  
> “这里有一个明确的 surface point”

而是通过一个连续函数间接描述整个场景。

你可以直接和前面讲的 3D Gaussian Splatting 对比。

### 3DGS：显式表示

3DGS 直接存很多 Gaussian：

$$G_1,G_2,\dots,G_N $$

每个 Gaussian 都有：

$$ \mu,\Sigma,\text{color},\alpha,\dots$$

所以你可以明确指出：

> 这里有一颗 Gaussian，它中心就在 $(x,y,z)$。

这叫 **explicit representation**。

### NeRF：隐式表示

NeRF 没有直接存“这里有某个 primitive”。

它存的是一个神经网络：

$$F_\theta$$

你输入坐标，它才现算这个位置的颜色和 density。

所以：

```
3DGS:
空间 ≈ 很多明确存在的 Gaussian

NeRF:
空间 ≈ 一个神经网络函数
```

这就是 explicit 和 implicit 最大的区别。

### 1.2
using neural implicit radiance fields, only with multi- view RGB images from two different states，这种方法为什么能够解决 limited generalization to unseen categories due to the variations in shape and motion of articulated objects.

### 解析
我之前学过的那种深度学习，用 loss 来训练模型的方式是最常见的监督学习，比如猫狗分类之类的，它们学的都是 features，但是完全没法泛化，比如一个分辨猫狗的模型，你输入一张兔子的照片进来就炸缸了。

Neural implicit field 完全不是这个目标

现在换成 NeRF / neural implicit radiance field。

- 它不是：“给我很多物体，我学出它们的共同 feature。”
- 而是：“给我这一个具体物体/场景的很多观测，我用一个 neural network 把这个具体场景拟合出来。”

也就是说：

$$\text{一个场景的多视角图像} \rightarrow \theta_{\text{scene}} $$

网络学的是一个函数：

$$F_\theta(x,y,z,\mathbf d) \rightarrow (\sigma,\mathbf c) $$

其中：

- $(x,y,z)$：空间坐标
- $\mathbf d$：观察方向
- $\sigma$：该位置的 density
- $\mathbf c$：颜色

所以它最终要实现的是：

> 给我一个 3D 位置，我告诉你这里有没有东西、是什么颜色。

但是也不是说 neural implicit network 里面“没有 feature”。

它当然也有 hidden layers：

$$(x,y,z) \rightarrow h_1 \rightarrow h_2 \rightarrow \cdots \rightarrow (\sigma,c) $$

所以内部当然会形成 feature。

但这些 feature 的目标不是：“提取门的一般特征，以便泛化到下一扇门。”

而是：“帮助这个网络拟合当前这个具体场景的连续空间函数。”

所以两者的区别不是：

- 一个有 feature
- 一个没 feature

而是：

### 普通深度学习

feature 是为了：

$$ \text{跨样本复用} $$

### Neural implicit fitting

feature 是为了：

$$\text{拟合当前实例的函数}$$

一个特别直观的对比

#### 普通 classification network

假设训练 10000 张猫狗图片：

$$x_i\rightarrow y_i$$

网络试图学：

> “猫和狗之间有哪些稳定的视觉特征？”

训练完以后：
$$
\theta^*$$

固定。

然后：

$$\text{new image} \rightarrow f_{\theta^*} \rightarrow \text{prediction}$$

不重新训练。

#### Neural implicit field

假设现在只重建一个杯子。

你有这个杯子的 100 张多视角照片。

网络不是要回答：

> “这是杯子吗？”

而是要回答：

> “空间坐标 $(x,y,z)$ 这里有没有杯子的表面？”

所以最后得到：

$$F_{\theta_{\text{cup}}} $$

它描述这个具体杯子。

换成柜子以后：

$$F_{\theta_{\text{cabinet}}}$$

是另一套参数。

不是：

$$F_{\theta_{\text{cup}}} \rightarrow \text{直接处理 cabinet}$$

而是重新优化出：

$$ \theta_{\text{cabinet}}$$

### 1.3
PARIS faces challenges in multi-part perception and smooth dynamic surface reconstruction, suffering from the entangled implicit representation.这又是什么意思？

### 解析
> PARIS 能构建一个 3D implicit representation，也能描述物体随状态变化后的表面；问题是它对“哪些区域属于同一个 rigid part”这件事，表示得不够显式、不够干净。

你可以把它想成一个柜子：

- 柜体
- 左门
- 右门

PARIS 可能能很好地回答：

> “在这个位置，表面应该在哪里、长什么样。”

也可能能描述：

> “从 state 0 到 state 1，这些表面发生了怎样的变化。”

但它不一定天然有非常清楚的离散结构：

$$ \text{这些点全都属于左门} ,\  \text{那些点全都属于右门} ,\ \text{左门上的所有点应该作为一个刚体一起运动} $$

这就是论文说的 **multi-part perception challenge**。

更直白一点：

> **它知道“表面怎么变”，但未必很容易明确拆出“这是第几个部件、这个部件内部哪些地方必须绑在一起动”。**

这就是为什么作者嫌它的表示太 **entangled**(混在一起的)——几何、部件归属、运动关系揉在一个隐式表示里，不够容易拆开。

而 3DGS/REArtGS++ 这种显式表示更容易做成：

$$G_1,G_2,G_3,\dots$$

然后给每颗 Gaussian 一个 part probability：

$$M_i=[m_i^1,m_i^2,\dots,m_i^k]$$

这样就能更明确地说：

> 这颗 Gaussian 属于左门；  
> 那颗属于柜体；  
> 左门这一组 Gaussian 共享同一个 joint motion。

所以你的理解可以改成一句更准确的话：

> **PARIS 不是不会恢复表面，而是它更难把恢复出来的动态表面清楚地拆成多个彼此独立、内部刚性一致的部件。**

### 1.5
什么是 temporal geometric constrains？

### 解析
**temporal geometric constraints** 就是：

> **不只要求物体在某一个时刻的 3D 几何是合理的，还要求它在整个运动时间过程中，几何变化都合理、连续、一致。**

拆开看：

- **temporal** = 跟时间有关
- **geometric** = 跟 3D 几何形状有关
- **constraint** = 约束

所以合起来就是：

> **对“随时间变化的 3D 几何”施加约束。**

### 1.6
什么是joint parameters，什么是Gaussian primitives，它们是jointly optimized又是什么情况？
### 解析

假设我们现在重建一个柜门。

**Gaussian primitives** 就是用来表示这个 3D 物体的那些“小 Gaussian 元件”。每一颗 Gaussian primitive 都有自己的参数，比如中心位置、大小、朝向、颜色、透明度。很多颗 Gaussian 拼起来，才表示出整个门和柜体。

所以你可以把：

> Gaussian primitive

理解成：

> **构成 3D 场景的最小显式表示单元。**

这篇论文里，Gaussian 还是 planar Gaussian，也就是被压扁的小平面状 Gaussian。 

**joint parameters**(关节参数) 则不是在描述“门长什么样”，而是在描述：

> **门是怎么动的。**

比如一扇旋转门，joint parameters 可能包括：

- rotation axis：绕哪根轴转
- pivot point：旋转中心在哪里
- rotation angle：转多少
- translation：有没有平移

那什么叫 **jointly optimized**？

就是：

> **这两类参数不是先固定一类再求另一类，而是在同一个优化过程中一起改。**

比如模型现在预测不好 state 1 的图像。

它可能有两种原因：

1. Gaussian geometry 不对  
    也就是门本身重建歪了。
    
2. joint parameters 不对  
    比如 hinge 轴位置错了。
    

所以优化器会同时去调整：

- Gaussian 的位置、尺度、朝向等
- joint 的 axis、pivot、rotation、translation 等

也就是：

$$ \text{Gaussian parameters} + \text{joint parameters}$$

一起参与 loss 的反向传播和更新。

这就叫：

> **jointly optimized**

你可以直接记成：

> **Gaussian primitives = 长什么样**
> 
> **joint parameters = 怎么动**
> 
> **jointly optimized = 长什么样和怎么动一起调参数**

### 1.7 
什么是SDF？

### 解析
SDF 是 **Signed Distance Field**，中文一般叫 **有符号距离场**。

字面意思：

- **Signed** = 有正负号
- **Distance** = 距离
- **Field** = 给空间中每一个位置都定义一个值

所以 SDF 做的事情就是：

> **对空间中的每一个点，记录它离物体表面有多远。**

比如一个物体表面：

```
外部        +3cm
            •
            |
------------|------------  surface
            |
            •
内部        -2cm
```

通常约定：

- 物体外部：SDF 为正
- 正好在表面：SDF = 0
- 物体内部：SDF 为负

于是：

$$\mathrm{SDF}(x)= \begin{cases} >0, & x\text{ 在物体外部}\\ =0, & x\text{ 在物体表面}\\ <0, & x\text{ 在物体内部} \end{cases} $$

比如：

$$\mathrm{SDF}(x)=+0.03$$

表示这个点在表面外 3 cm。

而：

$$\mathrm{SDF}(x)=-0.02$$

表示这个点在物体内部 2 cm。

最关键的一点是：

> **物体表面就是 SDF = 0 的那一层。**

所以如果你有完整的 SDF，就等于你知道了整个物体的几何表面在哪里。

这篇论文提到 REArtGS 用 SDF 来增强 geometric constraints，也就是利用 SDF 对“表面应该在哪里”施加额外约束。 2511.17059v3

你现在可以直接记成：

> **SDF = 给 3D 空间每个点一个“到最近表面的有符号距离”，其中 0 对应真实表面。**

### 1.8

To address the aforementioned limitations, we pro- pose REArtGS++, a novel framework of Reconstructing gEneralizable Articulated objects via planar Gaussian Splatting and temporal geometric constraint, shown as Fig. 1. We model a decoupled screw motion for each joint and derive Gaussian’s motion from part motion blending, taking part segmentation probability as blending weights. In this way, we jointly optimize part-aware Gaussians and joint parameters without joint type priors.这段话我看不懂字面意思，不懂背后的原理，不懂各种术语

### 解析
这段核心其实只有一句：

> **REArtGS++ 不再先判断“这个 joint 是旋转还是平移”，而是给每个 part 都同时保留旋转和平移能力；每颗 Gaussian 根据“自己属于哪个 part 的概率”去跟着这些 part 运动，于是 part segmentation、Gaussian 位置和 joint parameters 可以一起优化。** 2511.17059v3

先看第一句：

> `We model a decoupled screw motion for each joint`

这里有两个词。

**screw motion** = 旋转 + 平移。

例如一个螺丝：

\[ \text{motion}=\text{rotation}+\text{translation} \]

**decoupled** = 解耦，也就是把这两部分分开表示。

所以这里不是说“每个 joint 真的是螺丝”，而是说：

> 每个 joint 都用一个足够通用的运动模型表示，这个模型同时允许 rotation 和 translation。

比如每个 joint 都有：

\[ \omega_j=\{q_j,o_j,t_j\} \]

其中：

- $q_j$：rotation
- $o_j$：pivot
- $t_j$：translation

于是：

如果最后

$$t_j\approx 0$$

那就是纯 rotation。

如果

$$ q_j\approx I $$

那就是纯 translation。

如果两者都不为零，就是 screw motion。

所以它不用再提前问：

> “你到底是 rotation 还是 translation？”

这就是它说的 **without joint type priors**。

然后第二句：

> `derive Gaussian's motion from part motion blending`

这个最容易看不懂。

先想一个柜子，有三个 part：

- part 1：柜体
- part 2：左门
- part 3：右门

每个 part 都有自己的运动：

$$T_1,\quad T_2,\quad T_3$$

现在有一颗 Gaussian $G_i$。

问题是：

> 这颗 Gaussian 到底应该跟哪个 part 一起动？

如果你已经百分之百知道它属于左门，那很简单：

$$G_i \text{ 跟着 } T_2 \text{ 动}$$

但模型一开始并不知道。

所以它给每颗 Gaussian 一个 **part segmentation probability**：

$$ M_i= [m_i^1,m_i^2,m_i^3] $$

例如：

$$M_i=[0.05,0.90,0.05] $$

意思就是：

- 5% 像柜体
- 90% 像左门
- 5% 像右门

于是它不直接硬选一个 part，而是做 **motion blending**：

$$ \mu_i(t) = \sum_j m_i^j T_j(\mu_i) $$

也就是：

> 每个 part 都“提议”一个这颗 Gaussian 应该去的位置，然后按照 part probability 加权平均。

例如三个 part 给出的结果分别是：

$$T_1(\mu_i)=A, \ \ T_2(\mu_i)=B, \ \ T_3(\mu_i)=C $$

而：

$$M_i=[0.05,0.90,0.05] $$

那么最终位置就是：

$$0.05A+0.90B+0.05C$$

所以这句话：

> `taking part segmentation probability as blending weights`

字面意思就是：

> **把“这颗 Gaussian 属于各个 part 的概率”，直接当成不同 part motion 的加权系数。**

这就是 blending weights。

你可以把它想得非常机械：

```
Gaussian Gi

属于 part1 的概率：0.1
属于 part2 的概率：0.8
属于 part3 的概率：0.1

part1 说：你应该移动到 A
part2 说：你应该移动到 B
part3 说：你应该移动到 C

最终：
0.1A + 0.8B + 0.1C
```

这就叫 **part motion blending**。

为什么这样做？

因为一开始 part segmentation 还不确定。

如果强行一开始就说：

> 这颗 Gaussian 100% 属于 part 2

可能会分错。

用 soft probability，就可以在优化过程中逐渐变成：

$$ [0.1,0.8,0.1] \rightarrow [0.02,0.96,0.02] $$

这样 part assignment 会越来越明确。

然后第三句：

> `jointly optimize part-aware Gaussians and joint parameters`

这里的 **part-aware Gaussians** 就是：

> 每颗 Gaussian 不只知道自己的位置、大小、颜色，还带着“自己属于哪个 part”的概率。

也就是普通 Gaussian：

$$G_i=(\mu_i,s_i,\cdots)$$

现在变成：

$$G_i=(\mu_i,s_i,\cdots,M_i)$$

其中：

$$ M_i=[m_i^1,\dots,m_i^k] $$

所以叫 **part-aware**。

然后一起优化两类东西：

第一类：

$$ \text{Gaussian parameters + part probabilities} $$

第二类：

$$ \text{joint parameters} $$

也就是：

$$ \{G_i,M_i\} \quad+\quad \{\omega_j\} $$

一起被 loss 更新。

这就是 **jointly optimize**。

完整逻辑其实是：

```
每个 part
都有自己的 joint motion
        ↓
每颗 Gaussian
有自己属于各个 part 的概率
        ↓
用这些概率混合各个 part 的 motion
        ↓
得到 Gaussian 在 t 时刻的位置
        ↓
render 出图像
        ↓
和真实 RGB 比较
        ↓
loss
        ↓
同时更新：
1. Gaussian 本身
2. part probability
3. joint parameters
```

所以它为什么能 **without joint type priors**？

因为它根本不需要先做：

```
这个 joint
↓
rotation?
还是
translation?
```

而是直接给每个 joint：

```
rotation 参数
+
translation 参数
```

一起优化。

最后优化结果自己决定它是什么：

- rotation 大、translation 小 → 更像 revolute joint
- rotation 小、translation 大 → 更像 prismatic joint
- 两个都有 → screw joint

所以整段话翻成人话就是：

> REArtGS++ 给每个 part 都定义一个同时包含旋转和平移的通用 joint motion，而不提前判断 joint type。每颗 Gaussian 都有一个“属于各个 part 的概率”，这些概率被用来混合不同 part 的运动，从而决定这颗 Gaussian 应该怎么移动。最终，Gaussian 的几何、Gaussian 的 part assignment，以及每个 part 的 joint parameters 都可以在同一个优化过程中一起学习，因此不再需要提前提供 rotation/translation 的 joint type prior。 

你这里最值得记住的是这条链：

$$\boxed{ \text{part probability} \rightarrow \text{motion blending} \rightarrow \text{Gaussian motion} } $$

和：

$$ \boxed{ \text{rotation + translation jointly modeled} \rightarrow \text{no joint type prior} } $$
