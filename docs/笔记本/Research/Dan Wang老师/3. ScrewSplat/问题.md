### Analysis
### 1. ScrewSplat

**ScrewSplat is the name of the method proposed in this paper.**

The name combines two ideas:

- **Screw** → screw theory, which is used to describe joint motion(关节运动)
- **Splat** → Gaussian Splatting, which is used to represent the object's 3D appearance and geometry

So you can roughly understand:

> **ScrewSplat = screw motion model + Gaussian Splatting**

### 2. Kinematic structure

**Kinematic structure means the structure describing how the different parts of an object are allowed to move relative to each other.**

For an articulated object, it includes things like:

- which part is static
- which parts can move
- what type of joint connects them
- where the joint axis is
- how each movable part moves

The paper explicitly says robots need to understand both the object's 3D geometry and its underlying kinematic structure, such as **joint types and axes**.

Take a laptop:

- keyboard base → static part
- screen → movable part
- hinge → revolute joint
- hinge direction → joint axis

All of that together is the **kinematic structure**.

Another example is a drawer:

- cabinet → static
- drawer → movable
- joint type → prismatic
- motion direction → forward/backward

So when the paper says:

> recover the object's geometry and kinematic structure

it means:

> reconstruct what the object looks like, and understand how its parts can move.

### 3. Screw axis

A **screw axis is a mathematical representation of a rigid-body motion**.

In this paper, a screw axis is written as

$$ S= \begin{bmatrix} \omega\\ v \end{bmatrix} \in\mathbb{R}^6 $$

where $\omega$ and $v$ describe the motion. 

You don't need to worry about the formula yet. First understand the physical meaning.

For a **revolute joint**, like a laptop hinge:

> the screw axis tells you **where the rotation axis is and what direction it points**.

For example:

```
      screen
        /
       /
------●------  ← hinge axis
 keyboard
```

That hinge line is basically what the screw axis is describing.

For a **prismatic joint**, like a drawer:

```
cabinet
┌───────────┐
│  drawer → → →
└───────────┘
```

there is no rotation. The screw axis tells you:

> **which direction the drawer translates.**

So you can temporarily think of a screw axis as:

> **the mathematical description of the axis/direction along which a movable part moves.**

The nice thing about screw theory is that it can represent both:

- rotation
- translation

in one unified framework.

### 4. Zero-shot

**Zero-shot means doing a new task without specifically training the model on examples of that exact task beforehand.**

In this paper, they talk about:

> **zero-shot, text-guided manipulation**

For example, suppose the robot has reconstructed a laptop using ScrewSplat.

You give it the text:

> “open laptop”

The robot was not necessarily trained with hundreds of labeled examples saying:

```
image 1 → open laptop
image 2 → closed laptop
image 3 → half-open laptop
```

Instead, they use a pretrained vision-language model, specifically CLIP, to understand the relationship between the text prompt and the rendered appearance. 

So:

```
Current state:
closed laptop

Text command:
"open laptop"

        ↓

ScrewSplat renders different possible joint angles

        ↓

CLIP judges:
which rendered image best matches "open laptop"?

        ↓

Find target joint angle

        ↓

Robot moves the laptop
```

That's why it's called **zero-shot text-guided manipulation**.

# Why Traditional 3D Reconstruction Methods Need Strong Assumptions and Multi-Stage Pipelines

## 1. Why is 3D reconstruction difficult?

Suppose we only have several RGB images of an object taken from different viewpoints.

For one pixel $(u,v)$ in an RGB image, we know the **viewing direction**, but we do not directly know how far away the corresponding surface point is.

Therefore:

$$  
\text{2D pixel} \rightarrow \text{a ray in 3D space}  
$$

rather than

$$  
\text{2D pixel} \rightarrow \text{one unique 3D point}  
$$

There are infinitely many possible 3D points along the same viewing ray that could project to the same image pixel.

Therefore, 3D reconstruction is fundamentally an **underdetermined problem**:

> The available 2D observations are often insufficient to uniquely determine the underlying 3D geometry and motion.

This is the fundamental reason why traditional reconstruction methods often need additional assumptions and intermediate procedures.

## 2. Why do traditional methods rely on strong assumptions?

The main reason is:

> **Because the reconstruction problem contains too many unknown variables and too many possible solutions. Strong assumptions reduce the search space and make the problem solvable.**

For example, suppose the entire object is assumed to be rigid.

Then the motion of every 3D point can be described by the same rigid transformation:

$$  
P_i^{t+1} = R P_i^t + T  
$$

where:

- $P_i^t$ is the 3D position of point $i$ at time $t$,
    
- $R$ is a rotation matrix,
    
- $T$ is a translation vector.
    

This assumption greatly simplifies the problem.

Instead of independently estimating how thousands of points move, the system only needs to estimate one $R$ and one $T$.

Therefore:

$$  
\text{strong assumption} \rightarrow \text{fewer unknowns} \rightarrow \text{easier optimization}  
$$

## 3. Why are articulated objects harder?

For an articulated object, such as a cabinet:

- the cabinet body may remain static,
    
- a door may rotate,
    
- a drawer may translate.
    

Therefore, one global rigid transformation is no longer sufficient.

Instead, different parts have different transformations:

$$  
P_i^{t+1} = R_{k(i)} P_i^t + T_{k(i)}  
$$

where $k(i)$ indicates which object part point $i$ belongs to.

But now a new unknown appears:

> Which point belongs to which rigid part?

So the method must somehow estimate the **part assignment**.

This leads to procedures such as **part clustering**.

At the same time, to know how a 3D point moves across frames, the system must know which image observations correspond to the same physical point.

This leads to **point correspondence matching**.

Therefore, articulated reconstruction often contains several mutually dependent unknowns:

$$  
\boxed{\text{geometry} \leftrightarrow \text{point correspondence} \leftrightarrow \text{part assignment} \leftrightarrow \text{motion}}  
$$

This creates a difficult circular dependency.

Traditional methods often break this difficult joint problem into several smaller stages and impose assumptions at each stage.

Typical assumptions may include:

- the object consists of a small number of rigid parts,
    
- points on the same part move rigidly together,
    
- camera poses are already known,
    
- enough visual texture exists for matching,
    
- the number of movable parts is known or limited,
    
- motion between frames is sufficiently small,
    
- depth measurements are available,
    
- different parts exhibit sufficiently different motion patterns.
    

These assumptions are needed because, without them, too many different 3D structures and motion explanations could fit the same images.

So the key causal relationship is:

$$  
\boxed{\text{2D observations are ambiguous}}  
$$

$$  
\Downarrow  
$$

$$  
\boxed{\text{additional constraints are needed}}  
$$

$$  
\Downarrow  
$$

$$  
\boxed{\text{these constraints become strong assumptions}}  
$$


## 4. What is point correspondence?

Suppose we take two photos of the same chair from different viewpoints.

A physical corner of the chair appears at

$$  
p_A = (120,80)  
$$

in image A, and at

$$  
p_B = (95,83)  
$$

in image B.

Although the pixel coordinates are different, they represent the **same physical 3D point**.

Therefore,

$$  
p_A \leftrightarrow p_B  
$$

is a **point correspondence**.

In simple words:

> Point correspondence means identifying which point in one image corresponds to the same physical point in another image.


## 5. Why do we need point correspondence?

A pixel in one image only gives us one viewing ray.

Suppose camera 1 observes one point and produces ray $r_1$.

Camera 2 observes the same physical point and produces ray $r_2$.

If we know that these two observations correspond to the same physical point, then we can estimate the 3D location by triangulation.

Conceptually:

$$  
\text{matching pixels} \rightarrow \text{two viewing rays} \rightarrow \text{triangulation} \rightarrow \text{3D point}  
$$

Therefore, correspondence is one of the fundamental tools used in multi-view reconstruction.

## 6. Why is point correspondence difficult?

The computer does not automatically know which pixels belong to the same physical location.

For example, suppose a white cabinet contains many visually similar corners.

A point in image 1 may look similar to several points in image 2.

The system may therefore accidentally match

$$  
\text{corner A in image 1}  
$$

with

$$  
\text{corner B in image 2}  
$$

even though they are different physical points.

This problem becomes especially difficult when the object contains:

- repetitive textures,
    
- textureless regions,
    
- reflections,
    
- shadows,
    
- occlusions,
    
- large viewpoint changes,
    
- moving parts.
    

Therefore:

$$  
\text{wrong correspondence} \rightarrow \text{wrong triangulation} \rightarrow \text{wrong 3D geometry}  
$$

## 7. What is part clustering?

Suppose a cabinet contains:

- a static cabinet body,
    
- a left door,
    
- a right door,
    
- a drawer.
    

After reconstructing many 3D points,

$$  
P_1, P_2, \dots, P_N  
$$

the system may try to divide them into several groups:

$$  
C_1, C_2, C_3, C_4  
$$

where each cluster corresponds to one physical part.

For example:

- $C_1$: cabinet body,
    
- $C_2$: left door,
    
- $C_3$: right door,
    
- $C_4$: drawer.
    

This process is called **part clustering**.

A common idea is:

> Points that move together probably belong to the same rigid part.

For example, points on the same cabinet door should approximately share the same rigid transformation.

## 8. Why can part clustering fail?

Motion does not always clearly distinguish different parts.

For example, consider a rotating door.

Points near the hinge move very little, while points far away from the hinge move a lot.

Therefore, a clustering method based mainly on motion may incorrectly conclude that points near the hinge belong to the static cabinet body.

Similarly, two different parts may temporarily move in similar ways.

Then the system might incorrectly merge them into the same cluster.

Therefore:

$$  
\text{incorrect motion estimation} \rightarrow \text{incorrect part clustering}  
$$

And incorrect clustering can then affect later articulation estimation.


## 9. What is a multi-stage pipeline?

A traditional articulated reconstruction system may use a pipeline such as:

$$  
\text{RGB video}  
\rightarrow  
\text{feature extraction}  
\rightarrow  
\text{point correspondence}  
\rightarrow  
\text{3D point reconstruction}  
\rightarrow  
\text{motion estimation}  
\rightarrow  
\text{part clustering}  
\rightarrow  
\text{joint estimation}  
\rightarrow  
\text{final articulated 3D model}  
$$

This is called a **multi-stage pipeline** because the final result is obtained through several intermediate procedures.

Each stage uses the output of the previous stage.


## 10. Why do multi-stage pipelines introduce potential points of failure?

The problem is that errors can propagate from one stage to another.

### Stage 1: correspondence matching

Suppose some point correspondences are incorrect.

Then:

$$  
\text{wrong correspondence}  
$$

causes incorrect triangulation.

### Stage 2: 3D reconstruction

The incorrectly matched points produce incorrect 3D locations.

Then:

$$  
\text{wrong 3D geometry}  
$$

affects motion estimation.

### Stage 3: motion estimation and clustering

Incorrect point trajectories may cause points to be assigned to the wrong object part.

Then:

$$  
\text{wrong clustering}  
$$

affects joint estimation.

Finally:

$$  
\boxed{\text{correspondence error} \rightarrow \text{geometry error} \rightarrow \text{motion error} \rightarrow \text{clustering error} \rightarrow \text{joint estimation error}}  
$$

Therefore, every intermediate stage becomes a potential **point of failure**.

Here, “point of failure” does not mean a 3D point.

It means:

> A step in the processing pipeline where an error may occur and then propagate to later stages.

## 11. What is auxiliary depth input?

An RGB image gives a color value for every pixel:

$$  
I(u,v) = (R,G,B)  
$$

For example:

$$  
I(120,80) = (128,210,43)  
$$

A depth map instead gives the distance from the camera to the visible surface:

$$  
D(u,v) = z  
$$

For example:

$$  
D(120,80) = 1.73 \text{ m}  
$$

Therefore:

- RGB tells us **what the pixel looks like**.
    
- Depth tells us **how far away the corresponding surface is**.
    

If a method requires **auxiliary depth input**, it means that RGB alone is not sufficient for the method.

The method additionally requires depth information from sources such as:

- RGB-D cameras,
    
- LiDAR,
    
- stereo cameras,
    
- structured-light sensors,
    
- time-of-flight sensors,
    
- monocular depth estimation models.
    

“Auxiliary” simply means:

> additional information provided in addition to the primary RGB images.

## 12. Why is depth useful for reconstruction?

Without depth:

$$  
\text{pixel} \rightarrow \text{unknown location somewhere along a ray}  
$$

With depth:

$$  
\text{pixel} + \text{depth} \rightarrow \text{specific 3D location}  
$$

Given the camera intrinsic matrix $K$:

$$  
P = D(u,v) K^{-1}  
\begin{bmatrix}  
u \  
v \  
1  
\end{bmatrix}  
$$

Conceptually:

> Pixel coordinates determine the viewing direction, while depth determines how far along that direction the surface lies.

Therefore:

$$  
\boxed{\text{direction} + \text{distance} \rightarrow \text{3D point}}  
$$

This is why depth can greatly simplify 3D reconstruction.

## 13. Why can auxiliary depth input be noisy?

Real depth sensors do not measure depth perfectly.

Unlike RGB cameras, which mainly record incoming light intensity and color, many depth sensors rely on more complicated physical mechanisms.

### Structured-light sensors

A sensor projects an infrared pattern onto the scene and estimates depth from how the pattern appears.

### Time-of-Flight sensors

A sensor emits infrared light and estimates distance from the returning signal.

### Stereo cameras

Two cameras observe the scene from slightly different positions, and depth is estimated from image disparity.

All of these techniques rely on assumptions about how light interacts with surfaces.

When those assumptions are violated, depth measurements become unreliable.

## 14. Why are transparent surfaces difficult for depth sensors?

Consider a glass surface.

Ideally, the sensor expects emitted light to hit the visible surface and return.

However, with glass, the light may pass through the surface and reach an object behind it.

For example:

$$  
\text{camera} \rightarrow \text{glass} \rightarrow \text{wall behind the glass}  
$$

The sensor may therefore measure the wall rather than the glass.

Suppose the true glass surface is

$$  
1.0 \text{ m}  
$$

away, while the wall behind it is

$$  
2.5 \text{ m}  
$$

away.

The depth sensor may incorrectly return

$$  
D = 2.5 \text{ m}  
$$

Some light may also reflect from the glass while other light passes through it, producing unstable or inconsistent measurements.

Therefore, transparent objects violate the assumption that:

> the detected signal comes from the first visible surface.

## 15. Why are reflective surfaces difficult?

Consider shiny metal or a mirror.

A depth sensor may emit light toward the surface.

Instead of returning to the sensor, the light may undergo specular reflection and travel in another direction.

Therefore, the returning signal may be:

- extremely weak,
    
- missing,
    
- reflected from another object,
    
- inconsistent with the true surface position.
    

This can produce:

- missing depth values,
    
- holes in the depth map,
    
- unstable depth,
    
- very large errors,
    
- incorrect 3D points.
    

Thus reflective surfaces can make geometric measurements unreliable.
## 16. Why is depth often described as noisier than RGB for transparent or reflective objects?

This does **not** mean that RGB reconstruction is easy for glass or mirrors.

Transparent and reflective objects are also difficult for RGB-based reconstruction.

However, an RGB camera will usually still record valid pixel values:

$$  
(R,G,B)  
$$

For example, a mirror still produces a normal-looking image containing reflected colors.

A depth sensor, on the other hand, may return:

- no measurement,
    
- zero,
    
- the distance of an object behind the glass,
    
- a completely incorrect value.
    

Therefore, for transparent or reflective surfaces, the **geometric depth measurement itself may become severely corrupted**.

That is why papers often describe depth input as noisy or unreliable in these situations.
## 17. How everything connects together

A traditional articulated-object reconstruction system may look like:

$$  
\text{RGB + depth}  
\rightarrow  
\text{point correspondence}  
\rightarrow  
\text{3D point tracking}  
\rightarrow  
\text{motion estimation}  
\rightarrow  
\text{part clustering}  
\rightarrow  
\text{joint / kinematic structure estimation}  
\rightarrow  
\text{final articulated 3D model}  
$$

The problem is that each intermediate result may contain errors.

For example:

$$  
\text{bad depth}  
\rightarrow  
\text{bad 3D points}  
\rightarrow  
\text{bad motion estimation}  
\rightarrow  
\text{bad clustering}  
\rightarrow  
\text{bad articulation}  
$$

Similarly:

$$  
\text{wrong correspondence}  
\rightarrow  
\text{wrong geometry}  
\rightarrow  
\text{wrong clustering}  
\rightarrow  
\text{wrong joint axis}  
$$

Therefore, traditional multi-stage pipelines can become fragile.
## 18. Core takeaway

The central reason traditional articulated 3D reconstruction methods often rely on strong assumptions and complicated intermediate procedures is:

> **The original problem is highly ambiguous and underdetermined. RGB observations alone do not directly reveal depth, correspondence, object parts, motion, or articulation.**

Therefore, traditional methods simplify the problem by imposing assumptions and solving several smaller subproblems sequentially.

The three important intermediate concepts are:

### Point correspondence

> Which observations in different images represent the same physical 3D point?

$$  
p_i^t \leftrightarrow p_j^{t+1}  
$$

### Part clustering

> Which reconstructed points belong to the same moving rigid part?

$$  
{P_i} \rightarrow {\text{part}_1,\text{part}_2,\dots}  
$$

### Auxiliary depth

> How far away is the surface corresponding to each pixel?

$$  
D(u,v) = z  
$$

The difficulty is that these quantities depend on each other:

$$  
\boxed{\text{geometry} \leftrightarrow \text{correspondence} \leftrightarrow \text{motion} \leftrightarrow \text{part assignment}}  
$$

Traditional methods often resolve this circular dependency by imposing strong assumptions and constructing multi-stage pipelines.

But this introduces another problem:

$$  
\boxed{\text{error in one stage} \rightarrow \text{error propagation to later stages}}  
$$

Therefore, newer methods often try to reduce the number of manually designed intermediate stages and jointly optimize geometry, motion, and articulation directly from RGB observations.

### What does “parameterization” mean?

**Parameterization = describing something using a set of numbers called parameters.**

For example, suppose I want to describe a point in 2D space.

Instead of saying:

> “the point over there”

I describe it with two numbers:

$$ (x,y) $$

For example,

$$(2,3) $$

Here, $x$ and $y$ are the **parameters**. So $(x,y)$ is a **parameterization of a 2D point**.

Another example: a circle.

A point on a circle can be described by an angle $\theta$:

$$ x=\cos\theta,\qquad y=\sin\theta $$

Instead of describing every possible point separately, I use **one parameter $\theta$**.

That is parameterization.So whenever you see "parameterize something". you can mentally replace it with: "**represent / describe it using some numbers that we can adjust.**"

Now let's come back to the paper. The authors want to describe a **joint axis**. For example, imagine the hinge of a laptop:

```
        screen
          /
         /
========●========  ← hinge axis
     keyboard
```

The computer needs some numerical way to represent that hinge axis. The paper uses a **screw axis** to represent it:

$$S= \begin{bmatrix} \omega\\ v \end{bmatrix} \in\mathbb{R}^6$$

So there are six numbers:

$$S= (\omega_1,\omega_2,\omega_3,v_1,v_2,v_3)$$

Those numbers are the **parameters describing the joint axis**. That is why we can say: the screw model **parameterizes** the joint axis. It means:

> the screw model converts the idea of “a joint axis somewhere in 3D” into numerical variables that the computer can work with.
### So what does the whole sentence mean?

The paper says:

> “a screw model that provides a continuous parameterization of joint axes”

Break it apart:

$$
\text{screw model} \rightarrow \text{a mathematical model describing rigid motion}
$$

$$\text{parameterization of joint axes}\rightarrow\text{represent the joint axis using numerical parameters}$$

$$\text{continuous parameterization} \rightarrow \text{those parameters are continuous numbers that can be changed smoothly}$$

So the whole thing means:

> **They use screw theory to represent each unknown joint axis using continuous numerical variables, so that the joint axis can be gradually adjusted during optimization.**

This is extremely important for ScrewSplat because the authors want to use optimization.

Imagine they start with a **wrong random axis**:

```
True hinge:
----------------→

Initial guess:
      /
     /
    ↗
```

The optimizer can gradually change the screw parameters:

```
      ↗
       ↗
        →
         →
----------------→
```

until it finds the correct hinge.

And this is exactly why the paper says they can **randomly initialize screw axes and then iteratively optimize them**.

So you can remember one very useful translation:

> **parameterization = 用一组参数/数字来表示一个东西**

and

> **continuous parameterization = 用可以连续变化的数值参数来表示一个东西**

Therefore:

> **continuous parameterization of joint axes = 用一组可以连续优化的数值来表示关节轴。**

This idea will become even more important when you reach $S=[\omega,v]^T$, because then you'll see **exactly what those parameters mean geometrically**.

## 1. Why does the paper say "without relying on discrete variables"?

The paper says:

> To represent joint types and counts without relying on discrete variables, we introduce confidence scores over screw axes and use a probability simplex to softly assign Gaussians to rigid parts.

The reason is that some unknowns in this problem are naturally **discrete**.

For example:

- joint type: revolute or prismatic
- joint count: 1, 2, 3, ...
- part label: base, movable part 1, movable part 2, ...

A hard discrete assignment could look like:

$$
\text{label}_i \in \{0,1,2\}
$$

This means Gaussian $i$ must belong to exactly one part.

However, ScrewSplat wants to optimize the whole system using gradient-based optimization. Gradient descent works much better with continuous variables than with hard discrete choices.

So instead of directly deciding:

> this screw exists / does not exist

or

> this Gaussian belongs to part 1 / part 2

the paper replaces these hard decisions with continuous values.

This is why it says:

> **without relying on discrete variables**

The motivation is also related to previous methods. Some previous approaches require prior knowledge such as:

- the number of movable parts,
- the number of joints,
- or the joint type.

ScrewSplat tries to avoid requiring this information beforehand.
## 2. What is a confidence score?

For each candidate screw axis $A_j$, ScrewSplat defines a confidence value

$$
\gamma_j \in [0,1].
$$

The screw primitive is written as

$$
A_j=(S_j,\gamma_j)
$$

where:

- $S_j$ = the screw axis
- $\gamma_j$ = the confidence of that screw axis

We can think of $\gamma_j$ as:

> **how strongly the model believes that this screw axis is useful or corresponds to a real joint.**

For example:

$$
\gamma_1 = 0.95
$$

means screw 1 is probably important.

But

$$
\gamma_2 = 0.08
$$

means screw 2 is probably unnecessary.

Instead of using a hard discrete variable such as

$$
z_j \in \{0,1\},
$$

where

- $z_j=1$ means the screw exists,
- $z_j=0$ means it does not exist,

the paper uses the continuous value

$$
\gamma_j \in [0,1].
$$

Therefore, the model can gradually reduce the importance of unnecessary screw axes during optimization.
## 3. What is a probability simplex?

Each Gaussian has a vector

$$
m_i=(m_{i0},m_{i1},\dots,m_{in_s}).
$$

The paper says this vector lies in a **probability simplex**.

This simply means:

$$
m_{ij} \ge 0
$$

for every $j$, and

$$
\sum_j m_{ij}=1.
$$

So all the entries behave like probabilities.

For example:

$$
m_i=(0.1,0.8,0.1)
$$

could mean:

- 10% probability of belonging to the static base
- 80% probability of belonging to movable part 1
- 10% probability of belonging to movable part 2

Therefore:

> **A probability simplex is a vector of nonnegative values that sum to 1.**
## 4. What does "softly assign Gaussians to rigid parts" mean?

A **hard assignment** means choosing exactly one part.

For example:

$$
m_i=(0,1,0).
$$

This means:

> Gaussian $i$ definitely belongs to part 1.

A **soft assignment** means allowing partial probabilities.

For example:

$$
m_i=(0.1,0.8,0.1).
$$

This means:

> Gaussian $i$ is mostly associated with part 1, but there is still some uncertainty.

During optimization, the probabilities can change smoothly:

$$
(0.3,0.4,0.3)
\rightarrow
(0.2,0.6,0.2)
\rightarrow
(0.05,0.9,0.05).
$$

So:

> **softly assign = assign using probabilities instead of a hard discrete label.**

This makes the assignment differentiable and easier to optimize.

## 5. Why does the paper say "rigid parts"? What about soft parts?

Here, **rigid** does not mean hard material.

It means:

> the shape of the part itself does not deform while it moves.

For example:

- laptop screen
- laptop base
- drawer
- cabinet
- chair component

These parts can rotate or translate, but their own shape remains fixed.

So a laptop is an **articulated rigid object**:

- each individual part is rigid,
- but different rigid parts can move relative to each other through joints.

In contrast, soft or deformable objects include:

- cloth
- rope
- rubber
- sponge

Their shapes can bend, stretch, or deform internally.

ScrewSplat is mainly designed for articulated objects made of rigid parts, not general deformable objects such as cloth.

One important wording point is:

> **softly assign Gaussians to rigid parts**

Here, **softly** describes the assignment method.

It does **not** mean the parts are soft.

So:

- **soft assignment** = probabilistic assignment
- **rigid part** = non-deformable component
