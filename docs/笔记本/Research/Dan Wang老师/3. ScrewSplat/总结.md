### 1. Problems of previous methods

Previous articulated-object recognition methods had several important disadvantages.

First, some methods required **prior knowledge of the number of joints or movable parts**. In other words, before running the method, the user already had to know how many articulated components existed. 2508.02146v2

Second, some methods required the **joint type to be known beforehand**, for example whether the joint was revolute or prismatic. 2508.02146v2

Third, some methods relied on **depth or RGB-D input** instead of only RGB. The paper points out that depth can be noisy, especially for transparent or reflective objects. 2508.02146v2

Fourth, many previous methods used **multi-stage pipelines**, such as:

- part clustering
- point correspondence matching
- motion analysis after segmentation

These intermediate stages make the whole pipeline more complicated, and errors in one stage can hurt the final result. 2508.02146v2

Fifth, some earlier approaches were limited in the kinds of objects they could handle. For example, PARIS is limited to single-joint objects with known joint type, while ArticulatedGS can only recover one articulation per optimization step. 2508.02146v2

So the real problem ScrewSplat addresses is:

> **Can we recover the geometry and kinematic structure of articulated objects directly from RGB images, without knowing the joint count or type beforehand, and without complicated intermediate stages?**

### 2. How ScrewSplat solves these problems

ScrewSplat combines **3D Gaussian Splatting** and **screw theory**.

Gaussian Splatting represents the object's geometry and appearance.

Screw theory represents the motion of movable rigid parts.

Instead of using hard discrete decisions for joint count, joint type, and part labels, ScrewSplat introduces:

- screw confidence scores $\gamma_j$
- part-membership probability vectors $m_i$

This lets the whole problem be optimized in a smooth, differentiable way.

The model initializes many candidate screws, then jointly optimizes:

- geometry
- part segmentation
- screw axes
- screw confidences
- joint angles

It renders RGB images and compares them with the real observations. The variables are updated so the rendered images match the real ones.

The parsimony loss

$$\beta\sum_j\sqrt{\gamma_j}$$

discourages the model from keeping unnecessary screw primitives.

So ScrewSplat solves the disadvantages of previous methods by making the pipeline:

> **RGB-only + end-to-end + no prior joint count + no prior joint type + no separate clustering/correspondence stage.**

### 3. What new capability does it provide?

After recovering the object model, ScrewSplat can also be used for **zero-shot text-guided manipulation**.

For example:

> “open laptop”

The model renders possible joint configurations, uses CLIP to find which configuration best matches the text, and then plans robot motion toward that target configuration. 2508.02146v2

### 4. Limitations of ScrewSplat

Its own limitations are different from the previous-method problems.

The first limitation is that it is sensitive to the parsimony weight $\beta$:

- $\beta$ too small → too many screws
- $\beta$ too large → real movable parts may disappear

The second limitation is that **shadows and lighting changes** can be mistaken for geometry or motion changes.

The third limitation is that current ScrewSplat assumes movable parts articulate relative to a single static base, so it cannot properly handle **serial kinematic chains** such as robot arms.

The fourth limitation is that it mainly handles **rigid articulated parts**, not general deformable objects such as ropes or cloth. 2508.02146v2

### 5. How the authors suggest solving these limitations

For the $\beta$ / screw-selection problem:

- better initialization of screw axes
- adaptive adjustment of $\beta$
- dynamically removing or densifying screw axes

For the shadow problem:

- explicitly model lighting
- make Gaussian color depend on joint configuration

For kinematic chains:

- use the product-of-exponentials formulation

\[ T' = e^{[S_1]\theta_1} e^{[S_2]\theta_2} \cdots e^{[S_n]\theta_n} T \]

For deformable objects:

- explore pseudo-rigid-body models, especially for one-dimensional deformable objects such as ropes. 2508.02146v2

So the clean paper-summary logic should be:

> **Previous methods had strong assumptions and complicated pipelines → ScrewSplat removes those assumptions with an end-to-end RGB-only differentiable formulation → but ScrewSplat itself still has optimization, lighting, kinematic-chain, and deformation limitations.**
