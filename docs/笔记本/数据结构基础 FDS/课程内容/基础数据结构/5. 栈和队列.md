
## 1. Stack ADT

### 1.1 栈的定义

Stack是一种 **Last-In-First-Out** 的线性表，简称 **LIFO**。

也就是说：

- 最后插入的元素最先被删除。
- 插入和删除都只发生在栈顶（top）。

可以把栈想成一摞盘子：新盘子只能放在最上面，取盘子也只能从最上面取。

### 1.2 栈的对象

Stack ADT 的对象是一个有限有序表：

```text
S = (a0, a1, ..., an-1)
```

它可以有 0 个或多个元素。

### 1.3 栈的操作

课件中给出的 Stack ADT 操作包括：

1. `int IsEmpty(Stack S);`

    判断栈是否为空。

2. `Stack CreateStack();`

    创建一个栈。

3. `DisposeStack(Stack S);`

    销毁一个栈。

4. `MakeEmpty(Stack S);`

    清空一个栈。

5. `Push(ElementType X, Stack S);`

    将元素 `X` 压入栈顶。

6. `ElementType Top(Stack S);`

    返回栈顶元素，但不删除它。

7. `Pop(Stack S);`

    删除栈顶元素。

!!! warning "ADT 错误与实现错误"
    对空栈执行 `Pop` 或 `Top` 是 Stack ADT 本身的错误，因为空栈没有栈顶元素。

    但对满栈执行 `Push` 是实现错误，而不是 ADT 错误。因为“满”来自具体实现，例如数组容量有限；ADT 本身只描述逻辑行为，并不要求栈天然有固定容量。

### 2.2 数组实现

数组实现通常用一个结构体记录容量、栈顶位置和数组本身：

```c
struct StackRecord {
    int Capacity;          /* size of stack */
    int TopOfStack;        /* the top pointer */
    ElementType *Array;    /* array for stack elements */
};
```

其中：

- `Capacity` 表示数组容量。
- `TopOfStack` 表示栈顶下标。
- `Array` 存放栈中元素。

课件中约定：

- `TopOfStack == -1` 表示空栈。
- `Push` 时 `TopOfStack++`。
- `Pop` 时 `TopOfStack--`。

#### 2.2.1 数组栈的基本操作

判断空栈：

```c
int IsEmpty(Stack S) {
    return S->TopOfStack == -1;
}
```

判断满栈：

```c
int IsFull(Stack S) {
    return S->TopOfStack == S->Capacity - 1;
}
```

压栈：

```c
void Push(ElementType X, Stack S) {
    if (IsFull(S)) {
        Error("Full stack");
    } else {
        S->Array[++S->TopOfStack] = X;
    }
}
```

取栈顶：

```c
ElementType Top(Stack S) {
    if (IsEmpty(S)) {
        Error("Empty stack");
    } else {
        return S->Array[S->TopOfStack];
    }
}
```

出栈：

```c
void Pop(Stack S) {
    if (IsEmpty(S)) {
        Error("Empty stack");
    } else {
        S->TopOfStack--;
    }
}
```

### 2.3 封装与错误检查

课件强调两点：

1. 栈模型必须被良好封装。

    除了栈自己的操作函数之外，代码的其他部分不应该直接访问 `Array` 或 `TopOfStack`。

2. `Push`、`Pop`、`Top` 前必须做错误检查。

    `Push` 前检查是否满；`Pop` 和 `Top` 前检查是否空。

!!! summary "栈实现小结"
    链表实现容量灵活，但频繁 `malloc/free` 可能较慢；数组实现简单、连续、速度快，但容量固定，需要检查满栈。

## 3. 栈的应用

### 3.1 Balancing Symbols

符号匹配问题：检查表达式中的 `()`、`[]`、`{}` 是否平衡。

算法如下：

```text
Make an empty stack S;

while (read in a character c) {
    if (c is an opening symbol) {
        Push(c, S);
    } else if (c is a closing symbol) {
        if (S is empty) {
            ERROR;
            exit;
        } else {
            if (Top(S) does not match c) {
                ERROR;
                exit;
            } else {
                Pop(S);
            }
        }
    }
}

if (S is not empty) {
    ERROR;
}
```

### 3.1.1 为什么这个算法正确？

遇到左括号时，把它压入栈中；遇到右括号时，它必须和“最近还没有匹配的左括号”配对。

而“最近还没有匹配的左括号”正好在栈顶，所以栈非常适合处理这类嵌套结构。

!!! example "正确例子：`{ [ ( ) ] }`"
    从左到右扫描，栈底写在左边，栈顶写在右边。

    1. 初始时，栈为空。

        ```text
        stack: []
        ```

    2. 读到 `{`，它是 opening symbol，压栈。

        ```text
        stack: [{]
        ```

    3. 读到 `[`，压栈。

        ```text
        stack: [{, []
        ```

    4. 读到 `(`，压栈。

        ```text
        stack: [{, [, (]
        ```

    5. 读到 `)`，它是 closing symbol。此时栈顶是 `(`，二者匹配，所以弹出 `(`。

        ```text
        stack: [{, []
        ```

    6. 读到 `]`，栈顶是 `[`，二者匹配，所以弹出 `[`。

        ```text
        stack: [{]
        ```

    7. 读到 `}`，栈顶是 `{`，二者匹配，所以弹出 `{`。

        ```text
        stack: []
        ```

    8. 扫描结束后栈为空，说明所有 opening symbol 都被正确匹配，因此表达式平衡。

!!! example "错误例子：`{ [ ( ] ) }`"
    这个例子中，括号数量看起来是够的，但嵌套顺序错了。

    1. 初始时，栈为空。

        ```text
        stack: []
        ```

    2. 读到 `{`，压栈。

        ```text
        stack: [{]
        ```

    3. 读到 `[`，压栈。

        ```text
        stack: [{, []
        ```

    4. 读到 `(`，压栈。

        ```text
        stack: [{, [, (]
        ```

    5. 读到 `]`，它是 closing symbol。此时栈顶是 `(`，但 `]` 应该匹配 `[`，所以栈顶不匹配。

        ```text
        stack: [{, [, (]
        ```

    6. 立刻报错并退出，因为最近还没有匹配的 opening symbol 是 `(`，它必须先遇到 `)`，不能先遇到 `]`。

    这个例子说明：符号平衡不只是数量相同，还要求嵌套顺序正确。

### 3.1.2 复杂度

每个字符只被扫描一次，每个符号最多入栈一次、出栈一次，因此：

$$
T(N) = O(N)
$$

其中 $N$ 是表达式长度。

这是一个 on-line algorithm，也就是说可以一边读入一边处理，不需要先拿到整个输入。

## 4. 后缀表达式求值

### 4.1 中缀、前缀、后缀

以表达式：

```text
a + b * c - d / e
```

为例：

- 中缀表达式（infix expression）：`a + b * c - d / e`
- 前缀表达式（prefix expression）：`- + a * b c / d e`
- 后缀表达式（postfix expression）：`a b c * + d e / -`


遇到复杂的式子，千万不要在脑子里硬转，用“全部加括号法”可以保证 100% 正确率。我们以 `A + B * C` 为例，目标是转成**后缀表达式**：

- **第一步：按优先级，给所有的运算加上括号。**
    - 原本是 $A + B \times C$，乘法优先，所以变成：`( A + ( B * C ) )`
- **第二步：把所有的运算符，移动到它专属的那个括号位置。**
    - **如果是转后缀：就把运算符移动到对应的**右括号**外面。即`( A ( B C )* )+`
    - **如果是转前缀：就把运算符移动到对应的**左括号**外面。即`+( A *( B C ) )`
- **第三步：把所有的括号去掉，大功告成！
    - **后缀结果：** `A B C * +`
    - **前缀结果：** `+ A * B C`

### 套用上面的公式来写一下$(a+b-c \times(\frac{d}{e}))+f$ ：
![](附件/458817f4f47704af2eb1de5ddbc67daa.jpg)


### 4.2 后缀表达式求值规则

从左到右扫描 token：

1. 如果 token 是操作数，直接压栈。
2. 如果 token 是操作符，从栈中弹出所需数量的操作数。
3. 计算结果。
4. 把结果重新压回栈。
5. 扫描结束后，栈中唯一元素就是结果。

!!! warning "二元运算的顺序"
    对于减法和除法，弹出顺序很重要。

    如果先弹出的是 `right`，后弹出的是 `left`，那么计算应为：

    ```text
    left op right
    ```

    例如遇到 `/` 时，不能算成 `right / left`。

### 4.3 Example

计算：

```text
6 2 / 3 - 4 2 * +
```

过程如下：

1. 读到 `6`，压栈。

    ```text
    [6]
    ```

2. 读到 `2`，压栈。

    ```text
    [6, 2]
    ```

3. 读到 `/`，弹出 `2` 和 `6`，计算 $6 / 2 = 3$，压回 `3`。

    ```text
    [3]
    ```

4. 读到 `3`，压栈。

    ```text
    [3, 3]
    ```

5. 读到 `-`，弹出 `3` 和 `3`，计算 $3 - 3 = 0$，压回 `0`。

    ```text
    [0]
    ```

6. 读到 `4`，压栈。

    ```text
    [0, 4]
    ```

7. 读到 `2`，压栈。

    ```text
    [0, 4, 2]
    ```

8. 读到 `*`，弹出 `2` 和 `4`，计算 $4 \times 2 = 8$，压回 `8`。

    ```text
    [0, 8]
    ```

9. 读到 `+`，弹出 `8` 和 `0`，计算 $0 + 8 = 8$，压回 `8`。

    ```text
    [8]
    ```

最终结果为：

$$
8
$$

### 4.4 复杂度

后缀表达式求值只需要从左到右扫描一次：

$$
T(N) = O(N)
$$

它的优点是不需要处理运算符优先级，因为优先级已经体现在后缀表达式的顺序里。

## 5. 中缀表达式转后缀表达式

### 5.1 基本观察

从中缀表达式转为后缀表达式时，有两个重要观察：

1. 操作数的相对顺序不变。

    例如 `a + b * c - d` 转成后缀后，操作数仍然按 `a b c d` 的顺序出现。

2. 高优先级操作符应该更早输出。

    因为后缀表达式中，操作符出现在它对应的操作数之后；越先计算的操作符，通常越早出现在输出中。

### 5.2 基本算法

维护一个操作符栈，从左到右扫描中缀表达式：

1. 如果 token 是操作数，直接输出。
2. 如果 token 是左括号 `(`，压入操作符栈。
3. 如果 token 是右括号 `)`，不断弹出并输出操作符，直到遇到左括号 `(`，然后丢弃这一对括号。
4. 如果 token 是普通操作符：

    - 当栈顶操作符优先级大于或等于当前操作符时，弹出栈顶并输出。
    - 然后把当前操作符压栈。

5. 输入结束后，把栈中剩余操作符全部弹出并输出。

### 5.3 无括号例子

将：

```text
a + b * c - d
```

转换为后缀表达式。

过程如下：

1. 读到 `a`，直接输出。

    ```text
    output: a
    stack:  empty
    ```

2. 读到 `+`，操作符栈为空，压栈。

    ```text
    output: a
    stack:  +
    ```

3. 读到 `b`，直接输出。

    ```text
    output: a b
    stack:  +
    ```

4. 读到 `*`，因为 `+` 的优先级小于 `*`，所以 `*` 压栈。

    ```text
    output: a b
    stack:  + *
    ```

5. 读到 `c`，直接输出。

    ```text
    output: a b c
    stack:  + *
    ```

6. 读到 `-`，栈顶 `*` 优先级大于 `-`，弹出 `*`；新的栈顶 `+` 优先级等于 `-`，也弹出 `+`；然后把 `-` 压栈。

    ```text
    output: a b c * +
    stack:  -
    ```

7. 读到 `d`，直接输出。

    ```text
    output: a b c * + d
    stack:  -
    ```

8. 输入结束，弹出剩余的 `-`。

    ```text
    output: a b c * + d -
    stack:  empty
    ```

所以：

```text
a + b * c - d  ==>  a b c * + d -
```

### 5.4 有括号例子

将：

```text
a * (b + c) / d
```

转换为后缀表达式。

过程如下：

1. 读到 `a`，直接输出。

    ```text
    output: a
    stack:  empty
    ```

2. 读到 `*`，压栈。

    ```text
    output: a
    stack:  *
    ```

3. 读到 `(`，压栈。

    ```text
    output: a
    stack:  * (
    ```

4. 读到 `b`，直接输出。

    ```text
    output: a b
    stack:  * (
    ```

5. 读到 `+`，由于栈顶是 `(`，不能把 `(` 弹出，所以 `+` 压栈。

    ```text
    output: a b
    stack:  * ( +
    ```

6. 读到 `c`，直接输出。

    ```text
    output: a b c
    stack:  * ( +
    ```

7. 读到 `)`，弹出并输出直到遇到 `(`。因此输出 `+`，然后丢弃 `(`。

    ```text
    output: a b c +
    stack:  *
    ```

8. 读到 `/`，栈顶 `*` 与 `/` 同优先级，弹出 `*`；然后把 `/` 压栈。

    ```text
    output: a b c + *
    stack:  /
    ```

9. 读到 `d`，直接输出。

    ```text
    output: a b c + * d
    stack:  /
    ```

10. 输入结束，弹出剩余的 `/`。

    ```text
    output: a b c + * d /
    stack:  empty
    ```

所以：

```text
a * (b + c) / d  ==>  a b c + * d /
```

### 5.5 括号的特殊规则

课件给出两个处理括号的关键点：

1. 除了处理右括号 `)` 时，永远不要把 `(` 从栈中弹出。
2. `(` 的优先级要分情况看：

    - 当 `(` 还没入栈、作为 incoming symbol 时，它的优先级最高，这样它可以顺利入栈。
    - 当 `(` 已经在栈中、作为 in-stack symbol 时，它的优先级最低，这样普通操作符不会把它弹出。

这就是为什么有时需要区分 **in-stack precedence** 和 **incoming precedence**。

### 5.6 结合性问题

对左结合运算符，例如减法：

```text
a - b - c
```

应该转换为：

```text
a b - c -
```

这对应：

```text
(a - b) - c
```

所以遇到第二个 `-` 时，需要弹出前面的 `-`。

但是指数运算通常是右结合的：

```text
2 ^ 2 ^ 3
```

应该理解为：

```text
2 ^ (2 ^ 3)
```

所以应转换为：

```text
2 2 3 ^ ^
```

而不是：

```text
2 2 ^ 3 ^
```

!!! warning "右结合操作符"
    对于右结合操作符，遇到同优先级操作符时不能简单地“栈顶优先级 >= 当前优先级就弹出”。否则会把右结合错误处理成左结合。

### 5.7 复杂度

每个 token 最多入栈一次、出栈一次，因此：

$$
T(N) = O(N)
$$

## 6. Function Calls 与系统栈

函数调用本身也依赖系统栈（system stack）。

每次函数调用时，系统通常会在栈上保存一个 stack frame，里面可能包括：

1. 返回地址（Return Address）。
2. 局部变量（Local Variables）。
3. 旧的 frame pointer。
4. 其他调用现场信息。

### 6.1 递归与系统栈

递归打印链表的例子：

```c
void PrintList(List L) {
    if (L != NULL) {
        PrintElement(L->Element);
        PrintList(L->next);
    }
}
```

这个函数是 tail recursion（尾递归），它是一个 bad use of recursion。

原因是：如果链表有 1,000,000 个节点，就可能产生 1,000,000 层函数调用，系统栈可能会被压爆。

### 6.2 尾递归可以被消除

上面的递归本质上可以写成循环：

```c
void PrintList(List L) {
    while (L != NULL) {
        PrintElement(L->Element);
        L = L->next;
    }
}
```


!!! summary "递归与非递归"
    递归总是可以被完全移除。非递归程序通常比等价递归程序更快，因为它少了函数调用开销。

    但是递归程序通常更简单、更容易理解，所以是否使用递归要看问题结构和数据规模。

## 7. Queue ADT

### 7.1 队列的定义

Queue是一种 **First-In-First-Out** 的线性表，简称 **FIFO**。

也就是说：

- 插入发生在一端。
- 删除发生在另一端。
- 最先进入队列的元素最先离开队列。

可以把队列想成排队：先来的人先被服务。

### 7.2 队列的对象

Queue ADT 的对象也是一个有限有序表，可以有 0 个或多个元素。

### 7.3 队列的操作

1. `int IsEmpty(Queue Q);`

    判断队列是否为空。

2. `Queue CreateQueue();`

    创建一个队列。

3. `DisposeQueue(Queue Q);`

    销毁一个队列。

4. `MakeEmpty(Queue Q);`

    清空一个队列。

5. `Enqueue(ElementType X, Queue Q);`

    将元素插入队尾。

6. `ElementType Front(Queue Q);`

    返回队头元素，但不删除。

7. `Dequeue(Queue Q);`

    删除队头元素。

等等

## 8. 队列的数组实现

链表实现队列比较直接，重点讲数组实现。

数组队列通常用如下结构：

```c
struct QueueRecord {
    int Capacity;          /* max size of queue */
    int Front;             /* the front pointer */
    int Rear;              /* the rear pointer */
    int Size;              /* optional: current size of queue */
    ElementType *Array;    /* array for queue elements */
};
```

其中：

- `Front` 指向队头。
- `Rear` 指向队尾。
- `Size` 记录当前元素个数，是可选字段。
- `Array` 存放队列元素。

### 8.1 为什么普通数组队列会浪费前面空间？

如果只让 `Rear` 一直向右移动，执行多次 `Dequeue` 后，数组前面会出现空位。

例如容量为 7 的数组：

如果删除 `Job1`、`Job2` 后：

前面的空位明明可以复用，但如果 `Rear` 只能向右走，就会很快碰到数组末尾。

所以数组队列通常要做成 circular queue。

## 9. Circular Queue

### 9.1 循环队列的核心思想

循环队列把数组想成一个环。
![](附件/Pasted%20image%2020260623155647.png)

当指针走到数组最后一个位置后，再往后走就回到 0：

$$
\text{next}(i) = (i + 1) \bmod \text{Capacity}
$$

这样数组前面被 `Dequeue` 空出来的位置就能被后续 `Enqueue` 重新使用。

### 9.2 指针移动

课件中的图采用这套约定：

- `Front` 指向队头元素。
- `Rear` 指向队尾元素。
- 空队列时，`Rear` 在 `Front` 的前一格。

入队时：

```c
Rear = (Rear + 1) % Capacity;
Array[Rear] = X;
```

出队时：

```c
Front = (Front + 1) % Capacity;
```

如果队列原本只有一个元素，那么出队前有 `Front == Rear`；出队后 `Front` 前进一步，于是又回到“`Rear` 在 `Front` 前一格”的空队列状态。

!!! note "不同教材的指针约定"
    有些教材会让 `Front` 指向队头前一个位置，此时空队列条件常写成 `Front == Rear`。

    但这份课件的图不是这种约定。课件中 `Front` 指向队头元素，所以空队列不是 `Front == Rear`。

关键思想是：指针移动用取模来实现“绕回去”。

![](附件/Pasted%20image%2020260623160030.png)

### 9.3 空队列与满队列的冲突

我们会发现，初始位置中，`Rear` 反而在 `Front` 的后面；插入第一个元素之后，`Rear` 才和 `Front` 指向同一个位置。而且，最后明明还有一个空位，为什么会说 `The queue is full` 呢？

空队列条件是：

```c
(Rear + 1) % Capacity == Front
```

也就是 `Rear` 的下一个位置就是 `Front`。这正好对应图中的初始状态：`Rear` 在 `Front` 前一格。

如果我们把所有格子都塞满，那么也会出现：

```c
(Rear + 1) % Capacity == Front
```

这就和空队列完全一样，无法区分。

所以我们选择**故意浪费一个空位置**。

此时，满队列条件变成：

```c
(Rear + 2) % Capacity == Front
```

也就是说，只要 `Rear` 再往后走两步就会到达 `Front`，就宣布队列满。

!!! question "为什么还有一个空格却说满了？"
    因为如果把最后一个空格也填上，`Rear` 的下一个位置就会变成 `Front`，这和空队列条件一模一样。

    为了让“`Rear` 在 `Front` 前一格”只表示空队列，我们牺牲一个数组位置不用。

### 9.4 不浪费空间的方法

课件提示：加入 `Size` 字段可以避免浪费一个空位置。

如果维护当前元素个数 `Size`，则：

- 空队列条件：

    ```c
    Size == 0
    ```

- 满队列条件：

    ```c
    Size == Capacity
    ```

这样即使出现“`Rear` 的下一个位置是 `Front`”这种容易混淆的状态，也能通过 `Size` 判断到底是空还是满。

!!! note "另一种想法"
    除了 `Size` 字段，也可以额外维护一个 `Tag` 或 `Flag`，记录最近一次操作是入队还是出队。

    对课件这套指针约定来说，如果 `(Rear + 1) % Capacity == Front` 且最近一次操作是出队，则为空；如果这个关系出现在填满所有格子后，则为满。

## 10. 本节总结

1. 栈是 LIFO，只在栈顶插入和删除。
2. 对空栈执行 `Top` 或 `Pop` 是 ADT 错误；对满栈 `Push` 是实现错误。
3. 栈可以用链表或数组实现，数组实现中 `TopOfStack == -1` 通常表示空栈。
4. 栈适合处理嵌套结构，例如括号匹配、后缀表达式求值和中缀转后缀。
5. 后缀表达式求值不需要处理运算符优先级，复杂度为 $O(N)$。
6. 中缀转后缀时，括号和右结合操作符是最容易出错的地方。
7. 函数调用依赖系统栈，过深递归可能导致栈溢出。
8. 队列是 FIFO，在一端入队、另一端出队。
9. 数组队列通常要做成循环队列，才能复用前面释放出来的位置。
10. 循环队列若只用 `Front` 和 `Rear`，通常需要浪费一个位置来区分空和满；加入 `Size` 字段可以避免这个浪费。
