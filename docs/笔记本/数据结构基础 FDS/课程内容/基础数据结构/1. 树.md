
## 1. 树的基本概念

### 1.1 树的定义

树是一组节点的集合。

树可以是空的；如果不是空树，那么它由下面两部分组成：

1. 一个特殊节点 $r$，称为根节点（root）。
2. 零个或多个非空子树 $T_1, T_2, \cdots, T_k$。每棵子树的根都由一条从 $r$ 出发的有向边连接。

!!! note "树的几个默认约定"

    1. 子树之间不能互相连起来，否则就不是树了。
    2. 树中的每个节点，都可以看成某棵子树的根（因为子树是互不相连的）。
    3. 如果一棵树有 $N$ 个节点，那么它有 $N - 1$ 条边。
    4. 画树的时候，通常把 root 画在最上面。

### 1.2 常用术语

1. **degree of a node**
    - 一个节点的 degree 等于它的子树数量，也就是它有几个 children。
2. **degree of a tree**
    - 一棵树的 degree 等于所有节点 degree 的最大值。
3. **leaf / terminal node**
    - degree 为 0 的节点叫 leaf，也就是没有 children 的节点。
4. **parent / children / siblings**
     - 有子树的节点是这些子树根节点的 parent；
     - 这些子树的根是它的 children；
     - 拥有同一个 parent 的节点互为 siblings。
5. **ancestors / descendants**
     - 从某个节点一路往上走到 root，路径上遇到的节点是它的 ancestors；
     - 某个节点的所有子树中的节点是它的 descendants。
6. **path**
    从 $n_1$ 到 $n_k$ 的 path 是一个节点序列：
    $$
    n_1, n_2, \cdots, n_k
    $$

    其中 $n_i$ 是 $n_{i+1}$ 的 parent。

7. **length of path**
     - 路径长度等于路径上的边数。
8. **depth**
     - 节点 $n_i$ 的 depth 是从 root 到 $n_i$ 的唯一路径长度。root 的 depth 为 0。
9. **height**
     - 节点 $n_i$ 的 height 是从 $n_i$ 到某个 leaf 的最长路径长度。leaf 的 height 为 0。
10. **height / depth of a tree**
     - 树的 height 等于 root 的 height，也等于最深 leaf 的 depth。

!!! warning "height 和 depth 很容易混"
    depth 是从 root 往下数，height 是从当前节点往 leaf 数。

    所以 root 的 depth 是 0，但 root 的 height 通常不是 0；leaf 的 height 是 0，但 leaf 的 depth 通常不是 0。

## 2. 树的表示

### 2.1 List Representation

一种直观表示方法是把树写成嵌套列表。

例如：

```text
( A )
```

表示只有一个节点 `A`。

```text
( A ( B, C, D ) )
```

表示 `A` 有三个孩子：`B`、`C`、`D`。

再比如：

```text
( A ( B ( E, F ), C ( G ), D ( H, I, J ) ) )
```

表示：

1. `A` 的孩子是 `B, C, D`。
2. `B` 的孩子是 `E, F`。
3. `C` 的孩子是 `G`。
4. `D` 的孩子是 `H, I, J`。

![](附件/Pasted%20image%2020260623171436.png)
这种表示很适合给人看，但不适合直接拿来写结构体。

问题在于：每个节点的孩子数量不固定。

例如 `A` 有 3 个孩子，`C` 只有 1 个孩子，如果结构体里直接开孩子数组，那么每个节点需要的空间大小都不一样，这就很不舒服。

### 2.2 FirstChild-NextSibling Representation

更常用的表示法是 FirstChild-NextSibling。

每个节点只保存两个指针：

1. `FirstChild`：指向第一个孩子。
2. `NextSibling`：指向下一个兄弟。

```c
typedef struct TreeNode *PtrToNode;

struct TreeNode {
    ElementType Element;
    PtrToNode FirstChild;
    PtrToNode NextSibling;
};
```

这样，无论一个节点有多少个孩子，结构体大小都是固定的。

![](附件/Pasted%20image%2020260623171343.png)

!!! note "这种表示不唯一"
    在普通树中，children 的顺序通常不重要，所以同一棵树的孩子可以按不同顺序链接。

    因此 FirstChild-NextSibling representation 不是唯一的。

## 3. 二叉树（Binary Tree）

### 3.1 定义

二叉树是一种特殊的树：每个节点最多有两个孩子。

这两个孩子分别叫：

1. 左孩子（left child）。
2. 右孩子（right child）。

!!! warning "普通树和二叉树的区别"
    在普通树里，children 的顺序通常不重要。

    但在二叉树里，left child 和 right child 是不同的。把左孩子和右孩子交换后，一般会得到另一棵不同的二叉树。

### 3.2 从普通树到二叉树

FirstChild-NextSibling 表示法其实可以把普通树转成一棵二叉树。

对应关系是：

1. `FirstChild` 看成 left child。
2. `NextSibling` 看成 right child。

![](附件/Pasted%20image%2020260623171514.png)
### 3.3 Skewed Binary Trees

如果一棵二叉树几乎退化成一条链，就叫 skewed binary tree。

常见有两种：

1. **Skewed to the left**

    每个节点几乎都只有左孩子。

2. **Skewed to the right**

    每个节点几乎都只有右孩子。

这种树虽然名义上还是树，但很多操作的复杂度会退化成链表级别。
![](附件/Pasted%20image%2020260623175116.png)
### 3.4 Complete Binary Tree

完全二叉树（complete binary tree）的特点是：

1. 所有 leaf nodes 都在相邻的两层上。
2. 除最后一层外，其他层都是满的。
3. 最后一层的节点从左到右连续排列，中间不能有空洞。

这类树很适合用数组存储。

如果根节点存在 `tree[1]`：

```text
tree[i] 的左孩子  = tree[2i]
tree[i] 的右孩子  = tree[2i + 1]
tree[i] 的父节点  = tree[i / 2]
```

![](附件/Pasted%20image%2020260623175056.png)

!!! note "为什么堆喜欢用数组？"
    堆通常是一棵完全二叉树，所以不需要真的存指针。

    只要知道某个节点的数组下标，就能用公式算出它的 parent、left child 和 right child。

### 3.5 二叉树的性质

这里需要注意层数/深度的编号约定。课件中的 level 从 1 开始数。

1. 第 $i$ 层最多有：

    $$
    2^{i - 1}
    $$

    个节点，其中 $i \ge 1$。

2. 如果一棵二叉树有 $k$ 层，那么最多有：

    $$
    2^k - 1
    $$

    个节点。

3. 对任意非空二叉树，都有：

    $$
    n_0 = n_2 + 1
    $$

    其中 $n_0$ 是 leaf nodes 的数量，$n_2$ 是 degree 为 2 的节点数量。

??? proof "$n_0 = n_2 + 1$ 的证明"
    设：

    1. $n_0$ 是 degree 为 0 的节点数。
    2. $n_1$ 是 degree 为 1 的节点数。
    3. $n_2$ 是 degree 为 2 的节点数。
    4. $n$ 是总节点数。
    5. $B$ 是总边数。

    显然：

    $$
    n = n_0 + n_1 + n_2
    $$

    一棵有 $n$ 个节点的树有 $n - 1$ 条边，所以：

    $$
    B = n - 1
    $$

    另一方面，所有边都从 degree 为 1 或 degree 为 2 的节点出发，所以：

    $$
    B = n_1 + 2n_2
    $$

    因此：

    $$
    n - 1 = n_1 + 2n_2
    $$

    代入 $n = n_0 + n_1 + n_2$：

    $$
    n_0 + n_1 + n_2 - 1 = n_1 + 2n_2
    $$

    整理得到：

    $$
    n_0 = n_2 + 1
    $$

### 3.6 Expression Trees

表达式树（expression tree / syntax tree）用树来表示表达式。

它的特点是：

1. leaf nodes 是 operands，也就是操作数。
2. internal nodes 是 operators，也就是运算符。

例如表达式：

```text
A + B
```

可以表示为：

```text
    +
   / \
  A   B
```

课件给的复杂一点的例子是：

```text
(a + b) * (c * (d + e))
```

它的后缀表达式是：

```text
a b + c d e + * *
```

从后缀表达式构造表达式树的方法和后缀表达式求值很像：

1. 遇到 operand，就创建一个单节点树并压栈。
2. 遇到 operator，就从栈中弹出两棵树。
3. 先弹出的是右子树，后弹出的是左子树。
4. 创建一个以 operator 为根的新树，把两棵子树接上。
5. 把新树压回栈。
6. 扫描结束后，栈中唯一的树就是表达式树。

![](附件/Pasted%20image%2020260623171943.png)

!!! warning "左右子树顺序"
    构造表达式树时，遇到二元 operator 后先弹出的是右子树，再弹出的是左子树。

    这和后缀表达式求值里 `left op right` 的顺序是同一个坑。

### 3.7 Tree Traversals

树遍历（tree traversal）就是 visit each node exactly once，也就是每个节点恰好访问一次。

#### 3.7.1 普通树的 preorder

preorder 的顺序是：

```text
先root，再leftChild，最后rightChild
```

```c
void preorder(tree_ptr tree) {
    if (tree) {
        visit(tree);
        for (each child C of tree)
            preorder(C);
    }
}
```

#### 3.7.2 普通树的 postorder

postorder 的顺序是：

```text
先leftChild，再rightChild，最后root
```

```c
void postorder(tree_ptr tree) {
    if (tree) {
        for (each child C of tree)
            postorder(C);
        visit(tree);
    }
}
```

#### 3.7.3 普通树的 levelorder

levelorder 是按层访问，也就是从上到下、从左到右。

它通常用 queue 实现：

```c
void levelorder(tree_ptr tree) {
    enqueue(tree);
    while (queue is not empty) {
        visit(T = dequeue());
        for (each child C of T)
            enqueue(C);
    }
}
```

!!! note "为什么 levelorder 用 queue？"
    因为 queue 是 FIFO。

    先入队的是更靠上一层、更靠左的节点，所以它会先被访问；访问某个节点时，再把它的 children 放到队尾，正好保证一层一层往下走。

#### 3.7.4 二叉树的 inorder

二叉树除了 preorder、postorder，还多了 inorder。

```text
先leftChild，再root，最后RightChild
```

递归版本：

```c
void inorder(tree_ptr tree) {
    if (tree) {
        inorder(tree->Left);
        visit(tree->Element);
        inorder(tree->Right);
    }
}
```

迭代版本：

```c
void iter_inorder(tree_ptr tree) {
    Stack S = CreateStack(MAX_SIZE);
    for (;;) {
        for (; tree; tree = tree->Left)
            Push(tree, S);

        if (S is empty)
            break;

        tree = Top(S);
        Pop(S);
        visit(tree->Element);
        tree = tree->Right;
    }
}
```

![](附件/Pasted%20image%2020260623172537.png)

!!! note "迭代 inorder 的直觉"
    inorder 要先访问最左边的节点。

    所以我们一路沿着 `Left` 往下走，并把路上的节点压栈。走不下去之后，从栈顶弹出一个节点访问它，再转向它的右子树。

### 3.8 树遍历的应用

#### 3.8.1 打印目录

如果文件系统是一棵树，那么打印目录时可以用 preorder。

```c
static void ListDir(DirOrFile D, int Depth) {
    if (D is a legitimate entry) {
        PrintName(D, Depth);
        if (D is a directory)
            for (each child C of D)
                ListDir(C, Depth + 1);
    }
}
```

这里 `Depth` 控制缩进。深度为 $d_i$ 的文件，前面缩进 $d_i$ 个 tab。

但是 `Depth` 是递归内部变量，不应该暴露给用户，所以可以再包一层接口：

```c
void ListDirectory(DirOrFile D) {
    ListDir(D, 0);
}
```

#### 3.8.2 计算目录大小

如果要计算一个目录的总大小，可以用 postorder 的思想。

先计算每个子目录大小，再加到当前目录上：

```c
static int SizeDir(DirOrFile D) {
    int TotalSize = 0;

    if (D is a legitimate entry) {
        TotalSize = FileSize(D);
        if (D is a directory)
            for (each child C of D)
                TotalSize += SizeDir(C);
    }

    return TotalSize;
}
```

复杂度是：

$$
T(N) = O(N)
$$

因为每个文件或目录只处理一次。

### 3.9 Threaded Binary Trees

#### 3.9.1 为什么需要线索二叉树？

关键观察是：普通二叉树里有很多空指针。

对于一棵有 $n$ 个节点的二叉树：

1. 每个节点有两个指针域，所以一共有 $2n$ 个指针域。
2. 非空孩子指针对应树中的边，一共有 $n - 1$ 条边。
3. 所以空指针数量是：

    $$
    2n - (n - 1) = n + 1
    $$

也就是说，一棵二叉树会浪费 $n + 1$ 个空链接。

Threaded binary tree 的想法就是：不要让这些空指针白白空着，而是把它们改造成 threads，帮助遍历。

#### 3.9.2 Inorder threaded binary tree 的规则


Inorder线索二叉树的规则如下：

1. 如果 `Tree->Left` 是 `NULL`，就把它替换成指向 inorder predecessor 的指针。
2. 如果 `Tree->Right` 是 `NULL`，就把它替换成指向 inorder successor 的指针。
3. 不能有 loose threads，所以 threaded binary tree 必须有一个 head node。

为了区分“真孩子指针”和“线索指针”，节点里需要额外的标记位。

```c
typedef struct ThreadedTreeNode *PtrToThreadedNode;
typedef PtrToThreadedNode ThreadedTree;

struct ThreadedTreeNode {
    int LeftThread;        /* TRUE means Left is a thread */
    ThreadedTree Left;
    ElementType Element;
    int RightThread;       /* TRUE means Right is a thread */
    ThreadedTree Right;
};
```

#### 3.9.3 Head node 的作用

head node 的作用避免出现loose thread，也就是要使得这个线索树符合rule 3。

假设一棵树的中序序列是：

```
A  B  C  D
```

那么问题来了：

```
A 的中序前驱是谁？
```

没有。

因为 A 是第一个。

```
D 的中序后继是谁？
```

也没有。

因为 D 是最后一个。


所以如果只按照 Rule 1 和 Rule 2，会出现这种情况：

```
A 的左线索不知道指向谁D 的右线索不知道指向谁
```

这样就发生了loose thread（松散/悬空的线索）



为了解决这个问题，我们需要引入头节点（head node）

# 头结点的作用

头结点相当于一个哨兵结点。

它不是普通数据结点，而是专门用来处理边界情况的。

原来：

```
第一个结点没有前驱最后一个结点没有后继
```

现在可以规定：

```
第一个结点的左线索指向 head最后一个结点的右线索指向 head
```

这样就不会有loose thread了。

假设中序序列是：

```
A  B  C  D
```

没有 head 的时候：

```
A 的前驱：没有D 的后继：没有
```

有 head 之后：

```
A 的前驱：headD 的后继：head
```

于是所有线索都有指向目标。

# 为什么要这样做？

因为这样遍历的时候更方便。

比如中序线索二叉树可以沿着线索一直找后继：

```
A -> B -> C -> D
```

走到 D 之后，D 的右线索指向 head。

一看到回到 head，就知道：

```
遍历结束了
```

如果没有 head，D 的右线索可能是 NULL，处理起来就要额外判断。

## 4. Binary Search Trees

### 4.1 BST 的定义

二叉搜索树（binary search tree, BST）是一棵二叉树。

它可以是空树；如果非空，那么它满足：

1. 每个节点都有一个 key，默认 key 是整数。
2. 所有 key 互不相同。
3. 左子树中所有 key 都小于 root 的 key。
4. 右子树中所有 key 都大于 root 的 key。
5. 左子树和右子树本身也都是 BST。

![](附件/Pasted%20image%2020260623175535.png)

!!! note "BST 为什么好用？"
    BST 把“大小关系”直接编码进树结构里。

    所以查找一个元素时，不需要两边都找：小了就去左边，大了就去右边。

### 4.2 BST ADT

二叉搜索树的Operation包括但不限于：

1. `SearchTree MakeEmpty(SearchTree T);`
2. `Position Find(ElementType X, SearchTree T);`
3. `Position FindMin(SearchTree T);`
4. `Position FindMax(SearchTree T);`
5. `SearchTree Insert(ElementType X, SearchTree T);`
6. `SearchTree Delete(ElementType X, SearchTree T);`
7. `ElementType Retrieve(Position P);`

### 4.3 Find

查找 `X` 时，从 root 开始：

1. 如果当前树为空，说明没找到。
2. 如果 `X < T->Element`，去左子树找。
3. 如果 `X > T->Element`，去右子树找。
4. 如果相等，返回当前节点。

递归版本：

```c
Position Find(ElementType X, SearchTree T) {
    if (T == NULL)
        return NULL;

    if (X < T->Element)
        return Find(X, T->Left);
    else if (X > T->Element)
        return Find(X, T->Right);
    else
        return T;
}
```

迭代版本：

```c
Position Iter_Find(ElementType X, SearchTree T) {
    while (T) {
        if (X == T->Element)
            return T;
        if (X < T->Element)
            T = T->Left;
        else
            T = T->Right;
    }
    return NULL;
}
```

如果目标节点深度为 $d$，那么：

$$
T(N) = O(d)
$$

最坏情况下，$d$ 接近树高 $h$。

### 4.4 FindMin 与 FindMax

BST 的最小值一定在最左边，因为越往左 key 越小。

```c
Position FindMin(SearchTree T) {
    if (T == NULL)
        return NULL;
    else if (T->Left == NULL)
        return T;
    else
        return FindMin(T->Left);
}
```

BST 的最大值一定在最右边，因为越往右 key 越大。

```c
Position FindMax(SearchTree T) {
    if (T != NULL)
        while (T->Right != NULL)
            T = T->Right;
    return T;
}
```

它们的复杂度都是：

$$
O(d)
$$

其中 $d$ 是从 root 走到最小/最大节点的路径长度。

### 4.5 Insert

插入的思路其实就是先查找。

从 root 出发：

1. 如果 `X < T->Element`，往左子树插。
2. 如果 `X > T->Element`，往右子树插。
3. 如果走到空树，就在这里创建新节点。
4. 如果遇到相同 key，课件代码选择什么也不做。

```c
SearchTree Insert(ElementType X, SearchTree T) {
    if (T == NULL) {
        T = malloc(sizeof(struct TreeNode));
        if (T == NULL)
            FatalError("Out of space!!!");
        else {
            T->Element = X;
            T->Left = T->Right = NULL;
        }
    } else if (X < T->Element) {
        T->Left = Insert(X, T->Left);
    } else if (X > T->Element) {
        T->Right = Insert(X, T->Right);
    }

    return T;
}
```

!!! warning "不要忘记 `return T`"
    插入代码最后必须返回 `T`。

    因为递归插入时，父节点会用返回值重新接住自己的 left 或 right 子树。

### 4.6 重复 key 怎么办？

常见做法有：

1. 直接忽略重复 key。
2. 在节点中增加 `count` 字段，重复插入时只让 `count++`。
3. 规定重复 key 放在左边或右边，但这样会让树更容易偏斜。
4. 节点中挂一个 list，保存相同 key 对应的多个元素。

### 4.7 Delete

BST 删除分三种情况。

#### 4.7.1 删除 leaf node

leaf node 没有孩子，直接把 parent 指向它的链接改成 `NULL` 即可。

#### 4.7.2 删除 degree 1 node

degree 为 1 的节点只有一个孩子。

删除时，用它唯一的 child 取代它。

```text
parent -> node -> child

变成：

parent -> child
```

#### 4.7.3 删除 degree 2 node

degree 为 2 的节点最麻烦，因为它左右孩子都有，不能直接拿某个孩子顶上来。

两种替换方法：

1. 用左子树中的最大节点替换它。
2. 用右子树中的最小节点替换它。

为什么这样可以？

1. 左子树最大值仍然小于原节点右子树中的所有值。
2. 右子树最小值仍然大于原节点左子树中的所有值。
3. 这两个候选节点本身至多只有一个孩子，所以接下来删除候选节点会变成 leaf / degree 1 的简单情况。



### 4.8 Delete 代码

以“右子树最小值”作为替代节点为例。


```c
SearchTree Delete(ElementType X, SearchTree T) {
    Position TmpCell;

    if (T == NULL)
        Error("Element not found");
    else if (X < T->Element)
        T->Left = Delete(X, T->Left);
    else if (X > T->Element)
        T->Right = Delete(X, T->Right);
    else if (T->Left && T->Right) {
        TmpCell = FindMin(T->Right);
        T->Element = TmpCell->Element;
        T->Right = Delete(T->Element, T->Right);
    } else {
        TmpCell = T;
        if (T->Left == NULL)
            T = T->Right;
        else
            T = T->Left;
        free(TmpCell);
       }
    return T;
}
```

删除、查找、插入的复杂度都和树高有关：

$$
T(N) = O(h)
$$

### 4.9 Lazy deletion

如果删除操作不多，可以用 lazy deletion。

做法是在每个节点里加一个 flag：

1. active：这个节点目前有效。
2. deleted：这个节点已经被逻辑删除。

删除时不真的 `free` 这个节点，只把 flag 标记为 deleted。

这样做的好处是：

1. 删除操作很简单，不需要处理复杂的节点重接。
2. 如果同一个 key 之后又插入回来，可以直接把 flag 改回 active，不需要重新 `malloc`。

问题是：如果 deleted nodes 越来越多，查找时可能经过很多已经删除的节点，这会严重影响效率。如果 deleted nodes 的数量已经接近 active nodes，那么树里有大量节点对当前数据集没有贡献，但查找路径仍然可能经过它们。这时就应该考虑重建树，或者真的删除节点。

### 4.10 平均情况与插入顺序

BST 的高度取决于插入顺序。

对同一组元素：

```text
1, 2, 3, 4, 5, 6, 7
```

如果按下面顺序插入：

```text
4, 2, 1, 3, 6, 5, 7
```

会得到比较平衡的 BST，高度为 2。

但如果按升序插入：

```text
1, 2, 3, 4, 5, 6, 7
```

BST 会退化成一条向右的链，高度为 6。

    BST 的操作看起来都是 $O(h)$。

    所以后面才会需要 AVL tree、Red-Black tree 这类自平衡搜索树。

## 5. 线段树（Segment Tree）

### 5.1 动机

给定一个数组 `A[0...N-1]`，如果我们需要频繁计算任意区间 `[L, R]` 的和，最直接的暴力做法是每次从 `L` 扫到 `R`：

```c
ElementType Query(ElementType A[], int L, int R) {
    ElementType sum = 0;
    for (int i = L; i <= R; ++i)
        sum += A[i];
    return sum;
}
```

一次查询的时间复杂度是：

$$
T(N) = O(N)
$$

如果只是偶尔查询一次，这没什么问题；但如果区间查询是一个频繁操作，每次都线性扫描就太慢了。

线段树可以在 $O(\log N)$ 内完成**区间查询**和**单点更新**。

### 5.2 结构

线段树把一个大区间不断拆成左右两个子区间，直到每个叶子节点只对应数组中的一个元素。

以数组为例：

```text
A = [7, 2, 5, 8, 3]
```

![](附件/Pasted%20image%2020260629155805.png)

线段树的每个节点负责一个区间 `[start, end]`：

1. 根节点负责整个区间 `[0, N-1]`。
2. 如果当前节点负责 `[start, end]`，则令 `mid = (start + end) / 2`。
3. 左儿子负责 `[start, mid]`。
4. 右儿子负责 `[mid + 1, end]`。
5. 当 `start == end` 时，这个节点就是叶子节点，对应数组中的单个元素。

!!! note "区间本身通常不存进 tree 数组"
    stored value 和 not stored, but computed on the fly。

    真正存在 `tree[node]` 里的通常只有这个区间的聚合值，比如区间和。至于当前节点对应哪个区间 `[start, end]`，是递归函数参数传下来的，不一定真的存进节点里。

### 5.3 数组存储

线段树逻辑上是一棵满二叉树，所以很适合用数组存储。通常让根节点放在 `tree[1]`：

```text
tree[node] 的左儿子 = tree[2 * node]
tree[node] 的右儿子 = tree[2 * node + 1]
```

对于上面的例子，存储关系大致是：

```text
tree[1] = 25   // [0,4]
tree[2] = 14   // [0,2]
tree[3] = 11   // [3,4]
tree[4] = 9    // [0,1]
tree[5] = 5    // [2,2]
tree[6] = 8    // [3,3]
tree[7] = 3    // [4,4]
tree[8] = 7    // [0,0]
tree[9] = 2    // [1,1]
```

空间复杂度是：

$$
S(N) = O(N)
$$

实际写代码时经常直接开 `4 * N` 大小的数组：

```c
int tree[4 * MAXN];
```

这是因为当 $N$ 不是 2 的幂时，数组下标可能会出现一些空洞。开 `4N` 虽然不是最紧，但足够安全，也最省心。

### 5.4 建树

从根节点开始，递归地分割区间，到叶子节点时赋值为 `A[start]`，回溯时合并两个儿子的值。

```c
void Build(int node, int start, int end) {
    // Base Case: Leaf Node
    if (start == end) {
        tree[node] = A[start];
        return;
    }

    // Recursive Step: Split and Build Children
    int mid = (start + end) / 2;
    Build(2 * node, start, mid);
    Build(2 * node + 1, mid + 1, end);

    // Merge Logic: Sum of children
    tree[node] = tree[2 * node] + tree[2 * node + 1];
}
```

调用时从根节点开始：

```c
Build(1, 0, N - 1);
```

建树会访问每个线段树节点一次，所以时间复杂度是：

$$
T(N) = O(N)
$$

不过建树通常只在最开始跑一次。

!!! question "为什么 Build 的返回值是 void？"
    因为线段树用**数组存储**，根节点永远在 `tree[1]`。子节点位置由索引自动算出（`2*node` 和 `2*node+1`），不需要返回任何东西。这和指针实现的树不同——指针需要返回新节点地址才能"挂"上去，数组的索引本身就是"天然指针"。

### 5.5 区间查询

查询区间 `[L, R]` 时，从根节点往下走，有三种情况：

1. **No Overlap：完全无交集。**

    当前节点区间 `[start, end]` 完全在查询区间 `[L, R]` 外面，即 `R < start || end < L`。这个节点对答案没有贡献，返回 0。

2. **Total Overlap：完全包含。**

    当前节点区间 `[start, end]` 完全落在查询区间 `[L, R]` 里面，即 `L <= start && end <= R`。这时可以直接返回 `tree[node]`，不用继续往下递归。

3. **Partial Overlap：部分重叠。**

    当前节点区间和查询区间有交集，但没有完全包含。此时递归查询左右儿子，再把左右结果合并。

```c
int Query(int node, int start, int end, int L, int R) {
    // Case 1: No Overlap
    if (R < start || end < L) return 0;

    // Case 2: Total Overlap
    if (L <= start && end <= R) return tree[node];

    // Case 3: Partial Overlap
    int mid = (start + end) / 2;
    int left_sum = Query(2 * node, start, mid, L, R);
    int right_sum = Query(2 * node + 1, mid + 1, end, L, R);
    return left_sum + right_sum;
}
```

调用方式：

```c
Query(1, 0, N - 1, L, R);
```

!!! example "查询 `[2,4]` 的执行过程"
    仍然用数组：

    ```text
    A = [7, 2, 5, 8, 3]
    ```

    查询 `[2,4]`，也就是要求 `A[2] + A[3] + A[4]`。

    从根节点 `[0,4]` 开始：

    1. `[0,4]` 和 `[2,4]` 是 Partial Overlap，所以继续看左右儿子。
    2. 左儿子 `[0,2]` 和 `[2,4]` 也是 Partial Overlap，继续往下。
    3. `[0,1]` 和 `[2,4]` 是 No Overlap，返回 0。
    4. `[2,2]` 被 `[2,4]` Total Overlap，直接返回 `tree[node] = 5`。
    5. 右儿子 `[3,4]` 被 `[2,4]` Total Overlap，直接返回 `tree[node] = 11`。

    合并结果：

    $$
    0 + 5 + 11 = 16
    $$

    所以 `Query(2, 4)` 的答案是 16。

区间查询的时间复杂度是：

$$
T(N) = O(\log N)
$$

!!! question "为什么每一层最多用到 4 个元素？"
    任意查询区间 `[L, R]` 在线段树上分解时，每一层最多只有**4 个节点被访问**：2 个在左边界附近的部分重叠节点 + 2 个在右边界附近的部分重叠节点。中间的全包含节点直接返回，不用往下递归。所以每层工作量是常数，总层数 $\log N$，总体 $O(\log N)$。

### 5.6 单点更新

将 `A[idx]` 更新为 `val`：从根节点找到对应的叶子节点，更新后回溯时重新计算每个祖先节点的值。

```c
void Update(int node, int start, int end, int idx, int val) {
    // Base Case: Leaf Node found
    if (start == end) {
        tree[node] = val;
        return;
    }

    // Recursive Step: Go left or right
    int mid = (start + end) / 2;
    if (start <= idx && idx <= mid)
        Update(2 * node, start, mid, idx, val);
    else
        Update(2 * node + 1, mid + 1, end, idx, val);

    // Backtracking Step
    tree[node] = tree[2 * node] + tree[2 * node + 1];
}
```

调用方式：

```c
Update(1, 0, N - 1, idx, val);
```

!!! example "把 `A[3]` 更新为 9"
    原数组是：

    ```text
    A = [7, 2, 5, 8, 3]
    ```

    原来 `A[3] = 8`，现在执行：

    ```c
    Update(1, 0, 4, 3, 9);
    ```

    查找路径如下：

    1. 根节点 `[0,4]` 包含 index 3，继续往下。
    2. `mid = 2`，index 3 在右儿子 `[3,4]` 中。
    3. `[3,4]` 的 `mid = 3`，index 3 在左儿子 `[3,3]` 中。
    4. 到达叶子 `[3,3]`，把值从 8 改成 9。

    然后开始回溯更新祖先：

    1. `[3,3]` 从 8 变成 9。
    2. `[3,4]` 从 `8 + 3 = 11` 变成 `9 + 3 = 12`。
    3. `[0,4]` 从 `14 + 11 = 25` 变成 `14 + 12 = 26`。

    没有经过的节点不需要动，比如 `[0,2]`、`[0,1]`、`[2,2]` 等。

单点更新的时间复杂度是：

$$
T(N) = O(\log N)
$$

### 5.7 注意事项

1. 线段树不只可以维护区间和，也可以维护 `min`、`max`、`gcd`、`xor` 等区间聚合信息。
2. 核心要求是聚合操作可以由左右子区间的答案合并得到。求平均值也可以做，但通常要维护区间和与区间长度，再计算平均值，而不是只存一个 average 就随便合并。
3. 对于区间更新，例如给 `[2,1000]` 中所有元素都加 10，普通单点更新会太慢。这类问题通常要使用 lazy propagation（延迟标记），PPT 中把它作为自学内容。
