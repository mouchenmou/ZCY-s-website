## 1. 优先队列 ADT

### 1.1 什么是优先队列

普通队列是 FIFO（先进先出），**优先队列**是优先级最高的先出。

支持的操作：

- `Initialize(MaxElements)` — 创建一个容量为 `MaxElements` 的优先队列
- `Insert` — 插入一个元素
- `DeleteMin` — 删除并返回最小元素（如果是最大堆则是 `DeleteMax`）
- `FindMin` — 查看最小元素（不删除）

!!! note "最高优先级不一定是最大值"
     `DeleteMin` 是 delete the element with the highest priority。

    这是因为在最小堆里，我们把 key 越小理解为优先级越高；如果使用最大堆，那么对应操作就是 `DeleteMax`。

### 1.2 简单实现对比

| 实现方式    | Insert            | DeleteMin               | 性质             |
| ------- | ----------------- | ----------------------- | -------------- |
| 无序数组    | $\Theta(1)$（加到末尾） | $\Theta(N)$（扫描找最小 + 移位） | 简单粗暴           |
| 无序链表    | $\Theta(1)$（插到头部） | $\Theta(N)$（扫描找最小）      | 删除只需 $O(1)$ 移除 |
| 有序数组    | $O(N)$（找位置 + 移位）  | $\Theta(1)$（删第一个/最后一个）  | 插入慢            |
| 有序链表    | $O(N)$（找位置）       | $\Theta(1)$（删第一个/最后一个）  | 插入慢            |
| **二叉堆** | **$O(\log N)$**   | **$O(\log N)$**         | ✅ 最优           |

!!! tip "为什么不用 BST/AVL 树？"
    AVL 树 Insert 和 Delete 都是 $O(\log N)$，理论上也可以做优先队列。但：

    - 优先队列**永远只删除最小元素**，不需要 BST 的全部搜索能力
    - 堆没有指针开销，常数因子更小
    - 堆天然是完全二叉树 → 数组存储 → Cache 友好

## 2. 二叉堆的结构性质

### 2.1 完全二叉树

!!! conception "完全二叉树（Complete Binary Tree）"
    一棵 $n$ 个节点、高度为 $h$ 的二叉树，如果它的节点和**高度为 $h$ 的完美二叉树**中编号 $1 \sim n$ 的节点一一对应，则它是完全二叉树。

    简单理解：**从上到下、从左到右**逐个填满，中间不能有空位。

高度为 $h$ 的完全二叉树：

$$
2^h \le N \le 2^{h+1}-1 \quad\Rightarrow\quad h = \lfloor \log N \rfloor
$$

### 2.2 数组表示

完全二叉树可以用**数组**存储，不需要指针——这就是堆最大的优势。

!!! example "数组与树的对应"
    我们选择浪费掉`Key[0]`这个节点，从数组的下标为1开始存储元素，这样子表示父节点和左右儿子会一目了然。
    ![](附件/Pasted%20image%2020260602221410.png)

!!! theorem "完全二叉树的顺序存储下标关系"
    如果一棵有 $n$ 个节点的完全二叉树按层序顺序存储，那么对于任意下标 $i$，其中 $1 \le i \le n$，有：

    $$
    parent(i) =
    \begin{cases}
    \lfloor i/2 \rfloor, & i \ne 1 \\
    \text{None}, & i = 1
    \end{cases}
    $$

    $$
    left\_child(i) =
    \begin{cases}
    2i, & 2i \le n \\
    \text{None}, & 2i > n
    \end{cases}
    $$

    $$
    right\_child(i) =
    \begin{cases}
    2i + 1, & 2i + 1 \le n \\
    \text{None}, & 2i + 1 > n
    \end{cases}
    $$

    直觉上就是：按层序编号时，编号为 $i$ 的节点下面最多挂两个位置，分别是 $2i$ 和 $2i+1$；如果这些位置超过了当前节点总数 $n$，说明对应孩子不存在。

!!! warning "注意"
    数组下标从 **1** 开始，`BT[0]` 留作哨兵（sentinel）。

### 2.3 堆的结构体和初始化

二叉堆用一个结构体保存容量、当前大小和数组：

```c
struct HeapStruct {
    int Capacity;
    int Size;
    ElementType *Elements;
};
```

初始化时要做三件事：

1. 检查 `MaxElements` 是否太小。
2. 给堆结构体和数组分配空间。
3. 设置 `Elements[0]` 为哨兵 `MinData`。

```c
PriorityQueue Initialize(int MaxElements) {
    PriorityQueue H;

    if (MaxElements < MinPQSize)
        return Error("Priority queue size is too small");

    H = malloc(sizeof(struct HeapStruct));
    if (H == NULL)
        return FatalError("Out of space!!!");

    H->Elements = malloc((MaxElements + 1) * sizeof(ElementType));
    if (H->Elements == NULL)
        return FatalError("Out of space!!!");

    H->Capacity = MaxElements;
    H->Size = 0;
    H->Elements[0] = MinData;

    return H;
}
```

!!! note "为什么数组大小是 `MaxElements + 1`？"
    因为 `Elements[0]` 不存正常元素，而是作为 sentinel。

    真正的堆元素从 `Elements[1]` 开始，所以如果堆最多存 `MaxElements` 个元素，数组就要开到 `MaxElements + 1`。

## 3. 堆序性质

!!! conception "最小堆（Min Heap）"
    每个节点的值**不大于**其所有子节点的值。根就是全堆最小的元素。
    
    反过来，**最大堆（Max Heap）**：每个节点**不小于**子节点，根是最大的。

![](附件/Pasted%20image%2020260623193908.png)
!!! tip "应用选择"

    - 需要每次取**最小** → 最小堆（如 Dijkstra）
    - 需要每次取**最大** → 最大堆（如 Heapsort）

## 4. 基本操作

### 4.1 插入（Insert）— 上滤（Percolate Up）

**思路：** 新元素先放到**最后**（维持完全二叉树结构），然后**一路向上**跟父节点比较，比父节点小就交换，直到找到合适位置。


```c
/* H->Elements[0] 是哨兵，值 ≤ 堆中所有元素 */
void Insert(ElementType X, PriorityQueue H) {
    int i;
    if (IsFull(H)) {
        Error("Priority queue is full");
        return;
    }
    for (i = ++H->Size; H->Elements[i / 2] > X; i /= 2)
        H->Elements[i] = H->Elements[i / 2];  /* 父节点下沉 */
    H->Elements[i] = X;                        /* 放入 X */
}
```

- 哨兵 `H->Elements[0]` 放置 ≤ 最小元素的值——保证循环一定会停下来。
- 时间复杂度：$O(\log N)$


### 4.2 删除最小（DeleteMin）— 下滤（Percolate Down）

**思路：**

1. 取出根节点（最小元素）
2. 把**最后一个元素**拎到根的位置
3. 一路向下跟**较小的儿子**比较，比儿子大就交换


```c
ElementType DeleteMin(PriorityQueue H) {
    int i, Child;
    ElementType MinElement, LastElement;
    if (IsEmpty(H)) {
        Error("Priority queue is empty");
        return H->Elements[0];
    }
    MinElement = H->Elements[1];              /* 保存最小值 */
    LastElement = H->Elements[H->Size--];     /* 取最后一个元素 */
    for (i = 1; i * 2 <= H->Size; i = Child) {
        Child = i * 2;                        /* 左儿子 */
        if (Child != H->Size
            && H->Elements[Child + 1] < H->Elements[Child])
            Child++;                          /* 右儿子更小，选它 */
        if (LastElement > H->Elements[Child])
            H->Elements[i] = H->Elements[Child]; /* 儿子上浮 */
        else
            break;                            /* 找到合适位置 */
    }
    H->Elements[i] = LastElement;
    return MinElement;
}
```

- 时间复杂度：$O(\log N)$

!!! question "`Child != H->Size` 这个条件能不能省？"
    ```c
    if (Child != H->Size
        && H->Elements[Child + 1] < H->Elements[Child])
        Child++;
    ```

    这里 `Child` 一开始是左儿子。如果 `Child == H->Size`，说明当前节点只有左儿子，没有右儿子。

    如果省掉 `Child != H->Size`，代码就会访问 `H->Elements[Child + 1]`，也就是访问一个不存在的右儿子。

### 4.3 其他操作

| 操作 | 方法 | 复杂度 |
|------|------|--------|
| DecreaseKey(P, Δ) | 降低位置 P 的值，然后**上滤** | $O(\log N)$ |
| IncreaseKey(P, Δ) | 增大位置 P 的值，然后**下滤** | $O(\log N)$ |
| Delete(P) | DecreaseKey(P, ∞) + DeleteMin | $O(\log N)$ |

!!! warning "堆不擅长查找任意元素"
    除了 `FindMin` 可以 $O(1)$ 看根节点，堆里找任意 key 通常要线性扫描整个数组。

    因为堆序只保证 parent 和 child 的局部大小关系，并不保证左子树所有元素都小于右子树，或者整棵树按中序有序。

## 5. 建堆（BuildHeap）— 重点

!!! question "为什么需要 BuildHeap？"
    一个一个 Insert 建堆需要 $O(N\log N)$。有没有更快的方法？有——**$O(N)$ 建堆**。

### 5.1 核心思路

给定一个无序数组，我们**直接把它当成一棵完全二叉树**（不满足堆序），然后从最后一个非叶节点开始，**逐个向下过滤（PercolateDown）**，最终整棵树满足堆序。

### 5.2 怎么找第一个非叶节点？

**最后一个非叶子节点 = 最后一个节点的父节点。**

最后一个节点的下标是 $N$，它的父节点下标是：

$$
\text{第一个非叶节点} = \lfloor N / 2 \rfloor
$$

!!! example "例子：$N=15$"
    最后一个节点编号 = 15，它的父节点 = $\lfloor 15/2 \rfloor = 7$。
    
    所以从**编号 7 开始**，依次对 7, 6, 5, 4, 3, 2, 1 做 PercolateDown。
    
    编号 8~15 都是叶子节点——叶子不需要下沉。

### 5.3 完整示例

```

         80          40
       /    \       /    \

    /  \   /  \   /  \   /  \

N=15，第一个非叶节点 = 7，依次处理 7,6,5,4,3,2,1。
```

### 5.4 为什么是 $O(N)$？

!!! abstract "定理"
    对于高度为 $h$、包含 $2^{h+1}-1$ 个节点的完美二叉树，所有节点的高度之和为 $2^{h+1} - 1 - (h+1)$。

**直观理解：** 大部分节点都在底层（叶节点），下沉距离很短；只有少数节点在高层，下沉距离长。

建堆的总时间 = 每个节点的下沉距离之和 $\propto N$，所以复杂度为 $O(N)$。

??? proof "BuildHeap 为什么是线性时间"
    对一个节点做 `PercolateDown`，最坏移动距离等于这个节点的高度。

    所以 `BuildHeap` 的总代价可以用“所有节点高度之和”来估计。

    对高度为 $h$ 的完美二叉树：

    - 高度为 $0$ 的节点有 $2^h$ 个；
    - 高度为 $1$ 的节点有 $2^{h-1}$ 个；
    - 高度为 $2$ 的节点有 $2^{h-2}$ 个；
    - ...
    - 高度为 $h$ 的节点有 $1$ 个。

    因此所有节点高度之和为：

    $$
    \sum_{i=0}^{h} i \cdot 2^{h-i}
    $$

    令 $j = h - i$，也可以写成：

    $$
    \sum_{j=0}^{h} (h-j)2^j
    $$

    这个和的结果是：

    $$
    2^{h+1} - 1 - (h+1)
    $$

    而完美二叉树的节点数是：

    $$
    N = 2^{h+1} - 1
    $$

    所以高度之和是：

    $$
    N - (h+1)
    $$

    因此：

    $$
    T(N) = O(N)
    $$

    对一般完全二叉树来说，节点数只会更少，总代价也不会超过同高度完美二叉树的量级，所以 `BuildHeap` 仍然是 $O(N)$。

!!! tip "跟逐个 Insert 对比"

    | 方法 | 复杂度 |
    |------|--------|
    | 逐个 Insert | $O(N\log N)$ |
    | BuildHeap（一次性） | $O(N)$ |

## 6. d-堆

所有节点有 $d$ 个儿子的堆。

- **好处：** 树更矮 → 插入时上浮距离更短
- **坏处：** DeleteMin 需要 $d-1$ 次比较来找最小儿子 → $O(d\log_d N)$
- **适用场景：** 优先队列太大、主存放不下时（例如外部排序）

### 6.1 d-堆的下标关系

如果仍然从下标 1 开始存储，那么第 $i$ 个节点的 $d$ 个儿子可以写成：

$$
d(i - 1) + 2,\ d(i - 1) + 3,\ \cdots,\ d(i - 1) + d + 1
$$

父节点下标是：

$$
\left\lfloor \frac{i - 2}{d} \right\rfloor + 1
$$

例如 $d = 3$ 时，节点 1 的孩子是 2, 3, 4；节点 2 的孩子是 5, 6, 7。

### 6.2 d 是不是越大越好？

不一定。

`d` 变大后，树高会变小：

$$
O(\log_d N)
$$

所以 `Insert` 的上滤路径会变短。

但是 `DeleteMin` 每下一层之前，都要在 $d$ 个孩子里找最小的那个，需要 $d - 1$ 次比较。

所以：

$$
\text{DeleteMin} = O(d \log_d N)
$$

而且课件还提醒：二叉堆里的 `*2` 和 `/2` 可以用 bit shift 很快完成，但一般的 `*d` 和 `/d` 不一定有这个优势。

因此 `d` 不是越大越好，而是要看应用场景。

## 7. 优先队列的应用

!!! example "第 $k$ 大元素"
    给 $N$ 个元素，找第 $k$ 大的。

    1. **排序**

        先整体排序，再取第 $k$ 大。

        复杂度：

        $$
        O(N \log N)
        $$

    2. **建最大堆，然后删 $k$ 次**

        先 `BuildHeap` 建一个最大堆，再连续执行 $k$ 次 `DeleteMax`。

        复杂度：

        $$
        O(N + k \log N)
        $$

    3. **维护大小为 $k$ 的最小堆**

        先把前 $k$ 个元素建成一个最小堆。之后扫描剩余元素：

        - 如果当前元素不大于堆顶，忽略。
        - 如果当前元素大于堆顶，删除堆顶并插入当前元素。

        扫描结束后，堆顶就是第 $k$ 大。

        复杂度：

        $$
        O(N \log k)
        $$

    第三种方法在 $k \ll N$ 时尤其有用。
