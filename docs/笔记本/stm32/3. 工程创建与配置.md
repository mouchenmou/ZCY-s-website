C 语言里面有一种东西叫 **预处理指令**，是在真正编译代码之前执行的。

最常见的就是：

```
#define ABC 123
```

意思是：

> 在编译之前，把代码里面所有的 ABC 替换成 123。

例如：

```
#define MAX 100

int a[MAX];
```

编译之前会变成：

```
int a[100];
```

这个过程叫**宏展开（Macro Expansion）**

---

还有一种更常见：

```
#define USE_LED
```

注意：

后面没有值。

它的意思不是定义一个变量，而是：

> 我声明一个标记：USE_LED存在。

类似于：

```
有这个标签
```

## 2. 那 STM32 为什么需要宏？


```
Define: USE_STDPERIPH_DRIVER
```

这个东西是 STM32 标准库里面用的。

我们打开 STM32 的头文件，例如：

```
stm32f10x.h
```

里面有类似：

```
#ifdef USE_STDPERIPH_DRIVER

#include "stm32f10x_gpio.h"
#include "stm32f10x_rcc.h"

#endif
```

什么意思？

### 情况1：

你定义了：

```
USE_STDPERIPH_DRIVER
```

那么：

```
#ifdef USE_STDPERIPH_DRIVER
```

成立。

于是：

```
#include "stm32f10x_gpio.h"
#include "stm32f10x_rcc.h"
```

会被执行。

也就是说：

> 我要使用 STM32 官方标准外设库。

---

### 情况2：

你没有定义：

```
USE_STDPERIPH_DRIVER
```

那么：

```
#ifdef USE_STDPERIPH_DRIVER
```

不成立。

于是：

```
#include "stm32f10x_gpio.h"
```

不会加入。

---

所以这个宏本质上是一个**开关**。

类似：

```
#define USE_STDPERIPH_DRIVER

打开STM32标准库功能
```

## 3. 为什么不直接写在代码里面？

比如：

```
#define USE_STDPERIPH_DRIVER
```

放在 main.c 第一行不行吗？

可以。

例如：

```
#define USE_STDPERIPH_DRIVER

#include "stm32f10x.h"

int main()
{

}
```

也可以工作。

但是工程大了以后：

比如：

```
main.c
led.c
key.c
usart.c
delay.c
```

每个文件都写：

```
#define USE_STDPERIPH_DRIVER
```

很麻烦。

所以 Keil 提供：

```
Options for Target
        ↓
C/C++
        ↓
Define
```

统一添加。

等价于：

你在每个文件最前面写：

```
#define USE_STDPERIPH_DRIVER
```

# 4. Include Path 是什么？

这个更重要。

我之前遇到过：

```
cannot open source input file "led.h"
```

就是因为这个。

假设你的工程：

```
Project

├── main.c

├── HARDWARE
│
└── LED
    |
    ├── led.c
    └── led.h
```

你的 main.c：

```
#include "led.h"
```

编译器看到：

```
我要找 led.h
```

它去哪找？

默认：

先找：

```
main.c所在目录
```

发现：

没有：

```
led.h
```

于是报错：

```
cannot open source input file
```

---

所以你告诉编译器：

> 以后找头文件，也去这里看看。

比如：

Include Path:

```
..\HARDWARE\LED
```

那么：

编译器搜索：

```
main.c目录
+
..\HARDWARE\LED
```

于是找到：

```
led.h
```

### 第二个：

```
..\USER
```


## 6. 一个完整流程

比如你写：

```
#include "stm32f10x.h"

int main()
{

}
```

编译过程：

### 第一步：找文件

编译器：

```
我要找 stm32f10x.h
```

搜索：

```
当前目录
↓
..\Libraries\STM32F10x_StdPeriph_Driver\inc
↓
..\USER
```

找到：

```
stm32f10x.h
```

---

### 第二步：看里面

发现：

```
#ifdef USE_STDPERIPH_DRIVER
#include "stm32f10x_gpio.h"
#endif
```

于是检查：

有没有：

```
USE_STDPERIPH_DRIVER
```

---

你的 Keil 里面有：

```
Define:
USE_STDPERIPH_DRIVER
```

所以：

继续包含：

```
stm32f10x_gpio.h
```

## 7. 可以这样理解

| 东西           | 作用            |
| ------------ | ------------- |
| #define      | 定义一个开关/替换文字   |
| Define选项     | 告诉编译器提前定义这些宏  |
| Include Path | 告诉编译器去哪里找.h文件 |
| .h文件         | 声明函数、变量、寄存器   |
| .c文件         | 真正实现函数        |

---

对于 STM32 标准库工程：

通常固定有：

```
Define:

USE_STDPERIPH_DRIVER


Include Path:

..\Libraries\STM32F10x_StdPeriph_Driver\inc
..\USER
```

这是模板工程里面常见配置。

你之前那个 `LED_Init undefined symbol` 错误，其实就是另一类问题：

- `led.h找不到` → Include Path问题
- `LED_Init找不到实现` → led.c没有加入工程或者函数没编译进去

这两个刚好对应今天讲的两个东西。你现在学 STM32 的话，**宏 + 头文件路径 + 工程文件管理** 是必须先搞懂的。你后面学 GPIO、RCC 的时候还会大量遇到 `#ifdef` 这种东西。
