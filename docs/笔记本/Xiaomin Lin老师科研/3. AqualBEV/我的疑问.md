### 1. Introduction

### 1.1 什么是 monocular depth estimation

### 解析：
**只用一张普通相机拍到的图，去估计图里每个位置距离相机有多远。**

这里：

- `monocular` = 单目，也就是**只有一个摄像头**
- `depth` = 深度，表示某个点离相机有多远
- `estimation` = 估计

所以中文一般叫：**单目深度估计**

比如输入一张水下 RGB 图像，模型可能预测出：

- 前面的石头距离 2 m
- 更远处的墙距离 6 m
- 背景距离 10 m

最后会得到一张 **depth map**，每个像素都有一个深度值。

这篇 AquaBEV 里提到它，是因为以前一种常见做法是：

`RGB image → depth estimation → 根据 depth 构建 occupancy map`

但 AquaBEV 不想这么绕。论文说 monocular depth 在水下视觉条件变化时会退化，所以它想直接：

`RGB image → BEV occupancy`

也就是说，**不先预测 depth，再转 occupancy，而是直接学 occupancy**。

你可以把区别理解成：

**monocular depth estimation 问的是：这个东西离我多远？**

**occupancy prediction 问的是：这个空间位置有没有东西占着？**

### 1.2
既然 monocular depth estimation不太好，那改成两个摄像机，用双目不就好了？

### 解析
双目的话，还要计算出两张不同的图片中的同一个点，太难了。

### 1.3
Using both sensors at inference increases hardware and integration complexity. 这两个传感器是哪两个传感器啊？

### 解析

**RGB camera + 3D imaging sonar**

也就是：

- 一个普通的 **RGB 相机**
- 一个 **3D 成像声呐**

### 1.4
既然把这两个sensor融合在一起很费劲，为什么training阶段还要设计成RGB + sonar supervision。我也不知道推理阶段是什么阶段

### 解析
第一，**训练的时候为什么还能用 RGB + sonar？**

因为这里不是说“RGB 和 sonar 一起喂给模型”。

AquaBEV 训练时其实是：

`RGB 图片 → 模型 → 预测 occupancy`

然后 sonar 只是用来告诉模型：

`正确答案应该长什么样`

也就是 sonar 相当于 **label / ground truth 的来源**。

你可以直接类比你学过的分类：

`图片 → 模型 → 预测是猫还是狗`

训练时你还得有：

`正确标签：猫`

这里 sonar 就相当于这个“正确标签”。论文明确说 sonar measurements **只用于构造 supervision**，并不会在 inference 时输入网络。

第二，你问的其实不是 “reasoning stage”，而是 **inference stage**。

你学过 training 和 test，对吧？

那你先把：

**inference ≈ test 时让模型做预测**

这样理解就够了。

比如：

训练时：

`图片 + 正确答案 → 算 loss → backward → 更新参数`

inference 时：

`新图片 → 模型 → 给出预测`

**不算 backward，也不更新参数。**

### 1.5 
什么是causal range decoding？

### 解析
**causal range decoding = 沿着距离方向，按照“近 → 远”的顺序来解码。**

AquaBEV 里先把场景表示成 polar coordinates，也就是：

- 一个轴是 **azimuth `θ`**：朝哪个方向
- 一个轴是 **range `r`**：离 sonar 多远

论文觉得 `range` 这个方向不是普通的空间维度，因为它天然有一个顺序：

**近处 → 远处**

所以它不希望模型在预测某个距离 `r` 的 occupancy 时，偷偷使用更远处 `r' > r` 的信息。

### 1. 6
什么是笛卡尔坐标系？什么是 directly decoding occupancy in Cartesian？论文中的这种方法跟directly decoding occupancy in Cartesian比起来优势在哪里

### 解析：
**Cartesian space 就是普通的直角坐标系空间。**

你平时最熟悉的就是：

- 横轴：$x$
- 纵轴：$y$

比如 BEV 俯视图里，一个障碍物的位置可以写成：

(x,y)=(3,2)

directly decoding occupancy in Cartesian space 就是模型直接预测 ** $(x,y)$ 的每个格子有没有障碍物。**

AquaBEV不是直接预测 $(x,y)$，而是：

```
RGB image
   ↓
polar representation
(θ, r)
   ↓
causal range decoder
   ↓
polar occupancy
   ↓
convert to Cartesian
   ↓
BEV occupancy
(x, y)
```

### 为什么 polar space 更适合这里？

最关键原因是：

**sonar 天生就是按“方向 + 距离”来感知世界的。**

Sonar 的数据本来就类似：

> 这个方向 $\theta$ 上，距离 $r$ 的地方有回波。

所以 sonar 天然是：

(θ,r)(\theta,r)

而不是：

(x,y)

## 2. Related work

### 2.1 

visual odometry and visual SLAM further reducing drift 这是为什么？

### 解析
这里的 **drift** 指的是：机器人靠 IMU、速度计之类不断积分自己的运动时，**小误差会越积越大，最后估计位置和真实位置越来越偏**。

论文这里说：

> **visual odometry and visual SLAM further reducing drift**

意思是：**视觉里程计（VO）和视觉 SLAM 可以利用相机看到的环境特征，来修正这种长期累积的位置误差。** 论文在这一段就是在讲水下没有 GPS，所以导航要依赖惯性、声学定位、SLAM，而视觉 odometry / visual SLAM 能进一步减小漂移。

### 2.2
Related work 这里我是完完全全的看不懂，一大堆专业术语一点都看不懂

### 解析
你现在完全没必要把 Related Work 里的每个名词都学会，它这一节本质上只是在告诉你：

**“以前别人做过哪些相关方向，以及为什么这些工作还不能直接解决 AquaBEV 的问题。”**

这篇论文的 Related Work 一共就三块，你先把主线抓住就行。

第一块，**2.1 Underwater Navigation and Spatial Mapping**，讲的是“水下机器人以前是怎么导航和建图的”。核心背景是：**水下没有 GPS**，所以机器人得依赖 IMU、acoustic positioning、SLAM、visual odometry 这些东西来估计自己在哪里。后面提到 active visual SLAM、inspection planning、semantic visual servoing 等，其实都只是作者在列举“以前大家已经做过很多水下导航方法”。

这一段你只需要记住：

> **以前水下机器人已经会导航、SLAM、建图，但 dense occupancy prediction directly from a single underwater RGB image 还没怎么被研究。**

也就是说，AquaBEV 想做的是一个更具体的新问题：

**单张水下 RGB → dense BEV occupancy**

第二块，**2.2 BEV and Occupancy Prediction**，讲的是陆地上已经有很多 BEV / occupancy 方法。

里面一大堆名字，比如：

- Lift-Splat-Shoot
- BEVFormer
- MonoScene
- VoxFormer
- TPVFormer
- SparseOcc
- GaussianFormer
- SelfOcc

这些你现在都不用细看。

作者只是想说：

> “陆地自动驾驶那边，已经有很多方法可以从 camera 预测 BEV 或 3D occupancy。”

有的方法靠：

- explicit geometry
- learned BEV queries
- voxel
- sparse voxel
- Gaussian primitives
- video supervision

但问题是：

**这些方法大多数是为 terrestrial，也就是陆地场景设计的。**

它们通常假设：

- camera geometry 比较稳定
- 数据很多
- 图像质量好
- sensor geometry 比较明确

而水下有：

- 图像退化
- sonar supervision 很 sparse
- camera 和 sonar 的几何关系更麻烦

所以作者说：这些陆地方法直接搬到水下，不一定合适。

这一节你可以压缩成一句话：

> **陆地上 occupancy prediction 很成熟，但直接搬到水下可能不行。**

第三块，**2.3 Polar and Range Structured Representations**（极坐标和范围表示），这块才和 AquaBEV 最直接相关。

这里作者开始讲：

> 有些传感器的数据，本来就是按“方向 + 距离”组织的。

比如 LiDAR 和 sonar。

所以以前有人用：

- polar representation
- cylindrical representation
- range-aware processing

来更自然地表示这类数据。

这里的核心不是让你记 PolarNet、PolarFormer、RangeFormer 这些名字。

你只要知道：

**以前已经有人发现，对 radial sensor，也就是这种从传感器向外发散的传感器，polar representation 往往比普通 Cartesian grid 更自然。**

但这些以前的方法主要是：

**直接处理 LiDAR 数据**

而 AquaBEV 不一样：

**它输入的是 RGB image，但中间用 polar space 来预测 sonar-supervised occupancy。**

这就是它和 previous work 的区别。

所以整章 Related Work 其实可以被你压缩成这三句话：

- **2.1：** 水下机器人以前已经有 SLAM、navigation、mapping，但“单张 RGB 直接预测 dense occupancy”很少有人做。
- **2.2：** 陆地上已经有很多 BEV / occupancy prediction 方法，但它们不一定适合水下。
- **2.3：** 以前有人用 polar representation 处理 LiDAR 这类 radial sensor；AquaBEV 借用了这个思想，但用于 **RGB → sonar-supervised occupancy**。

你现在读这篇论文，Related Work 里那些陌生名词，**90% 都可以先当论文名字跳过去**。真正需要搞懂的只有几个概念：**SLAM、BEV、occupancy、voxel、polar representation、LiDAR、sonar**。其他像 SparseOcc、COTR、GaussianFormer，本质上都只是不同的 previous methods。

### 2.3

你说以前水下机器人已经会导航、SLAM、建图，但 dense occupancy prediction directly from a single underwater RGB image 还没怎么被研究。我想知道dense occupancy prediction directly from a single underwater RGB image优于导航、SLAM、建图的点在哪里，为什么会选择使用ense occupancy prediction directly from a single underwater RGB image而不是选择使用导航、SLAM、建图？

### 解析

**dense occupancy prediction、SLAM、navigation、mapping 其实不是同一层级的东西，所以不是“选一个替代另一个”。**

更准确地说，这篇论文不是在说：

> “以前大家用 SLAM / navigation，现在我们发现 occupancy prediction 更好，所以把它们换掉。”

而是在说：

> **以前水下机器人已经有 SLAM、建图和导航系统，但这些系统仍然需要一个“感知模块”告诉它前面哪里有障碍物、哪里能走。AquaBEV 想改进的是这个感知模块。**

论文自己也说，DREAM、CORAL 这类系统已经维护 persistent spatial representation 来做 planning；但这些表示往往依赖 SLAM、几何传感器或者 estimated depth。作者关注的是：能不能**直接从单张水下 RGB 图像预测 dense occupancy**。

你可以把整个机器人系统想成这样：

```
相机/传感器
    ↓
perception 感知
    ↓
地图/occupancy
    ↓
planning 路径规划
    ↓
control 控制机器人走
```

这里：

- **SLAM** 主要回答：**“我在哪里？环境地图是什么样？”**
- **occupancy prediction** 主要回答：**“我周围哪些地方被占据，哪些地方可以走？”**
- **navigation** 主要回答：**“我要怎么从当前位置走到目标位置？”**

所以它们不是竞争关系。

举个最简单的例子。

假设水下机器人要穿过珊瑚礁。

SLAM 可以告诉它：

> “我现在大概在地图的 $(x,y)$ 这里。”

但是它还需要知道：

> “我前面 2 米是不是有一块石头？”

这个就属于 occupancy perception。

然后 navigation / planner 才能根据 occupancy map 决定：

> “前面有障碍，那我绕左边走。”

### 3.2

During training, It is paired with 3D imaging sonar returns $P_t^* = \{(x_i,y_i,z_i)\}_{i=1}^{N}, \tag{2}$ which are used only to construct supervision. Sonar mea- surements are not provided to the network at inference. 这个地方用作监督学习的话，作者怎么知道这个点是不是标准的点呢？万一是不标准的怎么办？

### 解析
**作者并不知道它是绝对完美的标准答案。**

论文其实从来没有说 sonar label 是完美的 “true world”。

他们只是把 sonar measurement 当作 **training supervision**，因为相比单张 RGB，它能提供更直接的几何信息。

### 3.3
Sonar returns within a short temporal window are ex- pressed in the reference frame at time (t) and projected onto the horizontal plane. 这段话我也没搞懂，说sonar就是在训练阶段会用到吗？在真正的环境中推理的时候用不到啊，那这个怎么又 Sonar returns 什么什么的了？

### 解析

你现在真正卡住的是 **“时间 t” 和 “训练/推理阶段” 被混在一起了**。这句话里的 sonar **仍然只属于训练阶段**。它没有突然跑到 inference 里去。

最关键的一点先说：

> **这里的 “time tt” 不是 “inference time”。**
> 
> 它只是说：训练数据中某一张 RGB 图片是在时刻 tt 拍的。

论文的训练样本可以想成这样：

```
训练阶段，某个时刻 t：

RGB image I_t
        │
        │ 送进 AquaBEV
        ↓
predicted occupancy
        │
        │ 和 label 比较
        ↓
       loss

与此同时：

t 附近采集到的 sonar returns
        ↓
处理成 occupancy label
```

也就是说，**sonar 从始至终都只是为了制作训练标签。**

论文前面说得很明确：

> During training, $I_t$ is paired with 3D imaging sonar returns ...

也就是**训练的时候**，RGB 图片 $I_t$ 配有 sonar 数据；并且这些 sonar measurement 只用于构造 supervision，inference 时不会给网络。

### 3.4

Sonar returns within a short temporal window are expressed in the reference frame at time tt and projected onto the horizontal plane.这句话我看不懂

### 解析
> **在训练数据制作时，取时刻 tt 附近一个很短时间窗口内采集到的 sonar returns，把这些 sonar returns 全部转换到 tt 时刻的坐标系里，然后再投影到水平平面上。**

这里最重要的是：**这句话整个都还在讲“怎么用 sonar 制作训练标签”**，跟 inference 没关系。论文前一句已经说了 sonar 只用于 training supervision，inference 时不输入 sonar。

你可以把它拆成三小段：

1. **Sonar returns within a short temporal window**
    
    不是只拿 t 那一瞬间的一帧 sonar，而是拿 t 附近一小段时间里的多帧 sonar 点。
    
    比如：
    
    - t-0.1s
    - t
    - t+0.1s
1. **are expressed in the reference frame at time tt**
    
    因为机器人在这短时间里会移动，所以不同时间测到的 sonar 点，原本各自在不同坐标系里。
    
    作者把这些点都转换成：
    
    **“如果都站在时刻 t 的机器人位置来看，这些点在哪里？”**
    
    也就是统一到 t 时刻的坐标系。
    
2. **and projected onto the horizontal plane**
    
    原来 sonar 点是 3D：
    
    (x,y,z)
    
    作者把高度 z 去掉：
    
    $$(x,y,z)\rightarrow(x,y)$$
    
    因为最后要做的是 2D BEV occupancy label。
    

所以整句你就记成：

> **把 tt 附近几帧 sonar 点收集起来 → 全部对齐到 tt 时刻 → 从 3D 压成 2D。**

这三步做完以后，作者才开始用这些 2D sonar 点去标 `occupied / observed free / unknown`。


### 3.5

Each projected return marks an occupied cell. Under the first return assumption, cells traversed by the corresponding ray from the sonar origin are marked as observed free. All remaining cells are unknown because the sonar provides no evidence that they are free or occupied.这一句也是一点都看不懂

### 解析：

第一句：

> **Each projected(被投影后的) return(返回的点) marks an occupied cell.**

直译：

> **每一个投影后的声呐回波点，都会把它所在的栅格标记为“被占据”。**

更自然一点：

> 每个经过投影的 sonar return，都说明对应的 BEV 格子里有东西。

这里：

- `projected return` = 前面从 3D 投影到 2D 平面后的 sonar 点
- `marks` = 标记
- `occupied cell` = 被障碍物占据的网格

也就是说，sonar 在某个位置收到回波，那作者就认为那个格子有物体。


第二句：

> **Under the first return assumption, cells traversed by the corresponding ray from the sonar origin are marked as observed free.**

直译：

> **在“第一次回波假设”下，从声呐原点出发、对应声波射线在到达该回波点之前所穿过的那些网格，会被标记为“已观测为空闲”。**

这句很绕，拆开：

- **Under the first return assumption** = 在“第一次回波假设”下
- **cells** = 网格 / 栅格
- **traversed by** = 被……穿过
- **the corresponding ray** = 对应的那条射线
- **from the sonar origin** = 从声呐原点出发
- **are marked as** = 被标记为
- **observed free** = 已观测为空闲

意思就是：

如果 sonar 第一次在 5 米处收到回波：

```
sonar → 1m → 2m → 3m → 4m → 5m障碍物
```

那作者认为：

- 1m 到 4m：声波能通过，所以是 `observed free`
- 5m：收到回波，所以是 `occupied`


第三句：

> **All remaining cells are unknown because the sonar provides no evidence that they are free or occupied.**

直译：

> **剩下的所有网格都被视为未知，因为声呐没有提供证据说明这些位置究竟是空闲的还是被占据的。**

这里最重要的是：

`没有 sonar 证据 ≠ free`

只是：

`不知道`

所以最后三种状态就是：

- sonar 回波落到的格子：`occupied`
- sonar 射线在第一次回波前经过的格子：`observed free`
- 其他没被 sonar 证明的格子：`unknown`

整段合起来最自然的中文就是：

> 投影后的每个 sonar 回波点都把对应格子标成“被占据”；按照第一次回波假设，从 sonar 到这个回波点之间被声波射线穿过的格子标成“已观测为空闲”；其余没有 sonar 证据的位置都标成“未知”。
