    0. Abstraction¶

    0.1¶

    what's the meaning of ScrewSplat, kinematic structure, screw axes, zero-shot

    Analysis¶

    1. ScrewSplat¶

    ScrewSplat is the name of the method proposed in this paper.

    The name combines two ideas:

    • Screw → screw theory, which is used to describe joint motion(关节运动)
    • Splat → Gaussian Splatting, which is used to represent the object's 3D appearance and geometry

    So you can roughly understand:

    ScrewSplat = screw motion model + Gaussian Splatting

    2. Kinematic structure¶

    Kinematic structure means the structure describing how the different parts of an object are allowed to move relative to each other.

    For an articulated object, it includes things like:

    • which part is static
    • which parts can move
    • what type of joint connects them
    • where the joint axis is
    • how each movable part moves

    The paper explicitly says robots need to understand both the object's 3D geometry and its underlying kinematic structure, such as joint types and axes.

    Take a laptop:

    • keyboard base → static part
    • screen → movable part
    • hinge → revolute joint
    • hinge direction → joint axis

    All of that together is the kinematic structure.

    Another example is a drawer:

    • cabinet → static
    • drawer → movable
    • joint type → prismatic
    • motion direction → forward/backward

    So when the paper says:

    recover the object's geometry and kinematic structure

    it means:

    reconstruct what the object looks like, and understand how its parts can move.

    3. Screw axis¶

    A screw axis is a mathematical representation of a rigid-body motion.

    In this paper, a screw axis is written as

    \[ S= \begin{bmatrix} \omega\\ v \end{bmatrix} \in\mathbb{R}^6 \]

    where \(\omega\) and \(v\) describe the motion.

    You don't need to worry about the formula yet. First understand the physical meaning.

    For a revolute joint, like a laptop hinge:

    the screw axis tells you where the rotation axis is and what direction it points.

    For example:

    For a prismatic joint, like a drawer:

    which direction the drawer translates.

    So you can temporarily think of a screw axis as:

    the mathematical description of the axis/direction along which a movable part moves.

    The nice thing about screw theory is that it can represent both:

    • rotation
    • translation

    in one unified framework.

    4. Zero-shot¶

    Zero-shot means doing a new task without specifically training the model on examples of that exact task beforehand.

    In this paper, they talk about:

    zero-shot, text-guided manipulation

    1. Introduction¶

    1.1¶

    analysis¶

    “Varying object configurations” means the object is observed in different articulation states / poses.

    For example, for a laptop, different configurations could be:

    • fully closed
    • slightly open
    • half open
    • almost fully open

    Why Traditional 3D Reconstruction Methods Need Strong Assumptions and Multi-Stage Pipelines¶

    1. Why is 3D reconstruction difficult?¶

    Suppose we only have several RGB images of an object taken from different viewpoints.

    For one pixel \((u,v)\) in an RGB image, we know the viewing direction, but we do not directly know how far away the corresponding surface point is.

    Therefore:

    \[ \text{2D pixel} \rightarrow \text{a ray in 3D space} \]

    rather than

    \[ \text{2D pixel} \rightarrow \text{one unique 3D point} \]

    There are infinitely many possible 3D points along the same viewing ray that could project to the same image pixel.

    Therefore, 3D reconstruction is fundamentally an underdetermined problem:

    The available 2D observations are often insufficient to uniquely determine the underlying 3D geometry and motion.

    This is the fundamental reason why traditional reconstruction methods often need additional assumptions and intermediate procedures.

    2. Why do traditional methods rely on strong assumptions?¶

    The main reason is:

    Because the reconstruction problem contains too many unknown variables and too many possible solutions. Strong assumptions reduce the search space and make the problem solvable.

    For example, suppose the entire object is assumed to be rigid.

    Then the motion of every 3D point can be described by the same rigid transformation:

    \[ P_i^{t+1} = R P_i^t + T \]

    where:

    • \(P_i^t\) is the 3D position of point \(i\) at time \(t\),

    • \(R\) is a rotation matrix,

    • \(T\) is a translation vector.

    This assumption greatly simplifies the problem.

    Instead of independently estimating how thousands of points move, the system only needs to estimate one \(R\) and one \(T\).

    Therefore:

    \[ \text{strong assumption} \rightarrow \text{fewer unknowns} \rightarrow \text{easier optimization} \]

    3. Why are articulated objects harder?¶

    For an articulated object, such as a cabinet:

    • the cabinet body may remain static,

    • a door may rotate,

    • a drawer may translate.

    Therefore, one global rigid transformation is no longer sufficient.

    Instead, different parts have different transformations:

    \[ P_i^{t+1} = R_{k(i)} P_i^t + T_{k(i)} \]

    where \(k(i)\) indicates which object part point \(i\) belongs to.

    But now a new unknown appears:

    Which point belongs to which rigid part?

    So the method must somehow estimate the part assignment.

    This leads to procedures such as part clustering.

    At the same time, to know how a 3D point moves across frames, the system must know which image observations correspond to the same physical point.

    This leads to point correspondence matching.

    Therefore, articulated reconstruction often contains several mutually dependent unknowns:

    \[ \boxed{\text{geometry} \leftrightarrow \text{point correspondence} \leftrightarrow \text{part assignment} \leftrightarrow \text{motion}} \]

    This creates a difficult circular dependency.

    Traditional methods often break this difficult joint problem into several smaller stages and impose assumptions at each stage.

    Typical assumptions may include:

    • the object consists of a small number of rigid parts,

    • points on the same part move rigidly together,

    • camera poses are already known,

    • enough visual texture exists for matching,

    • the number of movable parts is known or limited,

    • motion between frames is sufficiently small,

    • depth measurements are available,

    • different parts exhibit sufficiently different motion patterns.

    These assumptions are needed because, without them, too many different 3D structures and motion explanations could fit the same images.

    So the key causal relationship is:

    \[ \boxed{\text{2D observations are ambiguous}} \]
    \[ \Downarrow \]
    \[ \boxed{\text{additional constraints are needed}} \]
    \[ \Downarrow \]
    \[ \boxed{\text{these constraints become strong assumptions}} \]

    4. What is point correspondence?¶

    Suppose we take two photos of the same chair from different viewpoints.

    A physical corner of the chair appears at

    \[ p_A = (120,80) \]

    in image A, and at

    \[ p_B = (95,83) \]

    in image B.

    Although the pixel coordinates are different, they represent the same physical 3D point.

    Therefore,

    \[ p_A \leftrightarrow p_B \]

    is a point correspondence.

    In simple words:

    Point correspondence means identifying which point in one image corresponds to the same physical point in another image.

    5. Why do we need point correspondence?¶

    A pixel in one image only gives us one viewing ray.

    Suppose camera 1 observes one point and produces ray \(r_1\).

    Camera 2 observes the same physical point and produces ray \(r_2\).

    If we know that these two observations correspond to the same physical point, then we can estimate the 3D location by triangulation.

    Conceptually:

    \[ \text{matching pixels} \rightarrow \text{two viewing rays} \rightarrow \text{triangulation} \rightarrow \text{3D point} \]

    Therefore, correspondence is one of the fundamental tools used in multi-view reconstruction.

    6. Why is point correspondence difficult?¶

    The computer does not automatically know which pixels belong to the same physical location.

    For example, suppose a white cabinet contains many visually similar corners.

    A point in image 1 may look similar to several points in image 2.

    The system may therefore accidentally match

    \[ \text{corner A in image 1} \]

    with

    \[ \text{corner B in image 2} \]

    even though they are different physical points.

    This problem becomes especially difficult when the object contains:

    • repetitive textures,

    • textureless regions,

    • reflections,

    • shadows,

    • occlusions,

    • large viewpoint changes,

    • moving parts.

    Therefore:

    \[ \text{wrong correspondence} \rightarrow \text{wrong triangulation} \rightarrow \text{wrong 3D geometry} \]

    7. What is part clustering?¶

    Suppose a cabinet contains:

    • a static cabinet body,

    • a left door,

    • a right door,

    • a drawer.

    After reconstructing many 3D points,

    \[ P_1, P_2, \dots, P_N \]

    the system may try to divide them into several groups:

    \[ C_1, C_2, C_3, C_4 \]

    where each cluster corresponds to one physical part.

    For example:

    • \(C_1\): cabinet body,

    • \(C_2\): left door,

    • \(C_3\): right door,

    • \(C_4\): drawer.

    This process is called part clustering.

    A common idea is:

    Points that move together probably belong to the same rigid part.

    For example, points on the same cabinet door should approximately share the same rigid transformation.

    8. Why can part clustering fail?¶

    Motion does not always clearly distinguish different parts.

    For example, consider a rotating door.

    Points near the hinge move very little, while points far away from the hinge move a lot.

    Therefore, a clustering method based mainly on motion may incorrectly conclude that points near the hinge belong to the static cabinet body.

    Similarly, two different parts may temporarily move in similar ways.

    Then the system might incorrectly merge them into the same cluster.

    Therefore:

    \[ \text{incorrect motion estimation} \rightarrow \text{incorrect part clustering} \]

    And incorrect clustering can then affect later articulation estimation.

    9. What is a multi-stage pipeline?¶

    A traditional articulated reconstruction system may use a pipeline such as:

    \[ \text{RGB video} \rightarrow \text{feature extraction} \rightarrow \text{point correspondence} \rightarrow \text{3D point reconstruction} \rightarrow \text{motion estimation} \rightarrow \text{part clustering} \rightarrow \text{joint estimation} \rightarrow \text{final articulated 3D model} \]

    This is called a multi-stage pipeline because the final result is obtained through several intermediate procedures.

    Each stage uses the output of the previous stage.

    10. Why do multi-stage pipelines introduce potential points of failure?¶

    The problem is that errors can propagate from one stage to another.

    Stage 1: correspondence matching¶

    Suppose some point correspondences are incorrect.

    Then:

    \[ \text{wrong correspondence} \]

    causes incorrect triangulation.

    Stage 2: 3D reconstruction¶

    The incorrectly matched points produce incorrect 3D locations.

    Then:

    \[ \text{wrong 3D geometry} \]

    affects motion estimation.

    Stage 3: motion estimation and clustering¶

    Incorrect point trajectories may cause points to be assigned to the wrong object part.

    Then:

    \[ \text{wrong clustering} \]

    affects joint estimation.

    Finally:

    \[ \boxed{\text{correspondence error} \rightarrow \text{geometry error} \rightarrow \text{motion error} \rightarrow \text{clustering error} \rightarrow \text{joint estimation error}} \]

    Therefore, every intermediate stage becomes a potential point of failure.

    Here, “point of failure” does not mean a 3D point.

    It means:

    A step in the processing pipeline where an error may occur and then propagate to later stages.

    11. What is auxiliary depth input?¶

    An RGB image gives a color value for every pixel:

    \[ I(u,v) = (R,G,B) \]

    For example:

    \[ I(120,80) = (128,210,43) \]

    A depth map instead gives the distance from the camera to the visible surface:

    \[ D(u,v) = z \]

    For example:

    \[ D(120,80) = 1.73 \text{ m} \]

    Therefore:

    • RGB tells us what the pixel looks like.

    • Depth tells us how far away the corresponding surface is.

    If a method requires auxiliary depth input, it means that RGB alone is not sufficient for the method.

    The method additionally requires depth information from sources such as:

    • RGB-D cameras,

    • LiDAR,

    • stereo cameras,

    • structured-light sensors,

    • time-of-flight sensors,

    • monocular depth estimation models.

    “Auxiliary” simply means:

    additional information provided in addition to the primary RGB images.

    12. Why is depth useful for reconstruction?¶

    Without depth:

    \[ \text{pixel} \rightarrow \text{unknown location somewhere along a ray} \]

    With depth:

    \[ \text{pixel} + \text{depth} \rightarrow \text{specific 3D location} \]

    Given the camera intrinsic matrix \(K\):

    \[ P = D(u,v) K^{-1} \begin{bmatrix} u \ v \ 1 \end{bmatrix} \]

    Conceptually:

    Pixel coordinates determine the viewing direction, while depth determines how far along that direction the surface lies.

    Therefore:

    \[ \boxed{\text{direction} + \text{distance} \rightarrow \text{3D point}} \]

    This is why depth can greatly simplify 3D reconstruction.

    13. Why can auxiliary depth input be noisy?¶

    Real depth sensors do not measure depth perfectly.

    Unlike RGB cameras, which mainly record incoming light intensity and color, many depth sensors rely on more complicated physical mechanisms.

    Structured-light sensors¶

    A sensor projects an infrared pattern onto the scene and estimates depth from how the pattern appears.

    Time-of-Flight sensors¶

    A sensor emits infrared light and estimates distance from the returning signal.

    Stereo cameras¶

    Two cameras observe the scene from slightly different positions, and depth is estimated from image disparity.

    All of these techniques rely on assumptions about how light interacts with surfaces.

    When those assumptions are violated, depth measurements become unreliable.

    14. Why are transparent surfaces difficult for depth sensors?¶

    Consider a glass surface.

    Ideally, the sensor expects emitted light to hit the visible surface and return.

    However, with glass, the light may pass through the surface and reach an object behind it.

    For example:

    \[ \text{camera} \rightarrow \text{glass} \rightarrow \text{wall behind the glass} \]

    The sensor may therefore measure the wall rather than the glass.

    Suppose the true glass surface is

    \[ 1.0 \text{ m} \]

    away, while the wall behind it is

    \[ 2.5 \text{ m} \]

    away.

    The depth sensor may incorrectly return

    \[ D = 2.5 \text{ m} \]

    Some light may also reflect from the glass while other light passes through it, producing unstable or inconsistent measurements.

    Therefore, transparent objects violate the assumption that:

    the detected signal comes from the first visible surface.

    15. Why are reflective surfaces difficult?¶

    Consider shiny metal or a mirror.

    A depth sensor may emit light toward the surface.

    Instead of returning to the sensor, the light may undergo specular reflection and travel in another direction.

    Therefore, the returning signal may be:

    • extremely weak,

    • missing,

    • reflected from another object,

    • inconsistent with the true surface position.

    This can produce:

    • missing depth values,

    • holes in the depth map,

    • unstable depth,

    • very large errors,

    • incorrect 3D points.

    Thus reflective surfaces can make geometric measurements unreliable.

    16. Why is depth often described as noisier than RGB for transparent or reflective objects?¶

    This does not mean that RGB reconstruction is easy for glass or mirrors.

    Transparent and reflective objects are also difficult for RGB-based reconstruction.

    However, an RGB camera will usually still record valid pixel values:

    \[ (R,G,B) \]

    For example, a mirror still produces a normal-looking image containing reflected colors.

    A depth sensor, on the other hand, may return:

    • no measurement,

    • zero,

    • the distance of an object behind the glass,

    • a completely incorrect value.

    Therefore, for transparent or reflective surfaces, the geometric depth measurement itself may become severely corrupted.

    That is why papers often describe depth input as noisy or unreliable in these situations.

    17. How everything connects together¶

    A traditional articulated-object reconstruction system may look like:

    \[ \text{RGB + depth} \rightarrow \text{point correspondence} \rightarrow \text{3D point tracking} \rightarrow \text{motion estimation} \rightarrow \text{part clustering} \rightarrow \text{joint / kinematic structure estimation} \rightarrow \text{final articulated 3D model} \]

    The problem is that each intermediate result may contain errors.

    For example:

    \[ \text{bad depth} \rightarrow \text{bad 3D points} \rightarrow \text{bad motion estimation} \rightarrow \text{bad clustering} \rightarrow \text{bad articulation} \]

    Similarly:

    \[ \text{wrong correspondence} \rightarrow \text{wrong geometry} \rightarrow \text{wrong clustering} \rightarrow \text{wrong joint axis} \]

    Therefore, traditional multi-stage pipelines can become fragile.

    18. Core takeaway¶

    The central reason traditional articulated 3D reconstruction methods often rely on strong assumptions and complicated intermediate procedures is:

    The original problem is highly ambiguous and underdetermined. RGB observations alone do not directly reveal depth, correspondence, object parts, motion, or articulation.

    Therefore, traditional methods simplify the problem by imposing assumptions and solving several smaller subproblems sequentially.

    The three important intermediate concepts are:

    Point correspondence¶

    Which observations in different images represent the same physical 3D point?

    \[ p_i^t \leftrightarrow p_j^{t+1} \]

    Part clustering¶

    Which reconstructed points belong to the same moving rigid part?

    \[ {P_i} \rightarrow {\text{part}_1,\text{part}_2,\dots} \]

    Auxiliary depth¶

    How far away is the surface corresponding to each pixel?

    \[ D(u,v) = z \]

    The difficulty is that these quantities depend on each other:

    \[ \boxed{\text{geometry} \leftrightarrow \text{correspondence} \leftrightarrow \text{motion} \leftrightarrow \text{part assignment}} \]

    Traditional methods often resolve this circular dependency by imposing strong assumptions and constructing multi-stage pipelines.

    But this introduces another problem:

    \[ \boxed{\text{error in one stage} \rightarrow \text{error propagation to later stages}} \]

    Therefore, newer methods often try to reduce the number of manually designed intermediate stages and jointly optimize geometry, motion, and articulation directly from RGB observations.

    \[ m_{ij} \ge 0 \]

    A probability simplex is a vector of nonnegative values that sum to 1.

    For example:

    \[ m_i=(0.1,0.8,0.1). \]

    This means:

    Gaussian \(i\) is mostly associated with part 1, but there is still some uncertainty.

    During optimization, the probabilities can change smoothly:

    \[ (0.3,0.4,0.3) \rightarrow (0.2,0.6,0.2) \rightarrow (0.05,0.9,0.05). \]

    So:

    softly assign = assign using probabilities instead of a hard discrete label.

    This makes the assignment differentiable and easier to optimize.

    • cabinet
    • chair component

    1. Overall idea¶

    ScrewSplat tries to jointly recover:

    • the 3D geometry of the object,
    • which Gaussians belong to which rigid parts,
    • the screw axes of movable parts,
    • which candidate screws are actually useful,
    • and the joint motion in each observed configuration.

    Start with many 3D Gaussians and many candidate screws, then optimize them together so that the rendered RGB images match the observed RGB images.

    2. Index notation¶

    The paper uses three important indices:

    • \(i\) → index of Gaussian
    • \(j\) → index of screw
    • \(k\) → index of object configuration

    If there are:

    • \(n_g\) Gaussians,
    • \(n_s\) candidate screws,
    • \(n_a\) observed configurations,

    then:

    \[ i=1,\dots,n_g \]
    \[ j=1,\dots,n_s \]
    \[ k=1,\dots,n_a \]

    Important:

    \(k\) is not the number of configurations.

    It is the index of one configuration.

    For example, if there are 5 observed configurations:

    \[ k=1,2,3,4,5. \]

    3. Screw primitive \(A_j\)¶

    The paper defines the \(j\)-th screw primitive as

    \[ A_j=(S_j,\gamma_j). \]

    A screw primitive is not a physical object.

    It is one candidate joint hypothesis.

    So:

    \[ A_1,A_2,\dots,A_{n_s} \]

    represent different candidate joints.

    Each candidate screw contains:

    \[ A_j=(S_j,\gamma_j) \]

    where:

    • \(S_j\) = screw axis of candidate joint \(j\)
    • \(\gamma_j\) = confidence of candidate joint \(j\)

    \(S_j\) does not represent the pose of an object.

    It represents the motion axis of candidate joint \(j\).

    It is written as

    \[ S_j= \begin{bmatrix} \omega_j\\ v_j \end{bmatrix}. \]

    For a revolute joint, \(S_j\) describes things such as:

    • the direction of the rotation axis,
    • the position of the rotation axis.

    For a prismatic joint, it describes the translation direction.

    So:

    \(S_j\) describes how the movable part associated with candidate joint \(j\) would move.

    3.2 What is \(\gamma_j\)?¶

    The confidence score satisfies

    \[ \gamma_j\in[0,1]. \]

    It means:

    how strongly the model currently believes that candidate screw \(j\) is useful or corresponds to a real joint.

    For example:

    \[ \gamma_1=0.95 \]

    means screw 1 is strongly trusted.

    But

    \[ \gamma_4=0.03 \]

    means screw 4 is probably unnecessary.

    So \(\gamma_j\) is specifically the confidence of candidate screw \(A_j\).

    • \(c_i\) = color
    • \(m_i\) = part-membership probabilities

    5.1 What does "part-aware" mean?¶

    "Part-aware" means that each Gaussian does not only store geometry and appearance.

    It also stores information about:

    which rigid part this Gaussian may belong to.

    So:

    part-aware Gaussian = Gaussian with part-membership information.

    It does not mean the Gaussian knows semantic names such as:

    • screen,
    • keyboard,
    • drawer.

    It only knows probabilities over part slots.

    6. Part probability vector \(m_i\)¶

    The paper defines

    \[ m_i= (m_{i0},m_{i1},\dots,m_{in_s}). \]

    This is a probability simplex.

    That means:

    \[ m_{ij}\ge0 \]

    and

    \[ \sum_{j=0}^{n_s}m_{ij}=1. \]

    The meaning is:

    \[ m_{i0} \]

    = probability that Gaussian \(i\) belongs to the static base.

    For

    \[ j\ge1, \]
    \[ m_{ij} \]

    = probability that Gaussian \(i\) belongs to the movable part associated with screw \(A_j\).

    For example:

    \[ m_i=(0.1,0.8,0.1) \]

    could mean:

    • 10% static base,
    • 80% movable part controlled by screw 1,
    • 10% movable part controlled by screw 2.

    7. Soft assignment¶

    Instead of making a hard decision such as

    \[ m_i=(0,1,0), \]

    ScrewSplat allows soft assignments such as

    \[ m_i=(0.1,0.8,0.1). \]

    This means the Gaussian is mostly associated with one part, but the model still keeps uncertainty.

    During optimization:

    \[ (0.3,0.4,0.3) \rightarrow (0.1,0.8,0.1) \rightarrow (0.02,0.95,0.03). \]

    This makes the optimization continuous and differentiable.

    8. Why "rigid parts"?¶

    Here, "rigid" does not mean "hard material".

    It means:

    the shape of the part itself does not deform while it moves.

    Examples:

    • laptop screen,
    • laptop base,
    • drawer,
    • cabinet,
    • chair component.

    These parts may rotate or translate, but their internal shape stays approximately fixed.

    So ScrewSplat mainly focuses on articulated objects made of rigid parts.

    It is not designed for general deformable objects such as:

    • cloth,
    • rope,
    • rubber.

    Also note:

    "softly assign Gaussians to rigid parts"

    means the assignment is soft.

    It does not mean the parts are soft.

    9. Joint angle vector \(\theta_k\)¶

    For each object configuration \(k\), the paper defines

    \[ \theta_k= (\theta_{k1},\theta_{k2},\dots,\theta_{kn_s}) \in\mathbb{R}^{n_s}. \]

    Each configuration has one such vector.

    Why does it have \(n_s\) values?

    Because there are \(n_s\) candidate screws.

    Each screw has one corresponding motion amount in configuration \(k\).

    So:

    \[ \theta_{kj} \]

    means:

    the motion amount of candidate screw \(j\) in configuration \(k\).

    9.1 Difference between \(S_j\) and \(\theta_{kj}\)¶

    These two variables have very different meanings.

    \[ S_j \]

    tells us:

    which axis / motion direction the part follows.

    While

    \[ \theta_{kj} \]

    tells us:

    how much motion occurs along that axis in configuration \(k\).

    For a revolute joint:

    \[ S_j = \text{rotation axis} \]

    and

    \[ \theta_{kj} = \text{rotation angle}. \]

    Example:

    Suppose candidate screw 1 has learned the correct laptop hinge.

    Then

    \[ S_1 \]

    describes the hinge axis.

    If configuration 3 shows the laptop opened by approximately \(60^\circ\), then

    \[ \theta_{31} \approx60^\circ. \]

    The \(60^\circ\) does not come from \(S_1\).

    It comes from the observed configuration.

    So:

    \[ S_j = \text{where/how to move} \]
    \[ \theta_{kj} = \text{how much to move in configuration }k. \]

    10. Replicated Gaussians¶

    This is one of the main ideas of ScrewSplat.

    For each part-aware Gaussian \(H_i\), the model creates

    \[ n_s+1 \]

    replicated Gaussians.

    Why \(n_s+1\)?

    Because Gaussian \(i\) could belong to:

    • the static base,
    • movable part 1,
    • movable part 2,
    • ...
    • movable part \(n_s\).

    So the model creates:

    \[ G_{i0},G_{i1},\dots,G_{in_s}. \]

    Interpretation:

    • \(G_{i0}\) → assume Gaussian \(i\) belongs to the static base
    • \(G_{i1}\) → assume it moves with screw 1
    • \(G_{i2}\) → assume it moves with screw 2
    • ...

    These are computational possibilities, not physical copies of the real object.

    11. Static Gaussian copy¶

    For the static base:

    \[ G_{i0} = (T_i,s_i,\sigma_i m_{i0},c_i). \]

    The Gaussian pose remains

    \[ T_i \]

    because the static base does not move.

    Its opacity becomes

    \[ \sigma_i m_{i0}. \]

    So if

    \[ m_{i0} \]

    is large, the static copy is strongly visible.

    If

    \[ m_{i0} \]

    is small, the static copy becomes almost invisible.

    12. Movable Gaussian copy¶

    For candidate screw \(j\):

    \[ G_{ij} = \left( e^{[S_j]\theta_{kj}}T_i, s_i, \sigma_i\gamma_jm_{ij}, c_i \right). \]

    The most important part is

    \[ e^{[S_j]\theta_{kj}}T_i. \]

    It means:

    take Gaussian \(i\) and transform it according to screw axis \(S_j\) with motion amount \(\theta_{kj}\).

    So:

    \[ T_i \rightarrow e^{[S_j]\theta_{kj}}T_i. \]

    The exact matrix exponential can be studied separately.

    For now:

    \[ e^{[S_j]\theta_{kj}} \]

    can be understood as:

    the rigid transformation produced by screw \(j\) under motion amount \(\theta_{kj}\).

    13. Opacity¶

    Opacity controls how strongly a Gaussian contributes to the rendered image.

    The paper uses

    \[ \sigma_i\in[0,1]. \]

    Roughly:

    • opacity near 0 → almost transparent
    • opacity near 1 → strongly visible / opaque

    For the static copy:

    \[ \sigma_i m_{i0}. \]

    For a movable copy:

    \[ \sigma_i\gamma_jm_{ij}. \]

    The movable opacity contains three factors:

    \[ \underbrace{\sigma_i}_{\text{original opacity}} \underbrace{m_{ij}}_{\text{part membership}} \underbrace{\gamma_j}_{\text{screw confidence}}. \]

    So the copy becomes weak if either:

    \[ m_{ij}\approx0 \]

    or

    \[ \gamma_j\approx0. \]

    This lets ScrewSplat softly control which motion hypothesis contributes to rendering.

    14. Important distinction: \(m_i\) vs. \(\gamma_j\)¶

    This is very important.

    The part probabilities satisfy

    \[ \sum_{j=0}^{n_s}m_{ij}=1. \]

    because they form a probability simplex.

    But screw confidences do NOT satisfy

    \[ \sum_j\gamma_j=1. \]

    Each screw confidence is independent:

    \[ \gamma_j\in[0,1]. \]

    Why?

    Because multiple screws can all be real simultaneously.

    For example:

    \[ \gamma=(0.95,0.92,0.88,0.03) \]

    can mean:

    • screw 1 is likely real,
    • screw 2 is likely real,
    • screw 3 is likely real,
    • screw 4 is probably unnecessary.

    So:

    \(m_{ij}\) values compete for the membership of one Gaussian.

    But:

    \(\gamma_j\) values independently measure the confidence of different candidate screws.

    15. Rendering¶

    After replicating all Gaussians, ScrewSplat has

    \[ n_g(n_s+1) \]

    Gaussian copies.

    These are rendered using standard Gaussian Splatting alpha blending.

    The rendered image is compared with the real RGB observation.

    If the rendered image is wrong, optimization updates variables such as:

    • Gaussian geometry,
    • part probabilities \(m_i\),
    • screw axes \(S_j\),
    • screw confidences \(\gamma_j\),
    • joint angles \(\theta_k\).

    So all these variables are optimized jointly.

    16. Loss function¶

    The paper uses

    \[ L = L_{\text{render}} + \beta \sum_j \sqrt{\gamma_j}. \]

    The first term:

    \[ L_{\text{render}} \]

    encourages the rendered image to match the observed RGB image.

    The second term:

    \[ \beta\sum_j\sqrt{\gamma_j} \]

    is called the parsimony loss.

    Its purpose is:

    avoid using unnecessary screw primitives.

    16.1 Why should the model avoid unnecessary screws?¶

    It does not mean that the model should always use very few screws.

    If an object truly has many joints, the model should keep many screws.

    The real idea is:

    use only as many screws as are actually needed to explain the object motion.

    Without this penalty, the model may find a trivial solution.

    For example, the same movable part could be explained by:

    • screw 2 in configuration 1,
    • screw 7 in configuration 2,
    • screw 11 in configuration 3.

    The rendered images may still look good, but the recovered kinematic structure would be wrong.

    So the parsimony loss encourages the model to reuse a consistent small set of screws.

    16.2 Why does \(\sum_j\sqrt{\gamma_j}\) encourage fewer active screws?¶

    Suppose confidence is concentrated in one screw:

    \[ \gamma=(1,0,0,0). \]

    Then:

    \[ \sum_j\sqrt{\gamma_j}=1. \]

    Now suppose the same amount is distributed over four screws:

    \[ \gamma=(0.25,0.25,0.25,0.25). \]

    Then:

    \[ \sum_j\sqrt{\gamma_j} = 4\sqrt{0.25} = 2. \]

    So spreading confidence over many nonzero screws creates a larger penalty.

    Similarly:

    \[ \sqrt{0.5}+\sqrt{0.5} \approx1.414 > 1 = \sqrt{1}. \]

    Therefore:

    the square-root penalty encourages confidence to concentrate in fewer screws.

    16.3 Does \(\sum_j\gamma_j=1\)?¶

    No.

    In ScrewSplat:

    \[ \boxed{ \sum_j\gamma_j \text{ is not constrained to equal }1 } \]

    Each \(\gamma_j\) is independent.

    However, even if they were constrained to sum to 1, the square-root penalty would still prefer concentrated confidence because

    \[ \sqrt{a}+\sqrt{b} > \sqrt{a+b} \]

    for positive \(a\) and \(b\).

    17. Balance controlled by \(\beta\)¶

    The total loss is

    \[ L = L_{\text{render}} + \beta\sum_j\sqrt{\gamma_j}. \]

    So \(\beta\) controls the balance between:

    • explaining the RGB images accurately,
    • using fewer screws.

    If \(\beta\) is too small:

    the model may use too many screws.

    If \(\beta\) is too large:

    the model may suppress real screws and even incorrectly treat movable parts as static.

    Therefore, choosing \(\beta\) is important.

    The paper explicitly states that this is one limitation of ScrewSplat, especially for objects with many joints.

    18. Removing meaningless screws¶

    After optimization has progressed, the paper removes screw primitives that are considered meaningless.

    One important criterion is:

    \[ \gamma_j<0.1. \]

    Such screws have very low confidence and little effect on rendering.

    The model then fine-tunes using the remaining meaningful screws.

    6. Conclusion¶

    I can not understand the last two limitations of this paper.

    analysis¶

    The paper mainly discusses four limitations / future directions:

    1. sensitivity to the parsimony-loss weight \(\beta\)
    2. shadow and lighting effects
    3. inability to model kinematic chains
    4. inability to directly model deformable objects such as ropes

    1. Sensitivity to the parsimony-loss weight \(\beta\)¶

    Recall the ScrewSplat loss:

    \[ L = L_{\text{render}} + \beta\sum_j\sqrt{\gamma_j}. \]

    Here:

    • \(L_{\text{render}}\) encourages the rendered RGB image to match the real observation
    • \(\beta\sum_j\sqrt{\gamma_j}\) discourages unnecessary screw primitives

    The problem is that choosing \(\beta\) is difficult.

    If \(\beta\) is too small¶

    The penalty for using many screws becomes weak.

    Then ScrewSplat may use different screws to explain the same physical movable part in different configurations.

    For example, suppose a laptop really has only one hinge.

    Ideally:

    1
2
3
4
    configuration 1 → screw A3
configuration 2 → screw A3
configuration 3 → screw A3
configuration 4 → screw A3

    The same physical hinge should always be represented by the same screw.

    But if \(\beta\) is too small, the optimizer may instead produce:

    1
2
3
4
    configuration 1 → screw A2
configuration 2 → screw A7
configuration 3 → screw A4
configuration 4 → screw A10

    The rendered RGB images may still look correct, but the recovered kinematic structure is wrong.

    The paper calls this a trivial solution.

    So:

    \[ \boxed{ \beta \text{ too small} \Rightarrow \text{too many unnecessary screws} } \]

    If \(\beta\) is too large¶

    Now the model is strongly punished for keeping screws active.

    Therefore, the optimizer may try to reduce many confidence scores:

    \[ \gamma_j \rightarrow 0. \]

    If the penalty is too strong, even real joints may be suppressed.

    In the extreme case, ScrewSplat may conclude that the whole object is static.

    So:

    \[ \boxed{ \beta \text{ too large} \Rightarrow \text{real movable parts may disappear} } \]

    Therefore, ScrewSplat has to balance two goals:

    \[ \text{accurately reconstruct the RGB observations} \]

    and

    \[ \text{use only the necessary screws}. \]

    This becomes especially difficult for high-DoF objects with many joints.

    The paper gives an example of an object with six joints where ScrewSplat fails to recover all reliable joint axes.

    Future directions¶

    The authors propose several possible improvements:

    • better initialization of screw axes
    • adaptive adjustment of \(\beta\)
    • dynamically removing unnecessary screw axes
    • dynamically densifying / adding screw axes during optimization

    Here, densifying screw axes means adding more candidate screw axes when the current candidates are not sufficient.

    For example, a laptop screen rotates.

    The keyboard itself has not moved.

    However, the RGB appearance of the keyboard changes because the shadow changes.

    This creates a problem for ScrewSplat.

    The current model observes:

    the same region looks different in different configurations.

    But it does not explicitly know:

    this difference is caused by lighting and shadow rather than geometry or motion.

    Therefore, the model may incorrectly create:

    • extra Gaussians
    • extra parts
    • extra screws

    just to explain the visual difference.

    So the fundamental problem is:

    \[ \text{lighting / shadow change} \]

    may be mistaken for

    \[ \text{geometry / kinematic change}. \]

    Why does this happen?¶

    Each Gaussian has a color parameter:

    \[ c_i. \]

    In the current ScrewSplat formulation, the Gaussian color is basically fixed.

    But in reality, the appearance of the same Gaussian may change when the joint configuration changes because the lighting and shadows change.

    So instead of assuming

    \[ c_i=\text{constant}, \]

    a better future model may use something like

    \[ c_i(\theta), \]

    meaning:

    the appearance or color of Gaussian \(i\) can depend on the current joint configuration.

    Future directions¶

    The paper proposes possibilities such as:

    • explicitly optimizing lighting information
    • explicitly modeling shadow effects
    • allowing Gaussian color to depend on joint configuration
    • using additional deformation functions such as Implicit Linear Blend Skinning (LBS)

    3. Current ScrewSplat cannot properly model kinematic chains¶

    In the current ScrewSplat formulation, all movable parts are assumed to move relative to a single static base.

    Conceptually:

    Each movable part is directly associated with one screw relative to the same static base.

    Its motion can be written as:

    \[ T' = e^{[S_j]\theta_j}T. \]

    This works for objects where each movable part can be regarded as directly connected to the same base.

    What is a kinematic chain?¶

    A kinematic chain means that joints are connected serially.

    For example, a robot arm:

    It is attached to link 2.

    Link 2 is affected by joint 2.

    Joint 2 is itself downstream of joint 1.

    Therefore, the final position of the gripper depends on several joints together.

    For the final link, the motion is described as:

    \[ T' = e^{[S_1]\theta_1} e^{[S_2]\theta_2} \cdots e^{[S_n]\theta_n} T. \]

    This is called the product of exponentials formulation.

    Difference from current ScrewSplat¶

    Current ScrewSplat uses:

    \[ T' = e^{[S_j]\theta_j}T. \]

    This means:

    one movable part is controlled by one screw relative to the static base.

    But for a kinematic chain:

    \[ T' = e^{[S_1]\theta_1} e^{[S_2]\theta_2} \cdots e^{[S_n]\theta_n} T. \]

    This means:

    a downstream part is affected by multiple upstream joints.

    For example, the pose of a human hand depends on:

    • shoulder rotation
    • elbow rotation
    • wrist rotation

    So a single screw is not enough to describe the final hand motion.

    Future direction¶

    The authors want to extend ScrewSplat to support spatial kinematic chains such as robot manipulators using the product-of-exponentials formulation.

    4. Deformable objects such as ropes¶

    Current ScrewSplat mainly works with articulated objects made of rigid parts.

    A rigid part may move, but its own internal shape does not change.

    Examples include:

    • laptop screen
    • drawer
    • cabinet door
    • rigid chair component

    However, deformable objects behave differently.

    For example, a rope can change its shape continuously:

    The rope itself bends.

    Therefore, its motion cannot be accurately represented simply as:

    one rigid part moving around one screw axis.

    So current ScrewSplat is not designed to directly handle such deformable objects.

    Future direction¶

    The authors mention extending the method to one-dimensional deformable objects such as ropes.

    One possible direction is pseudo-rigid-body theory.

    The basic idea is to approximate a deformable object using multiple rigid-like segments connected together.

    So instead of treating the rope as one rigid body, it may be approximated as:

    1

    This may allow screw-based methods to approximately model some types of deformation.

    5. Overall Summary¶

    The limitations can be remembered as four questions.

    Limitation 1: Optimization¶

    How can we choose the correct number of screws?

    If:

    \[ \beta \text{ is too small} \]

    then:

    \[ \text{too many screws may remain}. \]

    If:

    \[ \beta \text{ is too large} \]

    then:

    \[ \text{real screws may disappear}. \]

    Possible future improvements:

    • better screw initialization
    • adaptive \(\beta\)
    • dynamically removing screws
    • dynamically adding / densifying screws

    Limitation 2: Appearance¶

    How can we distinguish lighting changes from real motion?

    Current problem:

    \[ \text{shadow change} \rightarrow \text{may be mistaken for geometry or motion change}. \]

    Possible future improvements:

    • model lighting explicitly
    • model shadows explicitly
    • allow Gaussian color to depend on joint configuration

    How can we model joints connected in a chain?

    Current ScrewSplat assumes something like:

    Limitation 4: Deformation¶

    How can we handle objects whose own shape changes?

    Current ScrewSplat mainly assumes rigid parts.

    It does not directly model deformable objects such as:

    • ropes
    • cloth
    • rubber

    Future work may explore pseudo-rigid-body models for some deformable objects.

    One-sentence summary¶

    ScrewSplat currently struggles with choosing the correct screw complexity, separating lighting changes from true motion, modeling serial kinematic chains, and handling deformable objects.
